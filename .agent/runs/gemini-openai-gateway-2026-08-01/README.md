# gemini-3.6-flash-high через OpenAI-совместимый шлюз — 2026-08-01

Первый замер модели, доступной НЕ через LM Studio, а через локальный шлюз
(`http://localhost:8317/v1`, авторизация по ключу). Инструмент —
`server/scripts/benchLocalModels.ts --runs 10 --mode schema`: реальный промт
хода `LLMService.generatePrompt()` и та же цепочка проверок, что в
`processResponse`.

| файл | что | schemaValidFirstTry |
|---|---|---|
| `before-fence-strip.json` | до снятия markdown-забора | **7/10** |
| `after-fence-strip.json` | после (`stripCodeFence`) | **10/10** |

Все три провала «до» — одна поломка: `Unexpected token '`'` на ```` ```json ````.
Внутри забора лежал целый корректный JSON, `finish_reason` = `stop`, то есть
терялся не смысл ответа, а один префикс. Сырые ответы провалов — в поле
`rawHead` каждого проваленного прогона.

Что этот замер сказал про сам шлюз:

- `response_format.json_schema` со `strict: true` он ПРИНИМАЕТ — ни одного 400
  на схему за 20 вызовов. Но НЕ применяет: модель за ним грамматике не следует,
  иначе забор был бы невозможен. Полагаться на строгий режим как на гарантию
  формата с этим шлюзом нельзя;
- размышления нет вовсе (`avgReasoningChars` 0 в обоих прогонах), хотя
  `reasoning_effort` не гасился;
- ход дешевле локального: 5,1 с в среднем против 60 с на локальной 9B, промт
  ~6–8k токенов, ответ ~600.

Ни одного `applicabilityFailures` за 20 ходов — выдуманных идентификаторов
модель не порождала.
