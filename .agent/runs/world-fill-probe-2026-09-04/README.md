# Проба канала: наполнение мира через локальный прокси — 2026-09-04

Задача пробы: выяснить, годится ли локальный шлюз (`cli-proxy-api`, порт 8317)
для наполнения слоёв сценарных данных — чтобы объёмная историческая работа не
съедала лимит сессии агента. Взята реальная задача из очереди: **P-4, стартовая
дипломатия 1946** (`rivals`/`allies` пусты у всех 157 стран).

Проба ставилась владельцем продукта, модель — `gemini-3.8-flash-high` через
`scripts/llm-run.ps1`. Данные в игру НЕ вносились: это проверка канала и
метода, не наполнение.

## Итог: канал годится, порционировать не нужно

| Заход | Что подано | Время | prompt / completion / total | Результат |
|---|---|---:|---|---|
| 1 | 12 стран подряд по алфавиту | 12 с | 198 / 320 / 2540 | 1 пара соперничества |
| 2 | **весь ростер, 157 строк** | 15 с | **2058** / 887 / 5115 | 14 соперничеств, 18 союзов |

Проверка машинная, а не на глаз: **0 неверных id, 0 дублей пар** — сверено с
`countries.json` по множеству идентификаторов.

## Три вывода, меняющих метод

**1. Порционировать по алфавиту — значит уничтожить задачу.** Первый заход дал
почти пустой результат не потому, что модель плоха, а потому что связь
существует только когда обе её стороны в одном запросе. Двенадцать стран подряд
по алфавиту (AFG, ALB, AND, ARG…) исторических связей между собой почти не
имеют, и модель честно ответила «нет соперников среди перечисленных». Скилл
`delegate-data-layer` требует «число записей в порции» — для РЕЛЯЦИОННОГО слоя
это требование надо читать иначе: порция должна содержать обе стороны связи,
иначе связи нет.

**2. Порционировать вообще не нужно: весь ростер стоит 2058 токенов.**
157 строк формата `id|name|sovereignty|overlord` — около 13 токенов на страну.
Это же число закрывает половину вопроса задания P-2 о бюджете промта: ростер
целиком помещается в один запрос с огромным запасом до объявленных ~20k.

**3. Видимый расход токенов ниже реального примерно вдвое.** `total_tokens`
5115 при `prompt + completion` = 2945: разница — reasoning-токены модели
«high». Планировать бюджет по сумме двух видимых полей нельзя.

## Качество ответа — предварительно высокое, но это НЕ приёмка

Модель выдала ровно те узлы 1946 года, вокруг которых строится эпоха:
`IRN`–`QAZ`, `IRN`–`QMH`, `IRN`–`SUN` (Иранский кризис целиком, все три
стороны), `CHN`–`TWN`, `FRA`–`QDV` (Индокитай), `NLD`–`QRI` (Индонезия),
`GRC`–`ALB`/`BGR`/`YUG` (греческая гражданская), `SUN`–`TUR` (кризис проливов),
`SUN`–`USA`. Союзы — договоры 1943–1945 (`CSK`–`SUN`, `POL`–`SUN`, `MNG`–`SUN`,
`SUN`–`YUG`), Содружество, Арабская лига, Хашимиты, `TWN`–`USA`.

Отдельно важно: модель правильно применила правило «зависимая единица своей
внешней политики не имеет, кроме случая, когда действует сама» — `QDV`, `QRI`,
`QAZ`, `QMH` попали в пары как самостоятельные акторы, остальные 30 с лишним
`Q*` не попали никуда.

**Чего проба НЕ доказала.** Полноту: 14 соперничеств для января 1946 — вероятно
мало, границы полноты не проверялись. Точность каждой пары по источникам не
верифицировалась. Устойчивость между прогонами (тот же промт дважды) не
измерялась. Это предмет приёмки P-4, а не пробы канала.

## Эксплуатационное

`429` от шлюза приходит и на одиночном запросе (пойман на втором заходе,
ответ за 3 секунды). Внутри игры это закрыто повтором с экспоненциальной паузой
(`LOCAL_LLM_RATE_LIMIT_RETRIES`, решение 2026-08-21), но **внешний скрипт
генерации обязан иметь свой повтор**: здесь помог `curl --retry 5
--retry-delay 25 --retry-all-errors`, тот же запрос прошёл со второй попытки.

## Воспроизведение

```
pwsh -File "D:/Pax Historia LOCAL/scripts/llm-run.ps1"
```

Поднимает прокси и ждёт появления модели в `/v1/models`. Дальше — POST на
`http://localhost:8317/v1/chat/completions` телом из `probe2-request.json`
(ключ `LOCAL_LLM_API_KEY` из `server/.env` главного checkout, в артефактах его
нет). Ответ как есть — `probe2-response.json`, разобранный JSON —
`probe2-parsed.json`.
