# Задание шлюзу: стартовая дипломатия 1946 — черновик и замер устойчивости

Слой `diplomacy.rivals` / `diplomacy.allies` пуст у всех 157 стран, и мир до
июля 1948 не знает, что идёт холодная война. Здесь — черновик наполнения,
сделанный через локальный шлюз, и главное: **замер его устойчивости**.

Ставил владелец продукта 2026-09-04, модель `gemini-3.8-flash-high` через
`cli-proxy-api`, температура 0.3, два независимых прогона одним и тем же
промтом. **Данные в игру НЕ вносились** — это вход для задания P-4, а не
готовый слой.

## Что подано модели

Весь ростер 157 строк `id|name|sovereignty|overlord` плюс жёсткие правила:
только id из ростера; каждая пара один раз; зависимая единица без своей внешней
политики, кроме случая, когда действовала сама; «why» обязано называть
конкретный факт — договор с годом, войну, кризис, претензию; состояние **на
январь 1946** и ничего, что началось позже. Плюс список осей для охвата
(советско-западный раскол, Иран, Греция, Китай, Индокитай, Индонезия, арабский
мир, субконтинент, Латинская Америка, Балканы, претензии на Турцию, зоны
оккупации, Содружество, советские договоры 1943–45).

## Главное: устойчивость низкая, и это меняет метод приёмки

| | Воспроизвелось в обоих | Только run1 | Только run2 |
|---|---:|---:|---:|
| Соперничества | **37** | 6 | 28 |
| Союзы | **36** | 14 | 41 |

Пересечение — 52 % объединения по соперничествам и 40 % по союзам. **Один
прогон не даёт слоя.** При этом расхождение — не шум и не выдумка: хвост run2
содержит Дюрандову линию, Фолкленды, Триест, египетские требования об эвакуации,
антарктические претензии; хвост run1 — Эфиопию против Италии за Эритрею и
Сирию против Турции за Хатай. Это обогащение, а не мусор.

Поэтому в `merged-draft.json` каждая пара несёт поле `confidence`: `both` —
воспроизвелась дважды, `run1`/`run2` — встретилась однажды. Ядро из 37 + 36 пар
можно считать надёжным; остальное идёт на ревизию.

**Один случай показывает, что ревизия нужна не только по полноте.**
Дюрандова линия в run1 записана как `AFG`–`GBR`, в run2 как `AFG`–`IND`. Обе
атрибуции защитимы: граница пролегала с Британской Индией, но внешнюю политику
Раджа вела Британия. Такие развилки модель не решит — их решает человек, и это
работа задания P-4, а не шлюза.

## Покрытие ростера

Задействовано **78 стран из 157**. Без единой связи остались 13 суверенных:
Андорра, Швейцария, Финляндия, Ирландия, Исландия, Либерия, Лихтенштейн,
Монако, Непал, Оман, Сан-Марино, Швеция, Ватикан — нейтралы и микрогосударства,
для января 1946 правдоподобно (Финляндию стоит перепроверить: Договор о дружбе
с СССР 1948-го в охват не входит, но положение под Союзной контрольной
комиссией — вопрос к исполнителю).

**41 пара с участием зависимой единицы** — правило про них модель применила
верно: `IRN`–`QAZ`, `IRN`–`QMH`, `FRA`–`QDV`, `IDN`–`QRI`, `GBR`–`QRI` вошли,
остальные три десятка `Q*` не попали никуда.

## Эксплуатационное

Прогон занимает 66–84 секунды. Видимый расход втрое ниже реального:
`total` 19715 при `prompt + completion` 5649 — остальное reasoning. Значит
бюджет на такие задания планируется по `total`, и один прогон полного ростера
стоит примерно 20–26 тысяч токенов.

`429` от шлюза ловится и на одиночных запросах — оба прогона шли с
`curl --retry 5 --retry-delay 25 --retry-all-errors`.

## Чего этот черновик НЕ доказал

Точность каждой пары по источникам — не проверялась ни одна. Полнота — граница
«сколько пар достаточно» не установлена, 71 и 91 это оценка модели, а не
критерий. Пригодность формата к загрузке — файл не проходил ни одной схемы
сценария. Всё три остаются критериями приёмки P-4.

## Воспроизведение

```
pwsh -File "D:/Pax Historia LOCAL/scripts/llm-run.ps1"
```

Затем POST на `http://localhost:8317/v1/chat/completions` телом `request.json`
(ключ `LOCAL_LLM_API_KEY` из `server/.env` главного checkout, в артефактах его
нет). Ответы как есть — `run1-response.json`, `run2-response.json`; разобранные —
`run1-parsed.json`, `run2-parsed.json`; сведённый черновик — `merged-draft.json`.
