# Рабочие скрипты сессии по морским зонам — 2026-08-06

**Это прототип, а не пайплайн.** Скрипты лежат здесь, чтобы следующая сессия не
собирала метод заново; в `scripts/map/build/` они переедут, когда метод будет
принят и обрастёт проверками.

Порядок запуска (cwd = этот каталог, пути внутри абсолютные):

| скрипт | что делает | время |
|---|---|---|
| `wa_raster.py` | **сначала это**: строит растры World Ablaze `wa_reg.npy`, `wa_sea.npy` из `provinces.bmp` мода | ~1 мин |
| `hoi4_naval.py` | разбирает ванильную HOI4, строит растры `hoi4_reg.npy`, `hoi4_sea.npy`, рисует их морскую карту | ~3 мин |
| `hoi4_fit.py` | доказывает, что карта HOI4 НЕ переводится в градусы линейно (нужен только как обоснование) | ~5 мин |
| `warp_wa.py` | подгонка деформации World Ablaze по контрольным точкам; печатает качество | ~2 мин |
| `build_ocean.py "<имя зоны IHO>"` | **основной**: режет ОДИН океан плавными контурами | ~5 мин |
| `build_world.py` | растровая версия на весь мир (обзорная, границы блочные) | ~12 мин |

## Что делает `build_ocean.py` (порядок шагов)

1. Берёт зоны World Ablaze, попадающие в целевой океан, и переводит их контуры
   в наши координаты через деформацию (`warp_wa.py`).
2. **Отбраковывает чужие куски** двумя независимыми правилами: имя зоны уже
   занято отдельной зоной нашего слоя, ЛИБО бо́льшая часть её площади лежит в
   другой нашей зоне. Второе правило нужно потому, что первое не ловит
   `West Caribbean Sea` при нашем `Caribbean Sea`.
3. Снимает наложения, раздаёт остаток **по срединной линии** между контурами
   соседей (диаграмма Вороного). Сеткой этого делать нельзя: она режет по осям
   и даёт лесенку, запрещённую требованием пользователя.
4. **Сливает обрезки** — кусок меньше `MIN_COASTLESS_KM2` (100 тыс. км²) и без
   единого прибрежного региона уходит в соседа по самой длинной общей границе.
5. Чистит геометрию ВНУТРИ зоны: закрывает дыры, где нет ни земли, ни другой
   зоны.
6. **Упрощает швы топологически** (см. ниже).
7. Печатает самопроверку и сохраняет `zones_<океан>.geojson`.

## Упрощение швов (2026-08-07)

Пополигонный `simplify` здесь запрещён: он двигает общую границу двух зон
по-разному с каждой стороны и раскрывает между ними щели. Поэтому:

- береговая линия океана берётся ЦЕЛИКОМ и не упрощается — её вершины пришли
  из нашего водного слоя, сдвинуть их значит оторвать воду от суши и от
  соседних зон IHO;
- она вычитается из границ зон, и упрощается только остаток — чистые швы;
- каждый шов упрощается ОДИН раз и потому одинаков для обоих соседей;
- полигоны собираются заново через `polygonize(берег + упрощённые швы)`.

Результат: вершины швов Атлантики 7476 -> 2184 (-71%), Пацифики -57%; прямая
диагональ несёт 2 точки вместо сотен. Файлы 0.82 -> 0.63 МБ и 0.58 -> 0.30 МБ.
Расхождение площади всего слоя -34 км² на 362.8 млн.

**Три ошибки, сделанные здесь подряд — не повторять:**

1. Дуга относилась к берегу по `distance(дуга, берег) == 0`. Ноль даёт простое
   КАСАНИЕ концом, а концом в берег упирается почти каждый шов — упрощение
   молча пропустило их все, и прямые остались с сотнями точек.
2. Тогда классификация пошла по доле длины на берегу. Дуга «90% берег + 10%
   шов» упростилась целиком и увела побережье: 25 тыс. км² зон вылезло на сушу.
3. Вычитание берега с буфером 1e-9 отодвигает конец шва на этот же 1e-9, шов
   перестаёт доходить до берега, грань не замыкается — десять зон остались без
   геометрии, поверх них легли чужие, наложение 11.3 млн км². Лечится
   продлением шва за берег (`OVERSHOOT_DEG`).

Пересборка выполняется, только если грани нашлись для КАЖДОЙ зоны; иначе
упрощение откатывается целиком. Полусобранная карта хуже неупрощённой.

### Что проверяет самопроверка и почему именно это

Первая версия смотрела только на стыки зон друг с другом и печатала «0 дыр, 0
наложений», пока внутри полигонов лежали 107 щелей и 65 разорванных пар частей
— их увидел пользователь в просмотрщике, а не я. Поэтому проверка смотрит и
наружу, и внутрь:

- наружу: наложение зон, непокрытая площадь океана, выход за его границы;
- внутрь: дыры без земли (артефакт), щели между частями шире 0.1 мм.

Два случая намеренно НЕ считаются дефектом: вытянутая дыра с землёй внутри —
это вытянутый остров, а зазор шириной 1e-15° — предел точности double, а не
щель. Проверка, кричащая на норму, будет отключена вместе с настоящими
находками.

**Грабли, уже наступленные здесь дважды.** Щели чинились снапом на сетку
(`set_precision`) — он двигает границу каждой зоны независимо и, смыкая щели
внутри зоны, раскрыл 8235 щелей МЕЖДУ зонами. Настоящий источник был в
`voronoi_share`: ячейки резались остатком поодиночке и переставали делить
общие вершины. Чинить надо источник, а не заглаживать след.

## Контрольные точки в открытом океане (2026-08-07)

Первая версия деформации держалась только на материках и прибрежных островах.
Замер по просмотру нарезки: зона `Hawaii` встала в **1548 км** от настоящих
Гавайев, `West Polynesia` — в Индийском океане. Медиана 141 км характеризовала
контрольные точки, а не карту: в центре Пацифики их не было ни одной.

Якоря нашлись внутри самих морских регионов WA: у 64 из них есть сухопутные
провинции — это острова. `ISLAND_CTRL` в `warp_wa.py` берёт центр СУШИ внутри
морского региона и привязывает к нашим островам. Восемь однозначных пар:
Гавайи, Азоры, Кабо-Верде, Бермуды (через `Sargasso Sea`), Маршалловы,
Марианы, Соломоновы, Новая Каледония. Неоднозначные (`West Polynesia`,
`Caroline Sea`, `Micronesian Islands`, `Wakean Atoll`, `Johnston Gap`) НЕ взяты:
неверная привязка имени уже стоила 1430 км ошибки.

**Островной якорь нельзя судить по leave-one-out.** Он один в своей части
океана, поэтому предсказание по остальным точкам мимо него — неизбежность, а
не брак: первый прогон выбросил Гавайи, ровно ту точку, ради которой всё
делалось. Для островов действует другой критерий — согласованность с грубым
линейным приближением (порог 2500 км, при собственной ошибке линейной модели до
1456 км). Ошибку привязки он ловит, за одиночество не наказывает.

Медиана после добавления островов — 182 км против 141. Число выросло потому,
что набор стал труднее и честнее, а не потому, что карта стала хуже: зона
`Hawaii` теперь накрывает все четыре гавайских региона.

### Негативный контроль

`SEAZONE_RAW=1 python build_ocean.py "<океан>"` возвращает поведение ДО правок
2026-08-07 — без шагов 2 и 4 и со старой раздачей остатка по ближайшему центру.
Нужен, чтобы сравнение было измерением, а не заявлением. Замер на Северной
Атлантике: старое — 28 зон, максимум прибрежных регионов **26**; новое — 21
зона, максимум **21**, дублей имён нет.

`build_ocean.py` и `build_world.py` подтягивают подгонку через
`exec(open("warp_wa.py").read().split("# --- переносим")[0])` — то есть
`warp_wa.py` должен лежать рядом.
