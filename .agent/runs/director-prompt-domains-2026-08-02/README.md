# Полный словарь доменов в промте — замер до/после, 2026-08-02

Правка: `LLMService.getResearchDomainsLine()` печатает в промте ВСЕ имена
доменов, которые примет валидатор, и правило `research_shift` требует копировать
имя оттуда дословно. До правки словарь не показывался нигде: у страны
печатались только домены с тиром > 0 (`getTechTierSummary`).

Инструмент — `server/scripts/runCampaignWithLLM.ts`, партия USA 1946-01 → 1948-01
(24 хода), модель `gemini-3.6-flash-high` через OpenAI-совместимый шлюз,
`LOCAL_LLM_TEMPERATURE=0`. По три прогона на конфигурацию: `temperature=0` на
этом шлюзе детерминизма НЕ даёт (проверено — три вызова одного промта дали три
разных текста), поэтому сравниваются распределения, а не отдельные прогоны.

Сводка считается `analyze.py` (лежит рядом):

```text
python analyze.py <каталог-прогона> [...]
```

## Что это значит, помимо исчезновения отказов

Рычаг исследований был фактически недоступен режиссёру: за 72 хода до правки
прошёл ОДИН `research_shift`, остальные попытки отклонялись по несуществующему
имени домена. После правки — 154, с разбросом по доменам: `nuclear` 65,
`aviation` 46, `industry` 18, `radar` 13, `rocketry` 11, `electronics` 1.

Общая активность при этом выросла (4,40 → 5,51 на ход), то есть исследования не
вытеснили остальное, а добавились: `production_shift` 112 → 65, `repress`
28 → 17, `diplomacy` 139 → 118 — часть внимания перетекла, но суммарно решений
стало больше.

## Что НЕ проверено

- Замер на одном сценарии, одной стране игрока и горизонте два года. Поздняя
  партия с войнами не покрыта.
- Правка сравнивалась только на `gemini-3.6-flash-high`. На локальной 9B тот же
  дефект наблюдался (7 выдуманных доменов за 10 ходов, замер 2026-07-30), но
  эффект правки там не мерился.
- Качество прозы между конфигурациями количественно не сравнивалось: длина и
  число абзацев не изменились, содержательная оценка — чтением.
