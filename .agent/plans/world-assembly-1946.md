## Зачем это отдельная задача

Три записи правок существуют и приняты, но **ни одна не применена к геометрии**,
и применить их нечем: поиском по репозиторию (`rg -l region_edits_islands
scripts/`) видно, что запись островов не читает ни один скрипт — только
документы и построитель самой записи. Для нарезки океанов интеграции в водный
слой нет. `build_ph_regions_1946.py` производит geojson, который никто не
потребляет.

То есть работа — не «прогнать пайплайн», а **написать сборщик**, которого нет.
Предыдущие сессии это осознанно отложили: докстринг `build_world_after_edits.py`
говорит «СКРИПТ НИЧЕГО НЕ МЕНЯЕТ в живой карте. Применение — отдельная задача с
ExecPlan из-за позиционного каскада `region_id`».

Лицензионный блок по World Ablaze **снят** решением пользователя 2026-08-07
(`docs/DECISIONS.md`: имена заменены на свободные, делимитация оставлена, мод
упомянут благодарностью, «внедрение слоя в мир — следующая задача»).
Пользователь 2026-08-08 разрешил менять мастер.

## Порядок работы (каждый шаг проверяем отдельно)

Шаги идут по одному, с полным замером и коммитом после каждого. Совмещать
нельзя: `remap_region_ids.py` сопоставляет старые и новые id по паре
`(name, iso_a2)`, и два одновременных изменения состава дают неоднозначности,
которые он честно откажется разрешать.

### Шаг 0. Снимок «до»

`git show HEAD:client/public/world_1946.geojson > _world_OLD.geojson` —
вход для `remap_region_ids.py` на каждом последующем шаге.

### Шаг 1. Морские зоны в водный слой

Заменить океанские секторы мастера (`SEA-….*Sector`, точный список определить
замером — не по памяти) на 85 зон из `zones_*.geojson`.

- Зоны обрезаны нашим берегом ещё в прототипе — берег не трогать.
- Проверка: сумма площади воды не изменилась; наложений 0; дыр 0;
  `audit_map_geometry.py` без новых находок; `build_neighbor_graph.py`
  без изолированных узлов.
- Каскад: сдвигаются только `SEA-`; `names_ru.json` и `ownership_1946.json`
  ремапить обязательно.

### Шаг 2. Филиппины 36 -> 29

Прогнать `build_ph_regions_1946.py`, заменить 36 фич `iso_a2 == "PH"` на 29.

- Проверка: сумма площади Филиппин не изменилась; перекрытий 0; каждая старая
  фича попала ровно в одну новую (поле `merged_from` в записи).
- Каскад: сдвигается всё после `ASI-` — это самый опасный шаг.

### Шаг 3. Острова, 27 операций

Применить `out/region_edits_islands.json` (слияния, разделы, переименования).

- Проверка: та же — площадь, перекрытия, «ни потерь, ни дублей».

### Шаг 4. Каскад и экспорт

`remap_region_ids.py --old _world_OLD.geojson --prefix <…> --apply` по каждому
затронутому префиксу, затем `freeze_master_map.py`, затем полный
`make_1946.py`.

**Обязательный контроль после экспорта** (эта проверка уже поймала живой
дефект — см. ниже): для каждого региона имя в `names.en.json` совпадает с
`name` полигона мастера, кроме известного снятия индексов «Burgas (5)».

### Шаг 5. Починить сдвиг EUR-0371…0377

Существующий дефект, не вносимый этой работой: мастер зовёт `EUR-0371`
«Berlin — Soviet Sector», игра — «Kiel Canal Zone», и владельцы съехали вместе
с именами (советский сектор Берлина принадлежит британской зоне). Причина —
`out/names_ru.json` и `ownership_1946.json` привязаны к нумерации, в которой
зона канала стояла на 371. Шаг 4 ремапит их и обязан это закрыть; если не
закроет — чинить отдельно.

## Негативный контроль

- **Сдвиг имён.** Проверка шага 4 обязана падать на текущем состоянии: сейчас
  7 регионов из 1444 расходятся (EUR-0371…0377). Тест, не проверенный на
  способность падать, покрытием не считается.
- **Каскад.** До ремапа `remap_region_ids.py` без `--apply` (dry-run) обязан
  показать ненулевое число сдвигов; после — ноль.
- **Площади.** Любой шаг, изменивший суммарную площадь суши или воды больше
  чем на 1 км², считается провалившимся, а не «почти получившимся».
