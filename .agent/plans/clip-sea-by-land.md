## Assumptions and unknowns

Диагноз ("проблема в грубости морского полигона, не в суше") сделан по
наблюдению (все 19 — реальные, узнаваемые географические фичи; все
соответствующие моря — либо океанские секторы, либо крупные
низкодетальные именованные моря), не по независимому измерению
разрешения каждого конкретного морского полигона. Не проверено: не
существует ли более точный источник для этих конкретных морей (English
Channel/Caribbean Sea/Bering Sea и т.д.), который дал бы лучший результат,
чем "вычесть сушу из грубого полигона".

## Alternatives and selected decision

Рассмотрено: искать более точные источники геометрии для каждого из ~10
разных морей — отклонено как непропорционально трудозатратное для задачи
"убрать наложение из отчёта" (наложение всё равно визуально не заметно —
суша рендерится поверх моря); вычитание суши из уже существующего
морского полигона — простое, безопасное, достаточное решение для заявленной
цели (0 наложений в диагностике).

Рассмотрено: явный список 19 (имя_суши, имя_воды) пар (как `MANUAL_
REVIEW_APPROVED` в `clip_land_by_water.py`) — отклонено в пользу общего
прохода "вычесть из воды всё, что она ещё пересекает" — не требует
поддержки списка, не ломается при будущих геометрических изменениях,
автоматически не трогает уже разрешённые предыдущим проходом случаи (там
пересечения уже 0).

## Discoveries

Направление клипа (земля vs вода) определяется тем, КАКАЯ сторона
неточна — не константа "всегда резать сушу" или "всегда резать воду".
Общий (не по списку) проход после точечного/пороговое-безопасного прохода
естественно ловит ровно остаточное множество случаев, без риска рассинхрона
списка с геометрией.

## Decision log

- Общий проход вместо явного списка 19 имён — самоподдерживающееся
  решение, не список для ручного сопровождения.
- Не искать более точные источники геометрии морей — непропорционально
  трудозатратно для цели "0 наложений в diagnostic", а не "музейно точная
  форма каждого моря".
