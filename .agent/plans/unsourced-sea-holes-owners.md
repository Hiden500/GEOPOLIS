## Assumptions and unknowns

Владелец каждой дыры взят по ближайшей УЖЕ СУЩЕСТВУЮЩЕЙ фиче в датасете
(distance 0.055-1.08° до выбранного владельца против 1.5-14° до следующей
альтернативы во всех 8 кластерах) — не независимое историческое
исследование с нуля. Это осознанный выбор (см. Alternatives), не
ограничение точности: нашлись уже готовые, более точные решения (QPS для
Микронезии, GRL как отдельная страна), чем наивный современный lookup дал
бы. Риск: если в датасете САМ ближайший сосед имеет неверного владельца
для 1946 (не проверялось заново для каждого из 11 задетых регионов, только
для тех что стали ближайшими соседями новых дыр) — унаследуется и сюда.

## Alternatives and selected decision

Рассмотрено: независимое историческое исследование (WebSearch) для каждого
из 8 кластеров с нуля — отклонено как избыточное: nearest-existing-feature
lookup дал однозначный (большой разрыв дистанций) ответ для всех 8
кластеров, а для содержательно рискованных случаев (Микронезия — переходный
период Japan/USA; Гренландия — отдельная страна vs Дания) датасет уже
содержал более точное решение, чем можно было бы быстро найти заново.

Рассмотрено: создавать НОВЫЕ именованные регионы для каждой дыры (как
пакет A для 11 пропущенных территорий) — отклонено: у пакета A были
РЕАЛЬНЫЕ ADM1/ADM2 сырые фичи с именами (Isle of Man, Christmas Island и
т.д.), у этих 20 дыр источника нет вообще — придумывать имя для fragment'а
атолла/банки было бы искусственным. Слияние в ближайший существующий
регион — географически осмысленный результат "бесплатно", тот же метод
уже применяется для дыр С источником.

## Discoveries

Датасет уже содержит `QPS` ("U.S. Naval Administration of the Former
Japanese Mandated Islands") как владельца Yap/Pohnpei — историческая
переходная администрация 1946 г. между капитуляцией Японии (1945) и
формальной UN Trust Territory (1947), точнее наивного современного
"Федеративные Штаты Микронезии". Аналогично Гренландия — отдельная
разыгрываемая страна (`GRL`), не слита в Данию. Оба — evidence, что
nearest-existing-feature lookup эффективнее независимого исследования с
нуля, когда датасет уже содержит вдумчивое решение.

Побочная находка при верификации: чужой (не мой) процесс слушал порт 3000
— командная строка указывала на главный checkout, не на этот worktree.
НЕ тронут (правило AGENTS.md про параллельные сессии) — верификация
сделана через отдельный явный порт вместо попытки разобраться, чей это
процесс. См. новый урок в skill `map-geometry-qa`.

## Decision log

- Владелец по nearest-existing-feature, не по независимому историческому
  исследованию — обосновано разрывом дистанций (0.055-1.08° vs 1.5-14°)
  и тем, что датасет уже содержал более точные решения для рискованных
  случаев.
- Слияние в существующий регион, не новый именованный регион — у этих
  дыр нет сырого источника с именем (в отличие от пакета A), придумывать
  имя было бы искусственным.
- Чужой процесс на порту 3000 — не тронут, верификация через отдельный
  порт вместо risky taskkill без уверенности во владельце процесса.
