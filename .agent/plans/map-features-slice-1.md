## Решено пользователем 2026-08-02: готовое поле `isCoastal`

Побережье считает пайплайн и кладёт булев `isCoastal` в `regions.core.json`.
Отвергнут альтернативный путь — пустить `SEA-` в `neighboringRegionIds`: он
меняет контракт поля, которое сегодня гарантированно land-only, и это увидел
бы весь серверный код, читающий соседей, ради одного булева признака. Вернуться
к нему можно, когда появится морская механика и морские зоны войдут в сценарий
(сейчас их там 0).

**Нового шага пайплайна не требуется — данные уже считаются и выбрасываются.**
`build_neighbor_graph.py` кладёт в `neighbor_graph.json` морских соседей вместе
с сухопутными, а `import_to_game.py:238` отбрасывает неземных при сборке
`neighboringRegionIds`. Ровно в этом месте и надо запомнить факт, а не
пересчитывать геометрию.

Замер 2026-08-02 по `neighbor_graph.json` — целевые числа приёмки:

| | регионов |
|---|---|
| сухопутных всего | 1451 |
| **с морским соседом → `isCoastal: true`** | **780** |
| только с озером → `isCoastal: false` | 50 |
| полностью внутренних | 621 |

**Озеро побережьем не считается.** 50 регионов касаются только `LAK-`; для
десанта и портов они внутренние. Правило: `isCoastal` истинно тогда и только
тогда, когда среди соседей есть `SEA-`.

Контроль: у всех 174 регионов-одиночек на островах морской сосед есть, то есть
ни один остров не окажется «внутренним».

## Scope

В срез входит:

1. `isCoastal` в `regions.core.json` — заполняется в `import_to_game.py` там же,
   где сегодня отбрасываются неземные соседи; `isCoastalRegion()` в
   `generateMapFeatures.ts` читает готовое поле вместо `return false`.
   Поле добавляется в тип региона в `shared/src/types/` — **правится в одной
   ветке**, параллельно нельзя (`AGENTS.md`);
2. генерация `port` для прибрежных регионов — правило отбора (все прибрежные?
   только с населением выше порога? только с городом?) предложить числом и
   показать, сколько портов получилось;
3. `city`-точки для Ленинграда, Киева и Минска — с координатами и привязкой к
   региону-приёмнику;
4. `mine` из `deposits`/`extraction` — правило отбора предложить и показать
   счёт по типам ресурсов.

В срез НЕ входит: экономические шаблоны input/output по типу фичи (это
игро-дизайн, `docs/MAP_FEATURES.md` Q6.1); военные объекты сверх нынешнего
`battalion`; протесты и восстания; дипломатические оверлеи; коннекторы
(`railway`/`canal`/`pipeline`) — они ждут модели потока (`TRADE.md` Q7).

Не задваивать `ResourceTick`: он единственный источник добычи
(`docs/ECONOMY.md`), а `mine` — визуальный маркер. Тот же урок, что с
удалённым `ProductionTick`.
