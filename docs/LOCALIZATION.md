# Локализация

Last updated: 2026-07-18

> **Текущий статус:** UI-слой на `react-i18next` реализован, включая HUD;
> data-layer локализован — `LocalizedText` покрывает `Region.names` и
> `Country.name`/`shortName` (мигрировано 2026-07-18). `en` есть всегда;
> на дату миграции `ru` был авторен только для части сущностей (~105 из
> ~199 стран сценария 1946) — остальные страны показывали английское имя
> даже при русском UI, намеренно, без выдуманных переводов. На сегодня
> перевод реестра 1946 года полный: `ru` есть у всех 157/157 стран сценария
> (`server/data/scenarios/1946/countries.json`).

## Назначение

Дом для дизайна мультиязычности игры. Два независимых слоя, с разными
инструментами и статусом — не путать один с другим:

1. **Данные** (`LocalizedText`) — имена сущностей мира: страны, регионы,
   в будущем — названия технологий/техники/фракций и т.п. Хранится как
   часть `GameState`, авторится/генерируется вместе с контентом.
2. **UI-строки** (`react-i18next`) — интерфейс клиента: кнопки, заголовки
   панелей, статичные подписи. Не часть `GameState`, живёт только в
   `client/`, ничего общего с данными партии.

`GameState.locale` — язык нарратива LLM (`title`/`descriptions`), выбирается
один раз при создании партии, не меняется на лету. С этого захода тот же
выбор на экране `ScenarioSelector` дополнительно управляет и языком
интерфейса (см. ниже) — один выбор, не два независимых.

Применимые правила для новых полей/строк: root `AGENTS.md` и
`client/AGENTS.md`.

## Критерий выбора слоя

Слой определяется одним вопросом: **кто задаёт множество строк**.

- Множество задаёт **контент** и расширяется без правки кода → строка живёт в
  данных с `LocalizedText`. Список стран приносит сценарий: 1946 даёт свои 157,
  1836 даст другие, мод — третьи. В словарях интерфейса они потребовали бы
  править клиент при каждом добавлении страны, то есть контент перестал бы быть
  контентом.
- Множество задаёт **движок** и оно фиксировано → строка живёт ключом в
  `react-i18next`. Ступени шкалы идеологии (`shared/src/defines/ideologyBands.ts`)
  — ровно семь на ось в любом сценарии; хранить их в данных значило бы
  дублировать четырнадцать одинаковых строк в каждом сценарии, а третий язык
  требовал бы правки сценарных данных.

Критерий не «где лежит файл» и не «это UI или не UI». Один каталог может
разойтись по обоим слоям — так устроен каталог идеологических зон
(2026-07-27): ступени шкалы задаёт движок и переводит словарь, именованные
якоря («Перонизм», «Либерализм Нового курса») приносит эпоха, и они несут
`LocalizedText` в `GameState.ideologyAnchors`.

**Производные строки не хранятся вообще.** Ярлык идеологии страны вычисляется
из координат (`shared/src/utils/ideologyLabel.ts`), а не лежит в данных: иначе
сдвиг курса реформой оставил бы игроку прежнюю надпись, а переводов
понадобилось бы 157 по числу стран вместо 30 по числу зон. Хранимое
`Country.politics.ideology` — легаси, оставшееся до сессии союзов
(`docs/DECISIONS.md`, 2026-07-27); игроку оно уже не показывается.

## Слой 1: данные (`LocalizedText`)

`shared/src/types/i18n/LocalizedText.ts`:
- `type Locale = "ru" | "en"` — расширяется по мере добавления языков.
- `type LocalizedText = Partial<Record<Locale, string>>`.
- `DEFAULT_LOCALE = "ru"`, `LLM_LOCALE = "en"` (какой локалью имена уходят в
  промт LLM — независимо от локали партии, LLM стабильно получает
  английские id/названия для читаемости, сама пишет нарратив на
  `GameState.locale`).
- `getText(text, locale)` — фолбэк-цепочка: запрошенная → en → ru → любая
  доступная → пустая строка.

**Реализовано:** `Region.names`, `Country.name`/`Country.shortName`
(2026-07-18, вместе с работой над 1946 country-entities — не отдельный заход,
т.к. пользователь явно попросил билингвальность для этого прохода).
12 рукописных файлов стран (`server/src/data/countries/*.ts`, сценарии
1836/2000) механически обёрнуты в `{en: "..."}` — без нового контента, тип
меняется, содержание нет. Генератор 1946 (`scripts/map/generate_country_
registry.py::make_country()`) эмитирует `{en, ru?}`: `ru` берётся из
`historicalNameRu`/`name_ru` конфига только там, где он реально авторен —
остальные страны реестра получают только `en`, без выдуманного перевода как
побочного эффекта.

**Исправлено (2026-07-18):** все клиентские вызовы `getText()` без
`i18n.language` теперь передают текущую локаль явно — и на сервере
(`LLMService.ts` — явно `LLM_LOCALE`, независимо от локали партии, как и раньше
для нарратива). Большинство панелей из того списка удалено вместе со старым
слоем 2026-08-07; из переживших правило держат `client/src/map/GeoJsonLoader.ts`,
`ScenarioSelector.tsx` и весь новый экран (`client/src/game/adapter.ts` получает
локаль параметром и не читает её из модуля).

## Слой 2: UI-строки (`react-i18next`)

Выбрана намеренно (не самодельное решение) — обсуждение и обоснование в
`docs/decisions/2026-07.md`/`docs/DECISIONS.md`: решающий довод — русская
плюрализация (1/2-4/5+ разные формы), которую пришлось бы переизобретать
вручную, причём поначалу неправильно.

### Хранение — namespace на компонент

```
client/src/i18n/
  index.ts                    # i18next.init()
  locales/
    ru/
      common.json              # общие строки (кнопки/ошибки)
      <componentName>.json     # по одному на компонент
    en/
      common.json
      <componentName>.json
```

Не единый монолитный файл на локаль — раздельные namespace позволяют
мигрировать компоненты параллельно без конфликтов на одном файле и держат
перевод рядом по смыслу с компонентом, который его использует.

### Переключение языка

Единая точка входа — существующий пикер на `ScenarioSelector.tsx` (был
подписан "Язык повествования LLM", переименован в "Язык" — теперь управляет
и интерфейсом, и нарративом LLM). Выбор вызывает `i18n.changeLanguage()`
сразу (живое переключение экрана выбора) и передаётся как обычно в
`GameState.locale` при создании партии. `App.tsx` дополнительно
подстраховывается `useEffect` на `game.locale` (на случай, если партия
загружена без прохода через селектор).

### Осознанно не тронуто

- **`client/src/map/MapView.tsx`** получил только точечный фикс (2026-07-18):
  `loadGameMapData`/`updateMapData` (`GeoJsonLoader.ts`) теперь принимают
  `locale` и резолвят `Country.name`/`Region.names` через `getText()` вместо
  падения по типу — иначе карта не типизировалась бы после миграции `Country`.
  Полноценная UI-строки-миграция самого `MapView.tsx` (легенда, попапы,
  контролы зума) по-прежнему не сделана — вне скоупа этого захода.
  `useEffect`, вызывающие `loadGameMapData`/`updateMapData`, не подписаны на
  `i18n.language` в зависимостях (уже был `eslint-disable exhaustive-deps` на
  первом из них) — переключение языка на лету не перерисовывает названия на
  карте без смены regions/countries; известный, некритичный пробел.

## Статус

**Реализовано:** `react-i18next`/`i18next`, namespace-файлы ru/en,
переключатель языка. Набор namespace держится равным тому, что просит живой
код: `client/src/i18n/__tests__/localeKeys.test.ts` падает и на ключе, которого
нет в словаре, и на расхождении наборов между локалями. Исторический
browser-check 2026-07-10 подтвердил тогдашний legacy UI; global audit
2026-07-15 выполнил typecheck/tests, но не новый end-to-end browser flow.

**Крупный незакрытый долг (2026-08-07):** новый экран почти не локализован.
`client/src/game/adapter.ts`, `Screen.tsx` и `panels.tsx` держат русские
строки прямо в коде — названия ТОМОВ, вкладки региона, подписи осей идеологии,
весь текст окна ручного цикла. Английской версии у них просто нет. Требование
«новые user-facing строки через `react-i18next`» (`AGENTS.md`) на этом слое
нарушено, и долг растёт с каждой правкой экрана.

**Известный, некритичный пробел:** id ресурса показывается как есть (`food`,
`timber`, `coal`...) в списке добычи по региону. Панель, где это было замечено
в 2026-07, удалена вместе со старым слоем, но сам пробел переехал в ПОЛОСУ
региона нового экрана; словарь `resourceTicker.json` с готовыми переводами
удалён вместе со своей панелью, так что переводы придётся завести заново.

**Не в этом заходе:** механизм live-пересчёта данных при переключении языка
без пересоздания партии/повторной загрузки (см. пробел `MapView.tsx` выше);
полная миграция UI-строк самой карты.
