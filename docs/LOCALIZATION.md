# Локализация

Last updated: 2026-07-06

> **UI-слой v1 в процессе реализации** (`react-i18next`, независимый
> гейм-дизайн разбор, 2026-07-06). Слой данных (`LocalizedText`) существует
> дольше и покрывает только `Region.names` — `Country.name`/`shortName`
> остаются `string`, отдельный, более поздний заход (не в этом).

## Назначение

Дом для дизайна мультиязычности игры. Два независимых слоя, с разными
инструментами и статусом — не путать один с другим:

1. **Данные** (`LocalizedText`) — имена сущностей мира: страны, регионы,
   в будущем — названия технологий/техники/фракций и т.п. Хранится как
   часть `GameState`, авторится/генерируется вместе с контентом.
2. **UI-строки** (`react-i18next`) — интерфейс клиента: кнопки, заголовки
   панелей, статичные подписи. Не часть `GameState`, живёт только в
   `client/`, ничего общего с данными партии.

`GameState.locale` — язык нарратива LLM (`title`/`descriptions`), выбирается
один раз при создании партии, не меняется на лету. С этого захода тот же
выбор на экране `ScenarioSelector` дополнительно управляет и языком
интерфейса (см. ниже) — один выбор, не два независимых.

Смежные доки: `AGENTS.md` §"Design for Multi-Locale From the Start"
(постоянное правило для новых полей/строк, не дублируется здесь).

## Слой 1: данные (`LocalizedText`)

`shared/src/types/i18n/LocalizedText.ts`:
- `type Locale = "ru" | "en"` — расширяется по мере добавления языков.
- `type LocalizedText = Partial<Record<Locale, string>>`.
- `DEFAULT_LOCALE = "ru"`, `LLM_LOCALE = "en"` (какой локалью имена уходят в
  промт LLM — независимо от локали партии, LLM стабильно получает
  английские id/названия для читаемости, сама пишет нарратив на
  `GameState.locale`).
- `getText(text, locale)` — фолбэк-цепочка: запрошенная → en → ru → любая
  доступная → пустая строка.

**Реализовано:** `Region.names`.
**Не реализовано:** `Country.name`/`Country.shortName` — всё ещё `string`.
Мигрировать нужно вместе с 12 рукописными файлами стран
(`server/src/data/countries/*.ts`, сценарии 1836/2000) и сгенерированным
реестром 1946 — отдельный заход, не делать походом при других задачах
(`AGENTS.md`).

**Известный, но не критичный баг:** часть клиентских вызовов `getText()`
(`inspectorTitle.ts`, `PlayerIntentPanel.tsx`, `TerritoriesPanel.tsx`,
`map/GeoJsonLoader.ts`) не передают локаль явно — молча берут
`DEFAULT_LOCALE`. Незаметно, пока весь интерфейс всё равно русский; станет
реальным багом, когда интерфейс (слой 2) начнёт нести реальную локаль.
Почистить при миграции `Country` или раньше, если раздражает раньше.

## Слой 2: UI-строки (`react-i18next`)

Выбрана намеренно (не самодельное решение) — обсуждение и обоснование в
`docs/decisions/2026-07.md`/`docs/DECISIONS.md`: решающий довод — русская
плюрализация (1/2-4/5+ разные формы), которую пришлось бы переизобретать
вручную, причём поначалу неправильно.

### Хранение — namespace на компонент

```
client/src/i18n/
  index.ts                    # i18next.init()
  locales/
    ru/
      common.json              # общие строки (кнопки/ошибки)
      <componentName>.json     # по одному на компонент
    en/
      common.json
      <componentName>.json
```

Не единый монолитный файл на локаль — раздельные namespace позволяют
мигрировать компоненты параллельно без конфликтов на одном файле и держат
перевод рядом по смыслу с компонентом, который его использует.

### Переключение языка

Единая точка входа — существующий пикер на `ScenarioSelector.tsx` (был
подписан "Язык повествования LLM", переименован в "Язык" — теперь управляет
и интерфейсом, и нарративом LLM). Выбор вызывает `i18n.changeLanguage()`
сразу (живое переключение экрана выбора) и передаётся как обычно в
`GameState.locale` при создании партии. `App.tsx` дополнительно
подстраховывается `useEffect` на `game.locale` (на случай, если партия
загружена без прохода через селектор).

### Осознанно не тронуто в этом заходе

- **`client/src/map/MapView.tsx`** — карта заморожена решением пользователя
  (2026-07-03), даже точечная замена строк на `t()` формально задача по
  файлу карты. Не трогать без явного запроса.
- **Названия стран/регионов на карте, в списках** — это слой 1 (данные), не
  слой 2 (UI-строки), отдельный заход.

## Статус

**Реализовано (2026-07-10):** слой 2 (UI-строки) полностью развёрнут.
`react-i18next`/`i18next` установлены, `client/src/i18n/index.ts`
инициализирован (16 namespace на ru/en), `main.tsx` подключает как
побочный эффект. Все 15 клиентских компонентов с текстом мигрированы —
`App.tsx`, `ScenarioSelector.tsx` (плюс живой переключатель языка) и
13 игровых панелей (`BudgetPanel`, `ErrorBoundary`, `EventTimelinePanel`,
`GameView`, `InspectorPanel`, `LLMPanel`, `PlayerIntentPanel`,
`ResearchPanel`, `ResourceTicker`, `TerritoriesPanel`, `TopStatBar`,
`Window`, `WorldRankingPanel`). `Record<string,string>`-карты лейблов
(категории бюджета, домены исследований, названия ресурсов) убраны в
пользу `t()`. Живая проверка в браузере: переключение языка на экране
выбора сценария распространяется на весь интерфейс партии без
перезагрузки; `npx tsc -b --noEmit` и `npx vitest run` (83/83) в `client/`
чистые.

**Известный, некритичный пробел:** `TerritoriesPanel.tsx` показывает id
ресурса как есть (`food`, `timber`, `coal`...) в списке добычи по
региону — так было и до этого захода (не регрессия), просто теперь по
соседству есть `resourceTicker.json:resources.*` с готовыми переводами,
которые можно переиспользовать. Не тронуто нарочно — точечная правка вне
скоупа файла-по-агенту; отдельная минорная задача, не блокирует ничего.

**Не в этом заходе (см. слой 1 выше):** `Country.name`/`shortName` всё ещё
`string`, карта (`map/MapView.tsx`) не тронута.
