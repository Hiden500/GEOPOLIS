# STACK PLAYBOOK — процессы под конкретный стек

> **HISTORICAL / EXPLANATORY (2026-07-15).** Это snapshot раннего bootstrap,
> не активный runbook. Реальные команды — manifests/CI, краткий matrix —
> root/nested `AGENTS.md` и skill `verify-change`. Ниже есть stale claims.

Практика работы с TS / Vitest / Zod / Python-пайплайном / Windows на момент
создания snapshot.

---

## Карта монорепо

```
client/   — React 19 + Vite + MapLibre; свой package.json, tsconfig, vitest
server/   — Express 5 + tsx; свой package.json, tsconfig, vitest
shared/   — типы/утилиты/данные; НЕ собирается отдельно, подключается алиасом
            @shared из обоих tsconfig (paths). Зависимостей не имеет.
scripts/map/ — Python-пайплайн карты (оффлайн, не рантайм)
server/data/ — данные сценариев (генерируются пайплайном, руками не править)
docs/     — авторитетная документация; docs/plans/ — планы аудита
```

Правило: изменение в `shared/` затрагивает оба workspace — проверять оба.

## Команды (Windows, PowerShell; из корня репо)

| Что | Команда |
|---|---|
| dev-сервер API | `cd server; npm run dev` (tsx watch, порт 3000) |
| dev-клиент | `cd client; npm run dev` (Vite; прокси API см. vite.config.ts) |
| тесты сервера | `cd server; npm test` (vitest run) |
| тесты клиента | `cd client; npm test` |
| один файл тестов | `cd server; npx vitest run src/simulation/war/WarTick.test.ts` |
| typecheck сервер | `cd server; npx tsc --noEmit -p tsconfig.json` |
| typecheck клиент | `cd client; npx tsc --noEmit -p tsconfig.app.json` |
| lint клиент | `cd client; npm run lint` |
| пайплайн карты | `python scripts/map/make_1946.py` (после плана 05; до него — цепочка по scripts/map/README.md) |
| валидация данных | `python scripts/map/validate_region_economy_1946.py` |

## Верификация перед коммитом (минимальный обязательный набор)

1. typecheck затронутых workspace (изменён shared → оба);
2. vitest затронутых workspace;
3. lint клиента, если трогал client;
4. валидатор данных, если трогал scripts/map или server/data;
5. симуляция менялась → same-seed тест и кампания-смок зелёные.

CI повторяет это в `.github/workflows/ci.yml` — локальный прогон обязан
предсказывать зелёный CI, «проверит CI» — не стратегия.

## Паттерны TypeScript этого проекта

- **Типы состояния** — `interface` в `shared/src/types/`, только
  сериализуемые поля. Дискриминированные union'ы — с полем `type`/`kind`.
- **Zod на границах, типы из схем.** Всё входящее извне (HTTP-body, ответ LLM,
  файлы данных) проходит `schema.parse/safeParse`; TS-тип выводится `z.infer`
  — не писать тип и схему параллельно.
- **Тики** — чистые функции `(game|country, ...deps) => void` в
  `server/src/simulation/<домен>/`; сервисы-классы не плодить (исторические —
  постепенно разбирать при касании). Новая логика — функции + команды.
- **Импорты shared** — только через алиас `@shared/...`, не относительными
  путями через workspace-границу.
- **ESM** (`"type": "module"`) — расширения и import-стиль как в соседних файлах.
- Комментарии в коде — русские, объясняют ограничение/решение со ссылкой на
  док/план (существующая конвенция), не пересказ строки.

## Паттерны тестирования (Vitest)

- Фикстуры мира — `server/src/test-utils/fixtures.ts`; расширять её хелперы
  (страна/регион/война с override-параметрами), не копипастить мир по тестам.
- Тик-тесты лежат рядом с тиком (`XTick.test.ts`), интеграционные — в
  `__tests__/`. Следовать существующей раскладке.
- Кампания-смок — единственное место, где допустимы «мягкие» assert'ы
  (диапазоны, инварианты); юнит-тесты assert'ят точно.
- Клиент: happy-dom + @testing-library — тестировать поведение хуков/логики
  (`useWindows.test.ts` — образец), не снапшоты разметки.
- Детерминизм-тест (после плана 01): хелпер `runCampaign(seed, months)` →
  глубокое сравнение двух прогонов. Гонять в каждом PR, затрагивающем симуляцию.

## Python-пайплайн

- Python ≥3.10, зависимости скриптов — стандартная библиотека (+ shapely,
  если добавится в плане 06 для point-in-polygon).
- Скрипты детерминированы: никакого random — джиттер только хэшем от id
  (существующая конвенция fill_region_economy).
- Выход пайплайна — единственный источник `server/data/**`; правка выхода
  руками запрещена (протокол данных в PROTOCOLS.md).
- Кодировки: файлы UTF-8; на Windows в скриптах открывать с
  `encoding="utf-8"` явно (уже конвенция).

## LLM-слой: как менять безопасно

Любое изменение контракта LLM трогает ЧЕТЫРЕ точки одновременно —
рассинхрон любой пары это баг:
1. текст промта (`LLMService.generatePrompt` — описание формата действий);
2. Zod-схема действия (`actionSchemas.ts`, после плана 02);
3. применение (маппинг действия на команду);
4. тест (валидное применяется / невалидное отклоняется с причиной).

Ручной clipboard-путь и автопуть (GeminiProvider) обязаны принимать один и
тот же формат — тестировать оба через общую точку `processResponse`.

## Git

- Ветки: `claude/<task>`; main всегда зелёный; мерж — только с зелёными тестами.
- Коммиты мелкие и тематические: рефакторинг отдельно от поведения, данные
  отдельно от кода, если возможно.
- Локальные коммиты — без запроса (standing-авторизация AGENTS.md);
  push и rewrite — только с явного подтверждения.
- Не коммитить: сгенерированное вне конвенции, `.env`, большие бинарники.
  Данные `server/data/**` и `scripts/map/out/**` коммитятся (конвенция
  воспроизводимости), с регенерацией через пайплайн.

- `Map`/`Set` в GameState молча превращаются в `{}` при `res.json` — уже
  стреляло (regionIndex). Правило 1 конституции.
- Изменил владение региона в обход команды — протухают индексы и агрегаты.
- Забытый док-футпринт — главный исторический провал агента: самопроверка
  перед завершением хода обязательна.
- Обрезанный вывод консоли — писать в файл и читать файл.
- `client/src/map/**` под freeze (домен Gemini/MAS) — не трогать без явного
  запроса пользователя.
