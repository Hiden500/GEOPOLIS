# ARCHITECTURE GUARDRAILS — удержание качества архитектуры в долгую

Принцип: правило, которое не проверяется автоматически, перестаёт соблюдаться
через месяц. Каждое правило конституции получает **fitness-функцию** —
исполняемую проверку в тестах или CI. Этот файл — реестр таких проверок и
процесс их эволюции.

---

## Fitness-функции конституции

| # | Правило | Проверка | Вид |
|---|---|---|---|
| 1 | GameState = plain JSON | тест: `expect(JSON.parse(JSON.stringify(game))).toEqual(game)` после createGame и после 12 месяцев симуляции | vitest |
| 2 | Мутации через команды | ревью-чек-лист + (после плана 03) grep-тест: в `simulation/**` нет записи в `diplomacy.relations[...] =` и т.п. вне `commands/` — список запретных паттернов пополняется при каждом инциденте | vitest (grep) |
| 3 | Эффекты — модификаторы | ревью-чек-лист; тест системы модификаторов на истечение | vitest |
| 4 | Баланс в defines | grep-тест: в `server/src/simulation/**` нет `const X = <число>` кроме белого списка структурных литералов | vitest (grep) |
| 5 | Детерминизм | (а) grep-тест: нет `Math.random`/`Date.now`/`new Date()` в `simulation/**`, `sim/**`, `services/**` кроме белого списка; (б) same-seed тест: `runCampaign(seed, 24)` дважды → deepEqual | vitest |
| 6 | LLM-контракт через Zod | тест: `processResponse` отклоняет действие вне схемы; за-каповое — с причиной; сырые координаты в действии — отклоняются | vitest |
| 7 | Контент через реестры | тест: неизвестный тип фичи/ресурса отклоняется валидатором реестра | vitest |
| 8 | LocalizedText/i18n | (а) grep-тест: новые name-поля в shared-типах не `string` (список исключений — легаси до миграции); (б) lint-правило/скрипт: в client/src нет русских строковых литералов вне locales/ | vitest + lint |
| 9 | Производное не хранится | покрывается №1 (Map/Set не переживут round-trip) + ревью | — |
| 10 | Слои не текут | grep-тест: в `shared/src/**` нет импортов из `server/`/`client/`; в `client/src/**` нет импортов из `server/src` | vitest (grep) |

Реализация grep-тестов: один файл `server/src/__tests__/architecture.test.ts`
(читает исходники fs+glob, ассертит паттерны). Дешевле и надёжнее кастомных
eslint-плагинов; переносить в eslint только то, что нужно подсвечивать в IDE.

## Данные

- CI-job валидации данных (план 05): инварианты целостности (симметрия
  соседей, владельцы существуют, столицы у своих стран, ресурсы из каталога,
  полнота локалей, население в допуске якорей).
- Правка `server/data/**` без правки `scripts/map/**` в том же диффе —
  подозрение на ручную правку данных: ревью-флаг.

## Кампании-смоки как долгосрочный радар баланса

`campaignSmoke.test.ts` — расширять при каждой механике. Целевой набор:
- 24 месяца мирного мира: нет NaN/Inf, население/ВВП в порядках, ни одна
  страна не обнулилась без причины;
- война мажоров до мира (после плана 08): война завершается, карта согласована;
- 120 месяцев: числа не разгоняются экспоненциально сверх допmedia
  (радар проблемы «264 года», бэклог 4.2).
Ассерты — инварианты и диапазоны, не точные числа (иначе смоки станут
тормозом любой калибровки).

## Процесс архитектурных изменений

1. Конституция меняется только явным решением пользователя; изменение =
   правка MASTER_PROMPT.md + датированная запись в DECISIONS.md + обновление
   fitness-функции в тот же ход.
2. Новое архитектурное правило без fitness-функции не принимается —
   «джентльменские соглашения» здесь не работают (проверено историей проекта).
3. Исключения из правил (белые списки grep-тестов) — с комментарием-причиной
   и датой; раз в квартал белые списки пересматриваются на предмет чистки.

## Регулярный аудит дрейфа (каждые ~20 коммитов или раз в месяц)

Чек агент проходит сам, результат — короткий отчёт пользователю:

1. **Док ↔ код:** ARCHITECTURE.md описывает реальные типы? Планы в
   docs/plans/README.md имеют актуальные статусы? TODO не содержит сделанного?
2. **Белые списки** fitness-тестов не разрослись?
3. **Дублирование:** новые сервисы/утилиты, дублирующие существующие
   (быстрый проход по `services/` и `shared/src/utils/`).
4. **Размер горячих файлов:** LLMService.ts, MapView.tsx и другие >500 строк —
   кандидаты на разбиение при следующем касании (не рефакторить превентивно).
5. **Мёртвый код/данные:** неиспользуемые экспорты и файлы-сироты
   (прецедент: 37 МБ game_map.json лежал мёртвым).
6. **Тестовое время:** сьют дольше ~60 с — искать квадратичные фикстуры.

## Бюджеты (мягкие пороги, превышение = обсудить, не запрет)

| Метрика | Бюджет | Зачем |
|---|---|---|
| Полный сейв | ≤ 5 МБ | скорость автосейва, git-диффы фикстур |
| Ответ `/game/state` | ≤ 2 МБ | до внедрения дельт этого хватает |
| Промт LLM | следить за ростом при каждом изменении generatePrompt (лог размера в dev) | контекст-бюджет — главный ресурс игры |
| Тик simulateMonth | ≤ 50 мс | запас ×100 к текущему; выход за бюджет = квадратичный алгоритм |
| Начальная загрузка карты | ≤ 5 МБ по сети | план 05 |

## Долгосрочные направления (проверять решением, а не привычкой)

- **Симуляция в shared/, сервер опционален** — стратегическая опция аудита
  (браузерный Web Worker + BYO-ключ). Каждое новое использование Node-API в
  симуляции (fs, process) отдаляет её — fitness-идея: grep на node-импорты в
  `shared/src/sim/**`.
- **Дельты состояния вместо полного GameState** клиенту — включать только
  при реальном превышении бюджета ответа, не превентивно.
