2. **Типы зашиты в TS union** (`shared/src/types/map/MapFeature.ts`, 25 типов) —

3. **Дрейф «визуал → механика» без решения.** Декларировано «визуальные

4. **Гигиена:** id через `Math.random`; нет поля происхождения (кто создал);

## Целевая модель

### Принцип 1: фича презентационна, механика — в модификаторах

Фича может ссылаться на модификаторы (план 03): завод = иконка +
`grantsModifierIds` (например `+X industryOutput` региона). Фича уничтожена →
модификаторы сняты. Механическая истина в одном месте.

### Принцип 2: два класса якорей

| Класс | Примеры | Якорь | Откуда координаты |
|---|---|---|---|
| Реальная география | города, столицы, порты, каналы, проливы | точка `[lng, lat]` | **датасет в пайплайне** |
| Динамика геймплея | батальоны, протесты, заводы, фронты | `regionId` | **резолвер движка** |

- **cities.json из пайплайна:** источник Natural Earth populated places /
  GeoNames (имя, население, точные координаты, флаг столицы). Скрипт фильтрует
  по порогу населения, мапит точку в регион (point-in-polygon), выдаёт
  `data/scenarios/<era>/cities.json`. Настоящие Мюнхен/Харьков/Осака для всех
  стран; `CAPITAL_OVERRIDES` удаляется; generateMapFeatures строит
  столицы/города из этого файла.
- **Резолвер размещения** (один модуль, детерминированный): динамическая фича
  получает regionId, точку вычисляет движок — прищёлкивая к ориентиру:
  завод → крупнейший город региона или deposit (план 04); протест → город;
  батальон → граница контакта; fallback — центроид региона + детерминированное
  смещение от id фичи (чтобы иконки не слипались).
- **LLM никогда не выдаёт сырые координаты** — только regionId / id городов;
  валидатор проверяет по справочнику; точку ставит резолвер.

### Принцип 3: реестр типов в данных

`shared/src/data/featureTypes.json`:
```json
{ "id": "steel_mill", "category": "industry", "iconId": "steel_mill",
  "defaultMinZoom": 5, "defaultTags": ["industry"],
  "effectTemplate": { "attribute": "industryOutput", "op": "mul", "value": 1.05 } }
```
- Новый тип = строка в JSON + иконка. TS-тип `MapFeatureType` становится
  `string`, валидность проверяется по реестру.
- **Манифест иконок** под генерацию (Nano Banana): список iconId + стиль-гайд
  в одном файле; генерировать пачкой по манифесту, не поштучно — иначе зоопарк
  стилей. Спрайт-атлас для MapLibre собирается из манифеста.

### Гигиена и масштаб

- id фичи — счётчик `GameState.nextFeatureId` (см. план 01), не random.
- Поле `source: "scenario" | "engine" | "llm"` — для отладки и чистки.
- Рендер: **один GeoJSON-source + symbol layer** MapLibre со спрайтом и
  зум-фильтрами (не React-компоненты на фичу) — держит 10⁴–10⁵ символов.
- Промт LLM: агрегаты («в регионе 3 завода, 1 авиабаза») + фичи, релевантные
  текущим событиям; никогда весь список.
- Индекс фич по regionId — вычисляемый, не хранимый.
- LLM-действия: `create_feature` / `remove_feature` с белым списком типов из
  реестра и капами на ход (через команды плана 03).

## Критерии приёмки

- [ ] Все столицы и города имеют реальные имена и координаты из cities.json; CAPITAL_OVERRIDES удалён.
- [ ] Динамическая фича без координат отображается в осмысленной точке региона (тест резолвера: детерминизм, попадание в полигон).
- [ ] Новый тип фичи добавляется без правки TS-кода (тест: тип из реестра проходит валидацию, неизвестный — нет).
- [ ] Фича с effectTemplate создаёт/снимает модификатор при создании/удалении (тест).
- [ ] 10 000 сгенерированных фич рендерятся без деградации FPS (ручная проверка) и не попадают в промт списком.
