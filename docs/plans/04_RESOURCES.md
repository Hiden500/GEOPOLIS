## Проблемы (текущее состояние)

`region.resourceProduction` — одно число, означающее сразу три вещи:
геологический потенциал, текущую добычу и изменяемое состояние
(`ResourceTick.ts:47-53` истощает его на 0.01%/мес прямо в данных).

Следствия:
- нельзя отличить «мало нефти» от «нефть есть, добыча не развёрнута» и от
  «добыча разрушена войной»;
- нет механики стройки шахт («шахты рядом с месторождениями» из PROJECT.md
  невыразимы);
- LLM/события не могут безопасно менять производство — только перезаписать число.

Заготовка уже есть: `shared/src/types/resources/ResourceDeposit.ts` существует,
но не используется. Каталог `shared/src/data/resources/resourceCatalog.ts`
(«только сырьё, переделы — выход промышленности») — правильный, не менять.

## Целевая модель — три слоя

| Слой | Что | Где живёт | Кто меняет |
|---|---|---|---|
| **Deposit** | `{ resource, richness, techGate? }` — потенциал | данные сценария (regions) | почти никто: истощение медленно, открытие — событие |
| **Extraction** | уровень добывающих мощностей 0..N по ресурсу | GameState | команды: стройка, война, события, LLM |
| **Output** | добыча за тик | **не хранится** — вычисляется | никто |

Формула тика:
```
output = richness × extractionFactor(level) × infraBonus × techBonus × modifiers
```
Существующие бонусы ResourceTick (инфраструктура, домен industry, сектор
mining) сохраняются как множители; их коэффициенты — в defines (план 03).

### Шаги

1. Типы: `RegionDeposit { resource, richness }` в Region (переименовать/пере-
   использовать поле `resourceProduction` → `deposits`; миграция данных — скриптом
   пайплайна, см. шаг 4). `Region.extraction: Partial<Record<ResourceId, number>>`
   — стартовый уровень задаётся сценарием (сегодняшние значения производства
   нормировать в richness × стартовый level = текущий выход, чтобы баланс не
   сдвинулся в момент миграции).
2. ResourceTick: считает output по формуле, кладёт в stockpile. Истощение —
   на richness депозита, скорость в defines. Output за последний тик можно
   кэшировать в поле для UI (`lastOutput`), но оно производное — не источник.
3. Команды (план 03): `buildExtraction(regionId, resource, +1 level)` — с ценой
   из defines и проверкой «есть deposit»; `damageExtraction(...)` — для войны
   и событий; временные эффекты («забастовка −50% на 6 мес») — модификаторы.
4. Python-пайплайн: `fill_region_economy_1946.py` / `resource_geography.py`
   выдают deposits + стартовые extraction вместо одного числа.
5. LLM: действия ограничены командами шага 3 с капами (±1 level за ход,
   модификаторы из белого списка). Сырые числа производства LLM не пишет.
6. Связь с MapFeature (план 06): фича `mine` создаётся при `buildExtraction`
   в регионе — визуальное лицо уровня добычи.

### За скобками (сознательно НЕ делать сейчас)

- Цепочки переработки (боксит→алюминий, руда→сталь) — переделы остаются
  абстрактной «промышленностью страны».
- Логистика ресурсов между регионами.
- Эластичность мировых цен (спрос/предложение двигают цену) — следующий шаг
  Trade v2, отдельным заходом (~30 строк в TradeTick, см. бэклог 09).

## Критерии приёмки

- [ ] `resourceProduction` как хранимое изменяемое число отсутствует; тики не мутируют данные месторождений (кроме медленного истощения richness).
- [ ] Тест: buildExtraction увеличивает output следующего тика; damageExtraction уменьшает.
- [ ] Тест: модификатор на добычу (например −50% на 6 мес) влияет и истекает.
- [ ] Пайплайн регенерирует regions с deposits; суммарный стартовый output стран равен прежнему (±1%) — баланс не сдвинулся.
- [ ] LLM-действие, пишущее произвольное число добычи, отклоняется валидатором.
