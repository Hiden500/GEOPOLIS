# 05 — Данные: расслоение JSON, валидация, пайплайн

Приоритет: P1. Предпосылка для сценария 1836 (план 07).
Статус: реализовано (см. статус в теле плана и `README.md`).
Зависимости: нет жёстких; согласован с 04 (deposits в regions).

## Проблемы (текущее состояние)

1. **regions.json смешивает 4 слоя** (`server/data/scenarios/1946/regions.json`,
   771 КБ, 1366 регионов): географию (id, geoJsonId, area, neighbors,
   sourceAdm1Codes), локализацию (names), стартовое состояние сценария
   (owner, population, экономика) — и всё это потом ещё и мутирует в GameState.
   Для 1836 география/имена общие, состояние другое → дублирование = дрейф.

2. **countries.json — сериализованный рантайм, а не авторские данные**
   (377 КБ, 128 стран): каждая страна тащит полностью нулевые `economy`
   (17 полей), `technology.domains` (14), `military.equipment` (8), пустую
   дипломатию. Добавление поля в EconomyState требует регенерации файла или
   обработки undefined.

3. **Нет валидации на загрузке.** regions/countries читаются сервером «на веру».

4. **Валидатор данных не в CI.** `scripts/map/validate_region_economy_1946.py`
   запускается руками; инварианты целостности не проверяются нигде.

5. **Два источника истины по ресурсам:** TS `RESOURCE_CATALOG` и Python
   `resource_geography.py::RESOURCE_HOTSPOTS` — разъедутся.

6. **Нет оркестратора пайплайна:** цепочка build_* → merge → translate →
   import → fill → validate восстанавливается только по README.

7. **Мёртвые/тяжёлые артефакты клиента:** `client/src/assets/game_map.json`
   (37 МБ) не имеет ни одного импорта — удалить; `client/public/world_1946.geojson`
   (34 МБ) грузится сырым — нужен TopoJSON/упрощение + сжатие.

8. Мелочи: `scripts/map/out/names_ru.json` — список вместо словаря по
   region_id; `neighbor_graph.json` обёрнут в лишний `{"neighbors": ...}`;
   артефакты out/ не имеют штампа генератора.

## Целевая раскладка

```
data/map/<era>/regions.core.json      — id, geoJsonId, area, neighbors (на эпоху карты; см. план 07)
data/map/<era>/names.en.json          — { "EUR-0001": "Andorra", ... }
data/map/<era>/names.ru.json
data/scenarios/1946/regions.state.json — owner, population, urbanization, stability,
                                          infrastructure, development, deposits, extraction
data/scenarios/1946/countries.json     — ТОЛЬКО авторское: id, name, color,
                                          capitalRegionId, tier, economyProfile,
                                          ненулевые старты (армия, дипломатия), subject_of
data/scenarios/1946/cities.json        — города с реальными координатами (план 06)
```

- Рантайм-объект Country со всеми нулями собирает `createCountry`
  (`server/src/data/countries/templates/CreateCountry.ts` уже есть) —
  Python-генератор нули не пишет.
- `LocalizedText` в рантайме остаётся; собирается при загрузке сценария из
  файлов имён. Новая локаль = новый файл имён, игровые данные не трогаются.
- 12 рукописных TS-стран (`server/src/data/countries/*.ts`) мигрируют в
  countries.json (авторский формат) — один источник истины.

### Валидация

1. **Zod на загрузке сценария** (сервер): схемы Region/Country-авторских данных,
   `parse` при `createGame`. Рукописная правка JSON не должна молча ронять
   симуляцию через 40 тиков.
2. **Инварианты в CI** (новый job, расширяющий validate_region_economy):
   - симметрия neighbor-графа;
   - каждый `ownerCountryId` существует в countries.json;
   - каждая `capitalRegionId` принадлежит своей стране;
   - каждый ресурс deposits ∈ RESOURCE_CATALOG;
   - полнота локализации по локалям (все region_id есть в обоих names.*);
   - суммы населения по странам в допуске якорей anchors.py.
3. **Один источник ресурсов:** npm-скрипт экспортирует RESOURCE_CATALOG в
   JSON (`scripts/map/out/resource_catalog.json`); Python-скрипты читают его
   и сверяют id.

### Пайплайн

- `scripts/map/make_1946.py` — оркестратор: гонит всю цепочку
  (build_* континенты → merge → translate → build_neighbor_graph → import →
  fill → validate), падает на первом расхождении.
- Каждый `out/*.json` — штамп в шапке: `_meta: { generator, version, date }`.
- `names_ru.json` → словарь по region_id; развернуть обёртку neighbor_graph.

### Клиент

- Удалить `client/src/assets/game_map.json` (37 МБ, мёртвый).
- `world_1946.geojson` → TopoJSON с квантованием (ожидаемо ~3–5 МБ) либо
  упрощение геометрии + брendered gzip/brotli на отдаче. Конвертация — шаг
  оркестратора; `GeoJsonLoader` учится разворачивать TopoJSON (библиотека
  `topojson-client`, ~10 КБ).

- [x] `make_1946.py` от чистого out/ до валидного сценария одним запуском.
- [ ] Начальная загрузка карты клиентом ≤ 5 МБ по сети. — **вне заходa**, см. отклонения.
- [~] Сценарий 1836 сможет добавить только `regions.state.json` + countries.json, не трогая core/names — **структурно возможно** (core/names расслоены и не зависят от regions.state.json), но 1836 сейчас использует синтетический `testRegions`, не датасет MAP, так что практическая проверка отложена до плана 07 (сам план так и формулирует).

## Отклонения при реализации

**Объём сужен до server/shared/Python** — по прецеденту плана 04 (избегать
`client/src/map/**`/карту, домен Gemini, заморожен решением пользователя
2026-07-03, см. `docs/TODO.md` «Постоянные рамки»). Реализовано целиком:
расслоение `regions.json` (Срез 1), `countries.json` без нулевых блоков
(Срез 2), единый источник каталога ресурсов TS↔Python (Срез 3), CI-джоб +
структурные инварианты (Срез 4), оркестратор `make_1946.py` (Срез 5).

**Не реализовано в этом заходе (сознательно, с обоснованием):**

1. **Клиентская часть плана** (проблема 7 из раздела «Проблемы», критерий
   «≤5 МБ по сети»): удаление мёртвого `client/src/assets/game_map.json`
   (37 МБ), конвертация `world_1946.geojson` (34 МБ) в TopoJSON + смена
   `GeoJsonLoader`. Оба пункта — правки `client/`, домен Gemini, карта
   заморожена решением пользователя — не трогать без явного запроса. Пока
   не тронуто: клиент по-прежнему грузит `world_1946.geojson` сырым.
2. **Целевая раскладка директорий по плану** (`data/map/<era>/` отдельно от
   `data/scenarios/<id>/`) не введена — данные остаются под
   `server/data/scenarios/1946/`, как и раньше, просто расслоены на 4 файла
   там же. Прецедент решения — план 03 (правило 2 конституции называло
   `shared/src/sim/commands/`, реально используется `server/src/commands/`):
   план писался с опережением факта (единственный текущий "map era" — 1946,
   `data/map/<era>/` разделение станет осмысленным только когда появится
   второй сценарий на РЕАЛЬНОЙ географии, а не `testRegions` — решать вместе
   с планом 07, не раньше).
3. **12 рукописных TS-стран (1836/2000) не мигрированы** в авторский JSON-
   формат — `docs/TODO.md` явно ограничивает охват до релиза сценарием 1946
   (1836/2000 — сценарии-заглушки, не параллельная цель). `CreateCountry.ts`
   расширен так, что миграция остаётся дешёвой, когда до неё дойдут руки.
4. **Штампы `_meta: {generator, version, date}`** в промежуточных
   `scripts/map/out/*.json` (пункт 8 «мелочи») — реализовано только для
   нового `resource_catalog.json`, и БЕЗ поля `date` (сознательно): дата
   генерации меняла бы файл при каждом прогоне экспорта независимо от
   реального изменения данных, что сломало бы приём «нулевой git-diff при
   регенерации = рефакторинг не изменил данные», использованный для проверки
   всех 5 срезов этого плана. Остальные `out/*.json` (`ownership_1946.json`,
   `neighbor_graph.json`, `names_ru.json`, `countries_1946.json`) штампов не
   получили — их пишут скрипты полной пересборки геометрии (`build/`,
   `translate_world.py`), вне периметра этого захода.
5. **`names_ru.json` (список → словарь по region_id) и лишняя обёртка
   `neighbor_graph.json`** (та же «мелочь», пункт 8) — не тронуты: это формат
   ПРОМЕЖУТОЧНЫХ `out/`-артефактов (вход импортёра), а не то, что видит
   рантайм — `import_to_game.py` уже разворачивает их в удобную форму на
   входе. Ценность правки — только читаемость самих `out/`-файлов, не
   поведение; отложено.

**Найдено и осознанно принято** (не «баг-фикс заодно», а прямое следствие
объединения путей сборки 1946/1836/2000 через `createCountry`, Срез 2):
`country.economy.inflation`/`unemployment` для 1946-стран раньше были
всегда 0 (отдельный, независимый от `createCountry` нулевой блок в старом
`countries.json`) — теперь выводятся из `economyProfile`, как всегда было у
1836/2000. `campaignSmoke` (60 месяцев, майоры) не показал наблюдаемого
эффекта в проверенном горизонте — детали `docs/DECISIONS.md`.

Статус: **реализовано** (в суженном объёме выше). tsc(server+client) чист,
vitest server 590/592 (единственный красный — преэкзистентная находка
калибровки ВВП/чел Китая, `docs/TODO.md`, не связана с этим планом), client
83/83. Полная регенерация пайплайном (`make_1946.py`) даёт нулевой git-diff
на всех промежуточных и финальных артефактах. Живая проверка: `POST
/game/start` на реальном dev-сервере вернул корректный `GameState` для
сценария 1946.
