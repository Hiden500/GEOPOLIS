Зависимости: `TradeTick.ts` (план "Торговля v2", 2026-07-11) — валютная зона
надстраивается над уже существующей торговлей, не требует Шага 2/Шага 3
плана 08 и не блокируется картой.

## Проблемы (текущее состояние)

1. Мировая торговля (`docs/TRADE.md`) — единый мировой пул цены на
   категорию ресурса, одинаковый для всех 128 стран. Нет механики, отражающей
   реальную историческую динамику 1946-1999: биполярный мир с двумя финансово
   обособленными блоками (условно — "западный"/долларовый и советский/
   рублёвый), где члены блока торгуют друг с другом на льготных условиях и
   частично защищены от санкций, идущих извне блока.
2. Санкции (`DiplomacyState.sanctions`, `trade_embargo`) бьют по цели
   одинаково, независимо от того, кто накладывает эмбарго — союзник по блоку
   или внешняя держава. Нет понятия "защиты блока".
3. Нет данных о принадлежности стран к финансовым блокам — ни поля, ни
   авторского решения, кто в каком блоке (см. "Отклонения" ниже: сознательно
   не решается этим планом для всех 128 стран).

## Целевая модель

Валютная зона — не отдельная симуляция обменного курса (это `Victoria`-
сложность, которую проект сознательно избегает, `AGENTS.md`), а два простых
модификатора поверх уже существующих механик, применяемые к стране —
члену зоны:

### Данные

- `Country.currencyZoneAnchor?: string` — id страны-"якоря" зоны. Отсутствие
  поля = страна финансово независима (типичный случай для большинства из
  128 стран 1946 года — формальных блоков в первые послевоенные годы было
  мало). Сама страна-якорь это поле на себе не выставляет — "входит ли X в
  зону" определяется по факту, что другие страны ссылаются на X через
  `currencyZoneAnchor`, не по отдельному флагу "isAnchor".
- Раздельно от `diplomacy.sphereOfInfluence`/`diplomacy.puppets` — не каждая
  сфера влияния означает общий финансовый блок (пользователь явно решил не
  автоматически выводить зону из существующих дипломатических полей).

### Эффекты (`shared/defines/trade.ts`, новые константы)

1. **Торговый бонус внутри зоны** (`TradeTick.ts`): у страны с
   `currencyZoneAnchor` — экспортный доход умножается на
   `(1 + CURRENCY_ZONE_EXPORT_BONUS)`, стоимость импорта умножается на
   `(1 - CURRENCY_ZONE_IMPORT_DISCOUNT)`. Бонус получает только член зоны, не
   сам якорь (якорь — точка отсчёта зоны, не участник со скидкой).
2. **Защита от санкций** (`getEmbargoPenalty` в `TradeTick.ts`): штраф от
   конкретной эмбарго-страны учитывается полностью, если эмбарго накладывает
   свой же якорь или другой член той же зоны (зона не защищает от санкций
   "изнутри"); если эмбарго накладывает страна вне зоны — вклад этого
   эмбарго в общий штраф домножается на `(1 - CURRENCY_ZONE_SANCTION_PROTECTION)`.
   Итоговый штраф по-прежнему капается на 100%.

### Константы (тюнингуемые плейсхолдеры, не финальная калибровка — как
везде в `shared/defines/trade.ts`)

```ts
export const CURRENCY_ZONE_EXPORT_BONUS = 0.05;       // +5% к экспортному доходу члену зоны
export const CURRENCY_ZONE_IMPORT_DISCOUNT = 0.05;    // -5% к стоимости импорта члену зоны
export const CURRENCY_ZONE_SANCTION_PROTECTION = 0.5; // -50% штрафа от санкций ВНЕ зоны
```

### Вне модели (сознательно, не в этом плане)

- Обменные курсы, инфляционное заражение между членами зоны, коллапс зоны
  при кризисе якоря — `Victoria`-сложность, не то, что просил TODO-пункт
  (сравнение вариантов — `docs/DECISIONS.md`, 2026-07-11, пользователь выбрал
  только торговый бонус + защиту от санкций).
- Авторинг `currencyZoneAnchor` для всех 128 стран сценария 1946 — см.
  "Отклонения при реализации" ниже, не решается кодом самого плана.

## Критерии приёмки

- [ ] `Country.currencyZoneAnchor?: string` — новое опциональное поле в
      shared-типе, дефолт отсутствует (не авторится в `CreateCountry.ts` —
      честное "не задано", не placeholder).
- [ ] Член зоны (`currencyZoneAnchor` задан) получает экспортный бонус и
      импортную скидку по константам выше; якорь и независимые страны — нет.
- [ ] Эмбарго от якоря/другого члена зоны — полный штраф, без защиты.
- [ ] Эмбарго от страны вне зоны — штраф снижен на `CURRENCY_ZONE_SANCTION_PROTECTION`.
- [ ] Тесты на все 4 пункта выше (`TradeTick.test.ts`), включая случай "страна
      без `currencyZoneAnchor` — поведение не отличается от текущего".
- [ ] `docs/TRADE.md` — новый раздел с описанием механики и константами.
- [ ] `campaignSmoke` зелёный после регенерации (если для 1946 назначены
      реальные зоны) или без изменений (если авторинг зон отложен отдельным
      заходом — см. "Отклонения").

### Открытый вопрос: авторинг зон для 1946 (не блокирует критерии приёмки выше)

Критерии приёмки выше проверяют МЕХАНИЗМ (можно тестами на синтетических
фикстурах, без единой реальной страны 1946 с `currencyZoneAnchor`). Реальное
назначение зон для сценария 1946 — отдельный, самостоятельный вопрос
авторинга исторических данных, требующий не выдумывать состав блока для
128 стран без источника. Кандидаты для последующего (не обязательно этого)
захода:

1. **Минимальный документированный набор** — только страны с чётким
   историческим фактом на 1946 год (без интерпретации): зоны советской
   военной оккупации (`QGS`/`QKS`/`QMS`) — очевидный кандидат на `SUN` как
   якорь, это уже прямое военно-административное подчинение, не
   умозрительная классификация. Основной массив из 128 стран — оставить
   без `currencyZoneAnchor` (независимы), не тянуть спорные случаи.
2. **Историческая калибровка Gemini** (роль закреплена 2026-07-11,
   `docs/AGENTS.md` §"Координация моделей") — более широкий, сверенный по
   источникам набор (реальные торговые/финансовые соглашения 1946-1949,
   предшественники Comecon/Бреттон-Вудской системы), не наша реконструкция
   по памяти.

Не решать один в один с реализацией механизма — можно и нужно мержить
раздельно: сначала механизм (тестируем без реальных данных), потом
авторинг (отдельная, более осторожная задача).
