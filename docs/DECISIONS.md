## 2026-07-05 (пользователь) — Память страны: реализовано; рост eventHistory отложен

Продолжение обсуждения памяти страны (вопрос 7, P2.5). После нескольких кругов "предложи альтернативу" найден вариант без компромисса между стоимостью и потерей истории: движок берёт последние N заголовков (`title`) из уже существующего `eventHistory` по стране и показывает их строкой в `## Player Country`/`## Major Powers`/`## Spotlight Countries` — LLM ничего дополнительно не пишет (`title` она и так производит каждый цикл), только движок фильтрует/форматирует. N по тиру (игрок больше, majors/Spotlight меньше), тот же принцип, что `LLM_SPOTLIGHT_COUNT`.

Отклонённые варианты: (а) LLM пишет заметку по каждой стране каждый цикл — дорого по выходным токенам, дублирует `eventHistory`; (б) показывать только "последнее упоминание" (1 событие) — реально теряет историю, а не экономит. Честно признанный компромисс выбранного варианта — рост **входных** токенов (~400-500 на промт), но ограниченный (окно, не накопление) и не растущий с длиной партии — в отличие от (а), где росли бы и входные, и выходные.

Статус: **реализовано 2026-07-05** (`LLMService.getRecentTitlesLine()` + константы `PLAYER_RECENT_TITLES_COUNT`/`MAJOR_RECENT_TITLES_COUNT`/`SPOTLIGHT_RECENT_TITLES_COUNT`). Тесты — `LLMService.test.ts`, tsc/тесты зелёные (276 сервер). Живая проверка через preview: действие с `sourceCountryId: "CAN"` тегирует событие на Канаду, следующий промт показывает "Recent: Canada Signs Trade Deal (1946-01-01)" и в `## Player Country`, и в `## Major Powers`.

Отдельно, но в том же обсуждении: рост `eventHistory` без границ (не окно по стране, а весь журнал для "Хроники"/`GameState`) — реальная, но другая проблема. Пользователь предложил отдельный вызов LLM на сжатие старой истории. Решение: **отложенное улучшение** — сначала дешёвый детерминированный дефолт без LLM (старые записи теряют `description`, остаётся `title`+`date`), LLM-сжатие — только после того как (а) дешёвый вариант окажется недостаточным на практике и (б) готова автоматизация `GeminiProvider` (иначе лишний ручной шаг + расход дефицитного бесплатного лимита API). Ничего не реализовано, зафиксировано в `TODO.md`.

## 2026-07-05 (пользователь) — Таймлайн-интерфейс, синхронизация карты, автоматизация через Gemini API

Пользователь принёс референс интерфейса (скриншот "Timeline" из стороннего проекта): карточки событий по датам, теги стран/сущностей, полужирный заголовок, тело текста, сворачиваемый список изменений карты, кнопки "Intervene"/"Next Event". Наш текущий `LLMPanel` показывает нарратив одним сплошным текстом в textarea — неудобно читать, эта проблема реальна независимо от качества самого нарратива (см. запись выше).

1. **Таймлайн-интерфейс — реализовано.** Шаг 1: короткий `title` в ответе LLM (необязательное поле в схеме, не required — не ломает ответы без него), `LLMService.processResponse` использует его как `Event.title`, с фолбэком на прежнюю заглушку `"Мировые события (LLM, ход N)"`. Шаг 2: `EventTimelinePanel` (новое окно "Хроника") — карточки по датам, кликабельные теги стран (переиспользует существующий `onSelectCountry`/`InspectorPanel`, не новый механизм), абзацы нарратива разбиты по `\n\n`. Не сделано сознательно: сворачиваемый список изменений карты (зависит от Map Feature, см. пункт 2 — отложено вместе с картой), звук, фильтр по стране/типу — не блокеры, можно добавить отдельно. tsc/тесты зелёные (267/83), живая проверка через preview-браузер: карточка отрендерилась с датой/тегами/заголовком/абзацами, клик по тегу открыл инспектор страны.

2. **Смена названия/режима страны на карте + создание Map Feature из ответа LLM — обсуждено, отложено пользователем.** Оба реальны технически (наш прогон буквально описал «Албания провозгласила Народную Республику», но `LLMAction` не может это применить; `MapFeatureType` уже содержит `protest`/`uprising`/`government`/`border_dispute`, но `MapFeatureService` создаёт объекты только при старте игры). Оба — работа с картой, которая заморожена решением пользователя от 2026-07-03 («не брать без явного запроса»). Хотя пользователь сейчас явно попросил, при уточнении решил **отложить оба до снятия заморозки целиком**, не делать точечное исключение. Зафиксировано в `TODO.md`, не реализовывать без нового явного запроса.

3. **Автоматизация через Gemini API — согласовано, не реализовано.** Раз качество Gemini 3.1 Flash Lite подтверждено (см. запись выше), пользователь согласен строить `GeminiProvider` (часть давно запланированной `LLMProvider`-абстракции) на связке с уже проверенной `responseSchema`, через `GEMINI_API_KEY` в переменных окружения. Решение по порядку: сначала провайдер и полный автопрогон одного цикла, только потом — жёсткий гейт «ход только после ответа LLM» (см. запись выше, пункт 3) — двумя шагами безопаснее одного большого.

4. **Тег стран в тексте события (`(USA)` и т.п.) — оставить как есть, временно.** Полезно для тестирования (проверка grounding на глаз), но не для игрока. Уборка — отдельная, явно отложенная задача, не путать с решением о локали (запись выше).

Статус: пункт 1 — **реализовано и подтверждено живым прогоном**. Пункты 2-4 — решены/согласованы, не реализованы.

## 2026-07-05 (пользователь) — Пять решений по LLM-циклу: нарратив, локаль, гейт хода, длина хода

Обсуждение началось с дизайна "памяти страны между вызовами LLM" (P2.5, вопрос 7 — само по себе ещё не решено, см. открытые вопросы), но по ходу разбора реальных прогонов промта всплыли смежные, но отдельные решения:

1. **Нарратив/охват стран (баг, не памяти касается).** Прогон без намерения игрока показал: LLM игнорирует выданные `## Spotlight Countries` (Афганистан/Аландские острова/Албания/Андорра/Договорные Оман) и рассказывает про страны вне промта вообще (Австрию, Австралию — их нет даже в `## Country IDs`). Причина — не в памяти, а в слабой секции `## Instructions` (`LLMService.generatePrompt`): не требует глубины нарратива, не требует задействовать Spotlight-страны, не запрещает выдумывать страны вне ростера. Полностью текстовое поле `descriptions` вообще не валидируется (в отличие от `actions[]`). Решение: усилить инструкцию — минимум многоабзацный нарратив, обязательно затронуть 1-2 Spotlight-страны за цикл, явный запрет упоминать страны вне `## Country IDs`. Не блокирует ничего, реализуется отдельно и независимо от памяти.

2. **Мультиязычность генерируемого текста.** `AGENTS.md` §"Design for Multi-Locale From the Start" уже требует этого для любого generated content, но применить забыли ещё до текущей сессии — `descriptions`/`Event.description` остаются `string`. Обсуждались 3 варианта (dual-locale в одном JSON-ответе / два отдельных вызова LLM по языку / один язык + машинный перевод). Выбран четвёртый, более простой: **язык фиксируется на старте игры** (как выбор языка в большинстве игр), а не переключается на лету — `GameState` получает поле локали, LLM получает её как переменную промта и пишет только на этом языке весь плейтру. Дешевле всех трёх обсуждавшихся вариантов: не нужен dual-locale в каждом ответе LLM, не нужен второй вызов, не нужен переводчик.

3. **Ход обязан проходить через ответ LLM ("LLM — главный двигатель").** `docs/LLM_RULES.md` §"Роль LLM в архитектуре" (коммит `37a2868`, 2026-06-30) уже декларирует это как принцип, но **никогда не было применено в коде**: `POST /game/next-turn` → `GameService.advanceMonth()` не имеет вообще никакой связи с LLM-циклом, ход можно листать бесконечно без единого обращения к LLM. Это реальный, не выдуманный пробел. Блокер для жёсткого гейта прямо сейчас: работает только `ManualClipboardProvider` (ручной copy-paste), автоматизированные провайдеры (`GigaChat`/`OpenRouter`/`Ollama`, TODO P2.5, вопрос 10) не реализованы и не протестированы; из автоматизированных доступов у пользователя есть только бесплатный Gemini API с жёсткими лимитами. Решение: **сначала минимум один рабочий автоматизированный провайдер, потом гейт** — не откладывать бессрочно, а bundle делать вместе. Рекомендация по провайдеру (см. ниже) — начать с OpenRouter (уже в плане, агрегирует много бесплатных моделей, единоразовый топ-ап $10 снимает дневной лимит навсегда) + Groq как резервный (другая инфраструктура, на случай простоя/лимита первого).

4. **Переменная длина хода (1 неделя/1 месяц/3 месяца/6 месяцев).** Ранее отслеживалось как открытый вопрос 8 ("Правило 'когда именно вызывается LLM' при переменной длине хода"). Находка при разборе кода: `advanceTurnSchema` (`months: 1-12`) уже существует в `server/src/validation/schemas.ts`, но полностью не используется — `/game/next-turn` игнорирует тело запроса, `GameService.advanceMonth()` всегда ровно 1 месяц. Решение: **детерминированные тики остаются месячными** — переменная длина хода это каденция принятия решений/LLM-вызовов, а не новый шаг симуляции. 3/6 месяцев — просто N вызовов `simulateMonth` подряд (уже так делают тесты `SimulationEngine.test.ts`). 1 неделя — не новый тик, а более частая точка решения без немедленного тика: накопление до полного месяца, затем один `simulateMonth`. Отвергнутая альтернатива — переработка всех 6 тиков под произвольный период: значительно больше работы ради точности, которая игроку не нужна.

Статус: пункт 1 — **реализовано 2026-07-05** (`LLMService.generatePrompt()`: 3 обязательных абзаца, ≥2 Spotlight-страны конкретно, запрет стран вне `## Country IDs`, требование конкретных реальных исторических событий месяца; тесты в `LLMService.test.ts`, tsc/тесты зелёные 263/263). Пункт 2 (мультиязычность) — **частично реализовано 2026-07-05, см. поправку ниже: было понято уже, чем задумано пользователем**. Пункт 4 (переменная длина хода) — решён, не реализован. Пункт 3 — решение по подходу принято (гейт после провайдера), сам провайдер и сам гейт не реализованы. Вопрос 7 (память страны) отдельно всё ещё не закрыт — дизайн обсуждался (тир по стране/majors/остальным, разделение "память состояния" vs "нарративная память", авторство у LLM с лимитом длины на валидации), но не финализирован и не реализован.

**Поправка (2026-07-05, недопонимание масштаба пункта 2).** "Мультиязычность" в постановке пользователя означала **всю игру целиком** — интерфейс (все панели/кнопки, сейчас захардкожены по-русски примерно в 14 файлах компонентов), названия стран (`Country.name`/`shortName` — всё ещё plain `string`, известный пробел из `AGENTS.md` §"Design for Multi-Locale From the Start"), названия регионов (`Region.names` — уже `LocalizedText`, но часть вызовов `getText()` не передаёт локаль явно и молча берёт `DEFAULT_LOCALE`), и только в последнюю очередь — нарратив LLM. Реализовано 2026-07-05 было только последнее: `GameState.locale`, переключатель в `ScenarioSelector`, секция `## Language` в промте. Это не потерянная работа — `GameState.locale` остаётся правильным единым источником для будущей полной локализации, — но сама полная локализация интерфейса/имён **не сделана**, это отдельная, крупная, пересекающая архитектуру задача (см. `TODO.md`).

**Поправка (2026-07-05, живой тест пункта 1).** Прогнали усиленный промт (3 обязательных абзаца, ≥2 Spotlight-страны по существу, запрет стран вне `## Country IDs`) через Groq (Llama 3.3 70B) и Gemini 3.1 Flash Lite.
