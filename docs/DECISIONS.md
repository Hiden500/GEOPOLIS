## 2026-07-11 — Калибровка населения бедных стран (формульная сторона)

Проблема (найдена 2026-07-06): страны с очень низким ВВП/чел (`CHN` ~$83 против
ориентира $850, также `ARG`/`BRA`/`ITA`) теряли население в мирное время —
единственный красный тест `campaignSmoke`. Пользователь выбрал «углубить фикс
формулы» (а не отложить на калибровку данных Gemini).

**Корень (диагностика):** формула рождаемости `PopulationTick` привязывает её
ПОЛОЖИТЕЛЬНО к богатству, тратам на образование и welfare. Это обратно
демографическому переходу: бедные аграрные общества 1946 имели ВЫСОКУЮ
фертильность (+ высокую смертность), а не низкую. Бедная страна получала
тройное подавление рождаемости (низкий уровень жизни × низкие траты на
образование × низкие на welfare = 0.53 × 0.8 × 0.9), уходя ниже смертности.

**Фикс (нюанс баланса, формульная сторона):**
- `STANDARD_OF_LIVING_BIRTH_FLOOR=0.5` — пол уровня жизни ТОЛЬКО в рождаемости
  (не в смертности): бедность не подавляет фертильность ниже аграрной нормы.
- `BIRTH_RATE_EDUCATION_BASE`/`BIRTH_RATE_WELFARE_BASE` подняты 0.8/0.9 → 1.0:
  низкие соц-траты не штрафуют рождаемость ниже нейтрали; траты дают лишь
  мягкий бонус. Преимущество развитых стран в приросте — через НИЗКУЮ
  СМЕРТНОСТЬ (медицина/стабильность), а не через рождаемость.

Проверено эмпирически: `campaignSmoke` зелёный, мажоры (USA/SUN/…) проходят все
ассерции траектории (не занижал порог теста — решил по существу). Регрессионный
тест «бедная аграрная страна не убывает в мире» в `PopulationTick.test.ts`.

**Осталась сторона данных (домен Gemini):** сами ВВП/чел 128 стран не сверены с
источниками — историческая калибровка чисел остаётся кандидатом на проход
Gemini, но население больше не убывает. Впервые ВЕСЬ набор зелёный (658 server
+ 83 client).

## 2026-07-11 — Война Шаг 4: госдолг

`EconomyState.debt` — раньше `debtInterest` было висящим полем без долга.
Реализовано: дефицит → долг (казна пол 0, не уходит в минус; профицит сначала
гасит долг), `debtInterest = debt × monthlyRate` (пересчёт каждый тик до
расходов), ставка `DEBT_BASE(0.003) + DEBT_RISK_PREMIUM(0.013) × (1 −
avgHealth/100)` — слабое государство занимает дороже. Долг/ВВП выше
`DEBT_GDP_PENALTY_THRESHOLD(0.6)` штрафует рост ВВП; выше
`DEBT_CRISIS_GDP_THRESHOLD(1.0)` — мировой факт «на грани дефолта» в промт.

**Развилки (зафиксированы в старте логика-трека) применены:**
- Развилка А (казна-в-минус vs долг): дефицит → долг, казна floored at 0.
  Репарации (`WarService`) сохраняют проверку `amount ≤ 0` — существующий тест
  не сломан (казна не уходит в минус через economyTick, но makePeace ставит её
  напрямую в тестах).
- Развилка Б (протаскивание `game.modifiers` через `economyTick`): штраф росту
  считается напрямую как функция долг/ВВП, не timed-модификатором — сигнатуру
  не менял, конституцию не нарушил.

**Найдено при реализации (взаимодействие, предвиденное планом):** аустерити ИИ
(Правило A) триггерилась `treasury < 0` — с конвертацией дефицита в долг казна
больше не уходит в минус, правило стало бы мёртвым. Перевязал триггер на
дефицит + долг/ВВП выше того же порога 0.6 (ИИ режет расходы ровно когда долг
начинает вредить росту). Обновил 5 тестов аустерити + 2 теста бюджета
(`debtInterest` теперь производный, читается после тика, не статичный
фикстурный).

Статус: реализовано, 5 тестов долга (`EconomyTick.test.ts`) + 2 теста факта
(`SimulationEngine.test.ts`). tsc server+client чист, server 655 зелёных
(кроме преэкзистентного CHN — долг даже слегка сгладил: 2.26% vs 2.34%),
client 83/83. `docs/ECONOMY.md` §"Госдолг"/план 08/план 11 обновлены.
**Не сделано (кандидат):** команда/LLM-действие `default(countryId)` — сам
дефолт как отыгрыш LLM. Дальше по логика-треку — Шаг 2b (мир + границы,
согласуется с пользователем).

## 2026-07-11 — Целевой слой: счёт силы, позиция, цели игрока (план 11 категория B)

Пользователь: «продолжай в целевой слой». Модель выбрана пользователем —
**игрок сам ставит цели** (не навязанная движком победа/поражение вроде
«сверхдержава к дате»), в духе игры со свободнотекстовым намерением. Моя часть
— логика; UI (панель рейтинга, экран целей) — пользователь ведёт сам.

**Реализовано:**
- `getNationalPower(country)` (`shared/utils/nationalPower.ts`) — взвешенный
  композит ВВП (доминирует) + военная сила (та же мера, что WarTick) +
  население + тиры технологий. Веса/масштабы в `defines/objective.ts`.
- `computePlayerStanding` → `GameState.playerStanding {power, rank, total}`,
  пересчёт каждый ход в новом `ObjectiveTick` (после агрегации/боёв) +
  инициализация в `CreateGame`.
- `Country.goals` (`StrategicGoal`) переопределён из мёртвого плоского
  плейсхолдера {id,title,priority,completed} в типизированный union по `kind`:
  `reach_gdp`/`reach_power_rank`/`control_regions`/`reach_tech_tier`. Движок
  оценивает выполнение детерминированно каждый ход (`evaluatePlayerGoals`),
  ставит `completed` + мировой факт в промт LLM.
- `PUT /objective/goals` + команда `setPlayerGoals` (сбрасывает `completed` —
  им владеет движок; не трогает цели ИИ).

**Нюансы:** `control_regions` считает легальное владение, не оккупацию (цель про
устойчивый контроль). Позиция — производное состояние, но хранится ради дешёвого
доступа UI/промта без пересчёта 128 стран на рендер.

**Вне слоя (кандидаты):** навязанная победа/поражение (модель не выбрана);
free-text цели с LLM-оценкой (нужен живой Gemini); цели для ИИ. Отдельно от
приостановленных «национальных целей major-стран для LLM» (те блокированы
спорным ростером тиров — это ДРУГАЯ задача, про флейвор ИИ, не про игрока).

Статус: реализовано. Тесты: `nationalPower.test.ts` (shared, 7),
`ObjectiveTick.test.ts` (позиция + оценка целей), `commands/objective.test.ts`,
роут в `routes.integration.test.ts`. Весь набор зелёный: server 679, shared 7,
client 83, tsc чист. `docs/OBJECTIVES.md` (новый) / план 11 обновлены.

## 2026-07-11 — Война Шаг 2b: мир + аннексия (transferRegion) — план 08 замкнут

Уточнение пользователя сняло раннюю неоднозначность: «изменение границ, которое
я веду отдельно» = правка НАЧАЛЬНЫХ границ стран 1946 (датасет карты), а не
военная передача регионов. Значит военная логика границ (аннексия/`transferRegion`)
— в моём периметре. Реализовано.

`WarService.makePeace` → `applyPeaceTerms(war)` — детерминированные условия по
warScore. LLM/игрок решает КОГДА заключить мир (действие `peace`), движок —
СКОЛЬКО переходит:
- `|warScore| < WARSCORE_ANNEXATION_THRESHOLD(30)` → белый мир, граница не
  меняется, вся оккупация снята.
- Иначе победитель аннексирует оккупированные им регионы проигравшего, не больше
  `floor(|warScore| / WARSCORE_COST_PER_ANNEXED_REGION(25))` (по возрастанию id,
  детерминизм); остальное возвращается. Проигравший-оккупант не аннексирует.

`transferRegion` (`simulation/war/occupation.ts`) — единственная прод-мутация
`ownerCountryId` вне сценарной загрузки: меняет владельца + снимает оккупацию.
Помещён в occupation.ts (не commands/war.ts) во избежание цикла импортов
WarService↔commands; командная обёртка `commands/war.ts::transferRegion` — для
будущего LLM-действия. «Слишком жадный» договор невозможен по построению
(бюджет очков), поэтому явная валидация-отклонение из плана не нужна в
детерминированном варианте.

**Отложенное обогащение:** LLM предлагает конкретный составной `PeaceTerms`
(массив аннексий + опц. репарации/вассал), валидируемый против того же бюджета —
первое составное `data`-поле контракта, нужен живой Gemini-прогон. Команда
`default(countryId)` (Шаг 4) — тоже LLM-отыгрыш, не сделана.

(2) пороговый радиус подбирается руками под конкретный стык — не общий
алгоритм; (3) многопроходность без гарантии сходимости, и буфер раздувает
полигон во все стороны, создавая новые наложения на третьих соседей/моря,
которые дочищались каскадом пост-клипов.

**Новый метод — "gap-first" (`scripts/map/build/geometry_cleanup.py`):**
не наращивать полигоны навстречу друг другу, а найти САМУ пустоту и
раздать её. `polygonize` по объединению всех границ (изменяемая земля +
контекстная земля + вода) даёт точную мозаику ячеек; ячейка, не покрытая
ни землёй, ни водой — слайвер; каждый отдаётся изменяемой фиче с самой
длинной общей границей (длинные ленты предварительно режутся пополам
рекурсивно, чтобы сегменты ушли своим ближайшим регионам, а не вся лента
одному "победителю"). По построению: ноль новых наложений (слайвер —
пустота), ноль разрывов после одного прохода (второй прогон — проверка
инварианта, поглощает 0), шов ровно по существующей границе — то самое
"прилипание". Защиты: компактные блобы (потенциальные озёра-дыры) не
поглощаются + PROTECTED_HOLE_POINTS для известных озёр (порог компактности
ненадёжен — изрезанная береговая линия даёт ленточный Polsby-Popper);
прибрежные полосы (1 земля + вода) не трогаются (маскируются фоном);
"пинхолы" у границы одной фичи поглощаются в неё же; ячейки, обрезанные
рамкой clip_box, отбрасываются.

Удалено: `fill_palestine_gaps_to_neighbors`, `fill_gap_between_countries`,
`clip_country_against`, `clip_asia_against_seas` (~200 строк буферной
машинерии + 8 вызовов в main). `fill_palestine_egypt_gap.py` переписан на

## 2026-07-19-o (пользователь) — "Почти хорошо": Фарерские острова

чтобы убрать наложения — прямо противоречит намерению пользователя: сырое

будущий проход (резать СУШУ по линии моря).

**Находка 3 (главный баг): антимеридиан ломал "локальность" clip_box.**
Для морей, чьи части лежат по разные стороны линии перемены дат
(Берингово/Чукотское, тихоокеанские "секторы", Southern Ocean) —
`bounds()` ВСЕЙ MultiPolygon-фичи давал `(-180, ..., 180, ...)`, "локальный"
clip_box (±0.5°) оказывался почти всем земным шаром по долготе.
`absorb_compact_gaps` подхватывал компактные разрывы у Норвегии/Исландии/
Гренландии/Финляндии/Лабрадора как будто это Берингово море (найдено
пользователем на живом рендере). Исправлено: `clip_box` считается ПО
КАЖДОЙ ЧАСТИ отдельно (своя локальная область), не по bounds() всей
фичи — для одночастных легитимно глобальных фич (Southern Ocean, кольцо
вокруг Антарктиды) локальный bbox законно остаётся большим, это не баг.

**Чистка уже испорченного состояния.** Поскольку `seas_1946.geojson`
гитигнорится и предыдущий (закоммиченный) прогон уже записал испорченные
фичи, пришлось писать `cleanup_scattered_fragments()` — кластеризация
частей по близости (порог 2°), но ПЕРВАЯ версия (порог по суммарной
площади кластера) оказалась недостаточной: у Берингова моря десятки
мелких (~0.01-0.04 deg2) оторванных фрагментов у Гренландии/Лабрадора
кластеризовались МЕЖДУ СОБОЙ (просто близко друг к другу, не к настоящему
морю) в "достаточно крупный по сумме" кластер и выживали (85 из 117 частей
вне региона). Исправлено на "якорный" критерий: кластер легитимен, только
если содержит хотя бы одну часть с площадью >= 1.0 deg2 (настоящие "стволы"
на порядки крупнее любого оторванного фрагмента) — рой мелких кусков без
такого якоря отбрасывается целиком.

**Побочный баг, пойманный при отладке: `GeometryCollection`-деградация.**
White Sea упал с `AttributeError: 'NoneType' object has no attribute
'length'` — его геометрия оказалась `GeometryCollection` из 12 вырожденных

геометрия строится через union/intersection.

**Побочный баг экономики, найден на живой проверке.** Фарерские острова
получили population=1,201,165 (реальность ~23-30 тыс. на 1946) — `generic_
