## 2026-07-11 — Ресурсы: deposit/extraction/output (план 04_RESOURCES.md), реализовано целиком

План 08 (Шаг 1) слит в текущей ветке (не в main — работа продолжена по
прямому указанию пользователя «продолжай в текущей», без промежуточного
мержа). Следующий кандидат по дорожной карте — 04/05/06 в любом порядке.
Выбран **план 04**: 05 и 06 требуют правок `client/src/map/**` (закреплён
за Gemini, отдельно заморожен решением пользователя), 04 — целиком
`server/`+`shared/`+Python-пайплайн. Разведка (Explore-агенты упали на
лимите сессии — сделана прямыми чтениями) показала план заметно
контейннее планов 02/03/08: новое LLM-действие плоское (как уже
проверенные `research_shift`/`production_shift`), не составное; нет
конфликта с заморозкой карты; Python-миграция — одна функция с точным
сохранением текущего output. **Реализованы все 5 критериев приёмки одним
заходом**, без урезания.

`region.resourceProduction: Partial<Record<ResourceType, number>>` —
одно число, означавшее сразу geological potential, текущую добычу и
изменяемое состояние — заменено тремя слоями: `Region.deposits` (richness,
истощается медленно тиком), `Region.extraction` (уровень мощностей
`0..MAX_EXTRACTION_LEVEL`, меняется только командой), output (не хранится,
считает `ResourceTick.ts`). Формула: `output = richness ×
(level/MAX_EXTRACTION_LEVEL) × infraBonus × techBonus × miningBonus ×
occupationPenalty × resourceOutput-модификатор`. Новая команда
`server/src/commands/resources.ts::buildExtraction`/`damageExtraction` —
`buildExtraction` списывает `EXTRACTION_BUILD_COST` из казны, проверяет
`effectiveController`+deposit; `damageExtraction` — безусловное снижение
(не подключена ни к чему автоматически, задел под войну/события). Новый
белый атрибут модификаторов — `resourceOutput` (второй после `stability`,
план 03). Новое LLM-действие `build_extraction` — плоское, `delta: ±1` за
ход жёстким Zod-капом (`z.union([z.literal(1), z.literal(-1)])`), по
прецеденту `research_shift`/`production_shift`.

Python-пайплайн (`fill_region_economy_1946.py::compute_region_economics`)
переписан на `deposits`+`extraction = MAX_EXTRACTION_LEVEL` вместо одного
числа, прогнан, `regions.json` (1366 регионов) регенерирован. Проверено
скриптом сравнения JSON до/после: **точное (0% дрейфа) сохранение
стартового output**, не приближённое ±1% из критерия приёмки —
`extractionFactor = 1.0` побайтово воспроизводит старую формулу.

Побочный фикс: добавление `delta`-литералов в Zod-схему обнажило баг в
`GeminiProvider.ts::mergeIdenticalShapeBranches`/`enrichForGemini` (план
02, Срез 4) — эти функции были написаны только под дискриминированный
union объектов и падали (`TypeError`) на вложенном `anyOf` из
литералов-не-объектов (`z.union([z.literal(1), z.literal(-1)])`).
Исправлено guard-функцией `isMergeableDiscriminatedBranch`: схлопывание
веток (Gemini constrained-decoding не строит неразличимые по форме anyOf-
ветки, находка от 2026-07-10) применяется только когда все ветки — объекты
с `type`-дискриминантом, иначе массив не трогается. `const→enum` конверсия
заодно обобщена с «только string» на любой тип значения.

Не реализовано (за скобками плана, задокументировано в
`docs/plans/04_RESOURCES.md` §«Отклонения при реализации»): связь с
MapFeature `mine` (план 06, карта заморожена), `techGate?` на депозите
(`RESOURCE_CATALOG` уже даёт `eraIntroduced`/`techGate` на уровне ресурса),
автоматический триггер `damageExtraction` от войны/событий, детальная
видимость deposits/extraction по регионам в промте LLM, единый источник
каталога ресурсов TS↔Python (`MAX_EXTRACTION_LEVEL` дублируется вручную с
комментарием-синхронизацией).

Статус: **реализовано полностью**, tsc (server+client) и vitest (578/579,
единственный красный — преэкзистентная находка калибровки ВВП/чел Китая,
`docs/TODO.md`, не связана с этой работой) зелёные, client lint чистый на
тронутых файлах. См. `docs/ECONOMY.md` §"Добыча ресурсов",
`docs/ARCHITECTURE.md` §"Команды"/§"Модификаторы", `docs/LLM_RULES.md`

## 2026-07-11 (пользователь) — Команды/модификаторы/defines (план 03_MODIFIERS_COMMANDS.md), суженный объём

Планы 01+02 слиты в `main`. Разведка (3 параллельных агента + прямая проверка
ключевых файлов) показала: буквальный объём всех 4 шагов плана 03 значительно
больше, чем текст плана предполагает — счёт не на «несколько файлов», а на
~15 файлов с десятками безымянных числовых литералов, часть из которых
(`PoliticsTick.ts`/`PopulationTick.ts`) план вообще не упоминал. Реализован
осознанно суженный объём одного захода (та же модель, что в планах 01/02) —
детали срезов и полный список отложенного — `docs/plans/03_MODIFIERS_COMMANDS.md`
§«Отклонения при реализации».

**Решение 1 — слой команд в `server/src/commands/`, не `shared/src/sim/commands/`.**
`MASTER_PROMPT.md` правило 2 буквально называет `shared/src/sim/commands/`, но
весь слой тиков физически живёт в `server/src/simulation/` — директории
`shared/src/sim/` не существует вообще. `WarService`/`DiplomacyService`
(которые команды оборачивают) оказались технически портируемыми в `shared/`
(ноль server-specific импортов), но перенос — заметно больший и рискованный
дифф (правки импортов во всех потребителях) ради буквы правила, написанного
с опережением факта (аудит планировал «симуляция когда-нибудь переедет в
shared/», сама симуляция сегодня на 100% в `server/`). Пользователь выбрал
**`server/src/commands/`** — рядом с `simulation/`/`services/`, где реально
живёт игровая логика. Правило 2 в `MASTER_PROMPT.md` не редактируется —
только эта запись фиксирует фактическое расположение.

**Решение 2 — миграция `shared/src/constants/` → `shared/src/defines/` сейчас.**
В плане 02 пользователь явно отложил эту миграцию «до отдельного захода по
плану 03» — этот заход и есть тот отдельный. `budgetSpendingShareCaps.ts`/
`createEmptyEconomyState.ts` перенесены, `resourceWeights.ts` (подтверждённый
мёртвый код) удалён вместо переноса.

**Реализовано:**
- Слой команд (`server/src/commands/{diplomacy,war,economy,modifiers}.ts`) —
  тонкие обёртки над существующими сервисами; `AiBehaviorTick`/`LLMService`/
  `budget.ts` (три «внешних инициатора» по критерию приёмки) переключены на
  них вместо прямой мутации/разрозненных вызовов сервисов. Формулы Правил
  A/B/C `AiBehaviorTick.ts` (аустерити, коалиционный бандвагонинг, stability→
  welfare nudge) обёрнуты байт-в-байт — не переиспользуют похожие методы
  сервисов с другими побочными эффектами (`DiplomacyService.changeRelation`
  делает реципрокный сдвиг 50%, которого в AI-формуле нет).
- Модификаторы — минимальный сквозной срез на одном атрибуте (`stability`):
  `GameState.modifiers` (`SAVE_VERSION` 2→3), `effectiveValue()`
  (`shared/src/utils/modifiers.ts`), Cleanup-хук в `SimulationEngine.ts`
  сравнивает `expiresAt` с `game.currentDate` — осознанно не повторяет
  wall-clock баг `MapFeatureService.removeExpiredFeatures`. Реальная
