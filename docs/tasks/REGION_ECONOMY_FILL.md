# Задание: заполнение экономики регионов сценария 1946

Это задание для отдельной модели/прохода — не часть текущего пайплайна
`scripts/map/`. Геометрия, владельцы, соседство, локализованные имена уже
готовы; нужно заполнить экономические поля, оставленные нулевыми
плейсхолдерами.

## Вход

- `server/data/scenarios/1946/regions.json` — 1366 регионов (`Region[]`,
  схема `shared/src/types/map/Region.ts`). Заполнены: `id`, `geoJsonId`,
  `names` (en/ru), `ownerCountryId`, `area` (км²), `neighboringRegionIds`,
  `sourceAdm1Codes`. **Нулевые плейсхолдеры, которые нужно заполнить:**
  `population`, `urbanization`, `stability`, `infrastructure`,
  `development`, `gdp`, `resourceProduction`.
- `server/data/scenarios/1946/countries.json` — 127 стран (`Country[]`),
  `ownerCountryId` в regions.json ссылается сюда. `population`/`economy.gdp`
  у стран **не нужно заполнять отдельно** — они агрегируются автоматически
  из регионов при старте игры (`shared/src/utils/aggregateCountryData.ts`,
  вызывается из `server/src/game/CreateGame.ts`). Заполнять только регионы.
- `docs/HISTORICAL_ACCURACY.md` — обязательное требование исторической
  достоверности стартового состояния (1946 год).
- `shared/src/data/resources/resourceCatalog.ts` — каталог из 20 сырьевых
  ресурсов с `eraIntroduced`/`techGate`. Для 1946 (`startYear=1946`) активны
  все ресурсы с `eraIntroduced <= 1946`: смотри файл, `uranium` (1945) уже
  активен, `rareEarths`/`lithium` (1980) — нет, не заполнять их для 1946.

## Что заполнить, по каждому региону

| Поле | Диапазон/единицы | Примечание |
|---|---|---|
| `population` | абсолютное число | сумма по региону должна давать историческое население страны на 1946 |
| `urbanization` | 0..1 | доля городского населения |
| `stability` | 0..1 | внутриполитическая стабильность региона на старте |
| `infrastructure` | 0..1 | дороги/ж.д./порты относительно эпохи |
| `development` | 0..1 | общий уровень экономического развития |
| `gdp` | абсолютное число (та же денежная шкала, что и у `Country.economy.gdp`) | используется `calculateRegionGDP` как референс (`server/src/services/RegionEconomyService.ts`), но можно задать напрямую |
| `resourceProduction` | `Partial<Record<ResourceId, number>>` | только активные для 1946 ресурсы (см. каталог); 0 или отсутствие ключа — нет добычи |

## Требования

1. **Историческая достоверность старта** (`docs/HISTORICAL_ACCURACY.md`) —
   население, экономика и ресурсы должны отражать реальное состояние мира
   на январь 1946. После старта игра расходится с историей — это не
   ограничивает финальные значения, только начальные.
2. **Согласованность с владельцем.** Зоны оккупации Германии (`QGS`/`QGA`/
   `QGB`/`QGF`) и раздел Китая (`CHN`=коммунисты, `TWN`=Гоминьдан) уже
   запечены в `ownerCountryId` — не переопределять владельца, только
   заполнять экономику регионов в рамках уже заданного владельца.
3. **Сохранить неизменными:** `id`, `geoJsonId`, `names`, `ownerCountryId`,
   `area`, `neighboringRegionIds`, `sourceAdm1Codes`. Менять только
   перечисленные в таблице поля.
4. **Не выдумывать числа произвольно** (`AGENTS.md`, "Understand Before
   Changing") — где данных по конкретному региону нет, использовать
   разумную интерполяцию от известных страновых агрегатов (население
   страны, ВВП страны), а не одинаковые значения для всех регионов одной
   страны.
5. **Формат вывода** — тот же `Region[]`, тот же файл
   `server/data/scenarios/1946/regions.json` (или копия для ревью перед
   заменой). Схема не меняется, только значения.

## Как перегенерировать вход (если нужна свежая база)

```bash
python scripts/map/regen_names_ru.py
python scripts/map/import_to_game.py
python scripts/map/generate_country_registry.py
```

Это пересоздаёт `regions.json`/`countries.json` с нулевыми плейсхолдерами
заново — обнулит любые ручные правки экономики. Запускать только если
нужно подтянуть изменения геометрии/владельцев из `scripts/map/out/`.

## Проверка результата

- `cd server && npm test` — `RegionEconomyService`/`CreateGame`-связанные
  тесты не должны падать.
- Запустить сценарий 1946 в игре (`npm run dev` в `server/` и `client/`),
  выбрать страну, убедиться что ВПП/население в `TopStatBar` не нулевые и
  не выглядят как заглушка (см. `docs/tasks/` — это задание, проверка лежит
  на той же стороне, что выполняет заполнение).
