# Предложение по композиции HUD и информационных панелей

Статус: **обсуждается, не утверждено**

Дата: 2026-07-16

Основание: пользователь отклонил P1-компоновку и потребовал сначала согласовать
схему. До явного подтверждения этого документа UI-код по предложению не менять.

## Цель

Сохранить карту главным пространством, визуально связать национальные показатели
и навигацию, но не занимать фоном незаполненную ширину. Убрать постоянный
национальный briefing с карты и устранить эффект «окно внутри окна» в книгах
«Население» и «Рейтинги».

## 1. Компактный Header

Рекомендуемая композиция — Г-образный левый HUD и два независимых
content-sized блока справа:

```text
┌────────┬──────────────── СТАТЫ + РЕСУРСЫ ────────────────┐     [LLM]   [ДАТА | ХОД]
│        │ GDP  Казна  Нас.  Армия  Стаб.  Легит.  Ресурсы │             [инструменты]
│  ФЛАГ  ├─[1]─[2]─[3]─[4]─[5]─[6]─[7]─[8]─[9]─┐
│        │              КНОПКИ ПО КОНТЕНТУ       │
└────────┘                                       └ прозрачная карта
```

Геометрический контракт:

- у Header нет единой полноширинной подложки;
- флаг образует вертикальный якорь и связывает две строки;
- верхняя строка статов имеет ширину по содержимому с ограничением `max-width`;
- нижняя панель книг начинается справа от флага;
- её ширина равна фактической сумме кнопок, отступов и разделителей;
- фон и граница заканчиваются сразу после последней кнопки;
- свободная область справа прозрачна, через неё видна карта;
- LLM-status, дата/ход и инструменты справа не соединяются с левым блоком
  декоративным мостом и также имеют ширину по содержимому;
- при нехватке ширины сначала уплотняются числа и интервалы, затем ресурсы
  переходят в overflow; пустой фон не резервируется.

### Что означает «мостик»

Мостик — любая фоновая поверхность или рамка, визуально продолжающая группу
элементов после окончания её контента. В целевом варианте такой мостик не может
занимать весь viewport. Допустим только короткий конструктивный стык между
верхней строкой статов и панелью книг.

## 2. Национальный briefing по требованию

Постоянный `NationalBriefing` поверх карты убрать. Рекомендуемый anchor — флаг
страны, чтобы не добавлять ещё одну кнопку в Header:

```text
[ ФЛАГ ▼ ]
     │ click
     ▼
┌─────────────────────────┐
│ НАЦИОНАЛЬНАЯ СВОДКА     │
│ Ранг · национальная сила│
│ Цели и прогресс         │
│ Итог последнего хода    │
│                         │
│ [Открыть обзор страны]  │
└─────────────────────────┘
```

Поведение:

- закрыто по умолчанию;
- открывается под флагом;
- закрывается по Escape, клику снаружи и повторному клику по флагу;
- не меняет размеры Header и карты;
- действие «Открыть обзор страны» переносит игрока в подробную контекстную
  панель и не дублирует её содержимое целиком.

## 3. «Население»: плоский список вместо вложенных карточек

Текущая проблема: `SidePanel → panel-section → карточка региона` создаёт три
визуальные поверхности и ощущается как окно внутри окна.

Целевая схема:

```text
ГОС-ВО · CHINA
НАСЕЛЕНИЕ                                             [×]
─────────────────────────────────────────────────────────

ТЕРРИТОРИИ ИГРОКА · 8

Ганьсу                                      3.49M чел.
Пища 2.27K/мес · Древесина 81/мес
─────────────────────────────────────────────────────────
Хэбэй                                     37.08M чел.
Пища 33.26K/мес · Древесина 38/мес
─────────────────────────────────────────────────────────
Нинся                                       1.14M чел.
Пища 729/мес · Древесина 10/мес
```

Правила:

- большая внутренняя секция не имеет собственного фона, рамки и inset-card;
- строка региона не имеет карточной рамки;
- регионы разделяются одним `hairline`;
- название и население находятся в одной строке;
- ресурсы — компактная вторичная строка, без набора тяжёлых outlined-chip;
- одна территория должна занимать примерно 64–76 px, если нет дополнительных
  предупреждений или действий;
- hover/selection обозначаются слабой заливкой всей строки.

## 4. «Рейтинги»: таблица непосредственно на поверхности панели

```text
МИРОВОЙ РЕЙТИНГ

СТРАНА                  НАС.        ВВП       КАЗНА
──────────────────────────────────────────────────
■ Afghanistan            9.5M       201M      10.1M
■ Argentina             15.9M       2.17B     108.3M
■ China                110.0M       9.16B     457.8M
──────────────────────────────────────────────────
```

Правила:

- таблица не оборачивается во внутреннее окно/карточку;
- заголовок секции и таблица лежат на основной поверхности `SidePanel`;
- страна выравнивается влево, все числовые колонки — вправо;
- числа используют устойчивый компактный формат и не переносятся по символам;
- строки разделяются `hairline`, без индивидуальных рамок;
- выбранная страна получает одну слабую фоновую заливку;
- заголовок колонок может быть sticky внутри прокручиваемого содержимого;
- scrollbar панели — тонкий тёмный, без белого системного gutter.

## 5. Ограничения

- Не создавать полноширинный Header или декоративную полосу через карту.
- Не растягивать панель кнопок сверх фактического числа кнопок.
- Не возвращать постоянный `NationalBriefing` поверх карты.
- Не использовать более двух уровней визуальных поверхностей: сама панель и
  редкий локальный акцент; список/таблица не должны выглядеть отдельным окном.
- Не реализовывать эти изменения до утверждения wireframe пользователем.

   строки. Рекомендация: да.
2. Подтвердить: флаг открывает briefing-popover, а подробный обзор вызывается
   кнопкой внутри него. Рекомендация: да.
3. Выбрать оформление плоских списков: только разделители или слабое
   чередование строк. Рекомендация: только разделители, hover/selection заливкой.
4. После схемы отдельно решить ресурсную иерархию; до этого не убирать и не
   переставлять существующие источники ресурсов.
