## Назначение

Дом для дизайна военных конфликтов: как объявляется война, как она хранится
в состоянии игры, как считается бой, и какие последствия она тянет за собой
в других системах (политика, дипломатия). Расширяет 5 строк из
`docs/AI_RULES.md` ("Военная система").

Смежные доки: [`POLITICS.md`](POLITICS.md) (кризис легитимности после
войны), [`DIPLOMACY.md`](DIPLOMACY.md) (война как "зубы" союзов/сферы),
[`MAP_FEATURES.md`](MAP_FEATURES.md) (армии/флоты/авиабазы как визуальные
объекты, тег `battalion`).

## Текущее состояние в коде

### Поля `MilitaryState` (`shared/src/types/MilitaryState.ts`)

```
manpower, activePersonnel, reservePersonnel, militaryBudget
armyStrength, navyStrength, airStrength, nuclearWarheads
units: Unit[]
equipment: Record<EquipmentType, number>
```

### Состояние войны (реализовано 2026-07-06, Phase 1)

`GameState.wars: War[]` (`shared/src/types/War.ts`) — пара воюющих сторон
(с коалициями), дата начала, статус (`active`), счётчик флипов территории
для формулы мира. `LLMAction.type: 'war' | 'peace'` теперь реально создаёт/
завершает объект `War` через `WarService` (раньше был ярлыком-заглушкой без
модели состояния).

### Что уже есть и может быть фундаментом

- `MilitaryTick` (реализован, подключён — `AI_RULES.md` "Симуляция")
  считает рутинную военную динамику (manpower из населения региона, см.
  `AI_RULES.md` "Использование регионов"), но без понятия "противник" —
  работает независимо для каждой страны.
- Принцип боя уже зафиксирован в `AI_RULES.md:172-181`: **не**
  посекундная симуляция, а **модель фронтов/операций** — бой считается на
  границах контакта между регионами с разными `ownerCountryId`, находящимися
  в состоянии войны, не "по всей карте". Снабжение — от инфраструктуры
  региона и связности с тылом.
- `MapFeature` уже поддерживает военные типы (`battalion`, `fleet`,
  `airbase`, `naval_base`) и обязательный тег `battalion` для всех наземных
  соединений (`AGENTS.md`) — см. `MAP_FEATURES.md`.
- `Region.ownerCountryId` уже даёт границу контакта "бесплатно" (смена
  владельца — естественный результат боя), не нужна отдельная сущность.

## Легитимность после войны (реализовано 2026-07-06)

`docs/DECISIONS.md` (2026-06-22, "Threat/Rivalry Response"; уточнено
2026-07-06): исход войны → **детерминированное** изменение
`PoliticsState.legitimacy/governmentSupport` (`WarService.makePeace`) —
проигравший получает штраф, агрессор-проигравший — жёстче, затянувшаяся
ничья бьёт по обеим сторонам (военная усталость). Форма кризиса (протесты/
импичмент/переворот/ничего явного) — нарратив LLM, само срабатывание и
магнитуда — движок, не LLM.

## Реализовано (Phase 1, docs/DECISIONS.md 2026-07-06)

- `shared/src/types/War.ts` + `GameState.wars`.
- `server/src/services/WarService.ts` — `declareWar` (коалиции, идемпотентно),
  `makePeace` (формула легитимности), `getActiveWarBetween`.
- `server/src/simulation/war/WarTick.ts` — глобальный тик, контакт по
  `neighboringRegionIds`, флип `ownerCountryId`, `battalion` MapFeature на
  контактных регионах (убираются при `makePeace`).
- `AiBehaviorTick.ts` Правило D — порог войны для non-major.
- `LLMService.ts` — реальные `applyWarAction`/`applyPeaceAction`, секция
  `## Active Wars` в промте, инструкция избегать прямой войны между
  ядерными державами (не механика — только текст промта, полноценное
  сдерживание — Phase 3).
- `LLMResponseValidator.ts` — применимость `war`/`peace` (не дублирует
  идущую войну, нельзя объявить войну союзнику, `peace` требует активной
  войны).
- Живая проверка пройдена (объявление войны, коалиции, продвижение фронта,
  мир с легитимностью, очистка маркеров) — детали прогона и числа:
  `docs/DECISIONS.md`, 2026-07-06 ("War-система Phase 1").

## Явные пробелы Phase 1 (не реализовано сейчас)

- **Морские десанты (высадки)** — контакт ищется только через
  `neighboringRegionIds` (сухопутное соседство). Войны против заморских/
  островных целей без общей границы не находят точку контакта вообще, фронт
  не двигается. Отложено до починки `isCoastalRegion()`
  (`generateMapFeatures.ts`, сейчас всегда `false`) — готовая к внедрению
  механика (навал-превосходство открывает контакт) описана в TODO.md, не
  реализовывать плейсхолдером на `capitalRegionId`.
- **Phase 2** — tier-бакеты вооружения по видам техники, честное
  производство, привязка к `technology.domains`, декоративные названия
  оружия по эре, `LLMAction 'production_shift'`.
- **Phase 3** — логистика/окружение (BFS-связность), `War.supporters`
  (прокси от sphereOfInfluence), полноценное ядерное сдерживание в формуле
  порога ИИ (сейчас — только текстовая инструкция LLM, не механика).
- **Позже** — именные передвигаемые армии/флоты с приказами (Option 2 из
  обсуждения дизайна) — рост поверх Phase 1, не начинать без явного запроса.
