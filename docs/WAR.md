## Назначение

Дом для дизайна военных конфликтов: как объявляется война, как она хранится
в состоянии игры, как считается бой, и какие последствия она тянет за собой
в других системах (политика, дипломатия). Расширяет 5 строк из
`docs/AI_RULES.md` ("Военная система").

Смежные доки: [`POLITICS.md`](POLITICS.md) (кризис легитимности после
войны), [`DIPLOMACY.md`](DIPLOMACY.md) (война как "зубы" союзов/сферы),
[`MAP_FEATURES.md`](MAP_FEATURES.md) (армии/флоты/авиабазы как визуальные
объекты, тег `battalion`).

### Состояние войны (реализовано 2026-07-06, Phase 1)

`GameState.wars: War[]` (`shared/src/types/War.ts`) — пара воюющих сторон
(с коалициями), дата начала, статус (`active`), счётчик флипов территории
для формулы мира. `LLMAction.type: 'war' | 'peace'` теперь реально создаёт/
завершает объект `War` через `WarService` (раньше был ярлыком-заглушкой без
модели состояния).

### Что уже есть и может быть фундаментом

- `MilitaryTick` (реализован, подключён — `AI_RULES.md` "Симуляция")
  считает рутинную военную динамику (manpower из населения региона, см.
  `AI_RULES.md` "Использование регионов"), но без понятия "противник" —
  работает независимо для каждой страны.
- Принцип боя уже зафиксирован в `AI_RULES.md:172-181`: **не**
  посекундная симуляция, а **модель фронтов/операций** — бой считается на
  границах контакта между регионами с разными `ownerCountryId`, находящимися
  в состоянии войны, не "по всей карте". Снабжение — от инфраструктуры
  региона и связности с тылом.
- `MapFeature` уже поддерживает военные типы (`battalion`, `fleet`,
  `airbase`, `naval_base`) и обязательный тег `battalion` для всех наземных
  соединений (`AGENTS.md`) — см. `MAP_FEATURES.md`.
- `Region.ownerCountryId` уже даёт границу контакта "бесплатно" (смена
  владельца — естественный результат боя), не нужна отдельная сущность.

## Оккупация ≠ аннексия (реализовано 2026-07-11, план 08 Шаг 1)

> Только Шаг 1 плана `08_WAR_WAVE1.md` — Шаги 2-4 (war score/мирные
> договоры, потери, госдолг) отложены, см. «Отклонения при реализации» в
> файле плана.

Захват региона войной больше не переписывает владение мгновенно и навсегда:

- `Region.occupiedBy?: string` — оккупация поверх `Region.ownerCountryId`.
  Отсутствие = регион не оккупирован, полный контроль у легального
  владельца. `shared/src/utils/regionControl.ts::effectiveController(region)`
  — единая точка «кто сейчас фактически контролирует регион» (оккупант, если
  есть, иначе владелец).
- `WarTick.ts` — фронт (кто с кем граничит, у кого перевес) считается по
  `effectiveController`, не по легальному владению — иначе после первой же
  оккупации граница застревает на довоенной линии вместо боевой. Флип двигает
  только `occupiedBy` (`server/src/simulation/war/occupation.ts::
  setRegionOccupation`) — `ownerCountryId` не меняется войной вообще.
- **Эффекты оккупации:** добыча ресурсов региона (`ResourceTick.ts`) идёт
  оккупанту со штрафом (`OCCUPATION_EXTRACTION_PENALTY=0.5`,
  `shared/src/defines/occupation.ts`) — легальный владелец из оккупированного
  региона больше ничего не получает. `Region.stability` получает
  add-модификатор `OCCUPATION_STABILITY_PENALTY=-20` на весь срок оккупации
  (снимается при освобождении) — первое реальное использование
  region-уровневых модификаторов (план 03, белый список атрибутов не привязан
  к форме сущности — `target.kind` уже disambiguates `Country.politics.
  stability` от `Region.stability`).
- **Конец войны:** `WarService.makePeace` применяет условия по warScore
  (Шаг 2b, ниже) — победитель аннексирует часть оккупированного,
  неаннексированное возвращается легальному владельцу.
- **Осознанно не редиректится оккупанту**: ВВП/население страны
  (`aggregateCountryData.ts` по-прежнему считает по `ownerCountryId`),
  манпауэр/рождаемость/исследовательские центры (`MilitaryTick`/
  `PopulationTick`/`ResearchTick`) — план называет только «доход/добычу».
  Клиентская визуализация (штриховка оккупированной территории) — не
  реализована, интерфейс заморожен.

## Потери → демография (реализовано 2026-07-11, план 08 Шаг 3)

Война теперь стоит людей. `WarTick.ts` каждый месяц начисляет потери сторонам
активной войны и накапливает их в `War.casualties: Record<countryId, number>`
(вход для warScore — Шаг 2a — и мирового факта в промте LLM).

- **Объём потерь.** Общий помесячный урон = `WAR_CASUALTY_BASE_PER_FRONT_REGION`
  (`shared/src/defines/war.ts`, 10 000 — тюнингуемый плейсхолдер) × число
  фронтовых (контактных) регионов обеих сторон. Делится между сторонами по
  доле силы ПРОТИВНИКА: `своя доля = opposingStrength/(own+opposing)` —
  слабейшая сторона теряет больше. Без контакта (нет фронта) потерь нет.
- **Порядок списания** по каждой стране: `military.activePersonnel` в первую
  очередь (кадровые потери) → переполнение сверх активной армии уходит в
  `Region.population` регионов, которые страна фактически контролирует
  (`effectiveController`, пропорционально населению, пол 0) → `military.manpower`
  уменьшается на весь урон страны (мобилизационный пул ужимается и от павших
  солдат, и от погибших гражданских).
- **Нюанс баланса.** Интенсивность привязана к участку фронта, НЕ
  пропорциональна размеру армии. Поэтому маленькая армия быстро исчерпывается и
  потери «переливаются» в гражданское население — тематически это разгром малой
  армии, а не баг. Восстановление демографической ямы идёт естественным ростом
  `PopulationTick` (яма на десятилетия получается сама, отдельной механики
  восстановления нет).
- **Осознанно вне Шага 3:** порог потерь → мировой факт «X потеряла N человек»
  в промте (придёт с warScore, Шаг 2a); эффект потерь на legitimacy/stability
  сверх послевоенного штрафа (Шаг 2/4).

## warScore — кто побеждает (реализовано 2026-07-11, план 08 Шаг 2a)

`server/src/simulation/war/warScore.ts::computeWarScore(war)` — **чистая
функция**, не хранимое поле War (производное состояние — флипы + потери уже в
War — не дублируется в GameState, считается на месте, не рискует рассинхроном).
Диапазон −100..100 от лица атакующих (+ = атакующие впереди).

- **Территориальная компонента:** `(toAttackers − toDefenders) ×
  WARSCORE_PER_NET_FLIP` (15). ~7 чистых флипов = решительные 100.
- **Компонента потерь:** `(defenderCas − attackerCas)/(сумма) ×
  WARSCORE_CASUALTY_WEIGHT` (40). Кто пролил меньше крови относительно врага —
  в плюсе. Максимум ±40 от потерь, территория добивает до ±100 (капается).
- **Использование:** промт LLM (секция Active Wars теперь показывает war score
  + ярлык `warScoreLabel` + потери сторон) — модель предлагает соразмерный мир,
  не выдумывая по цифре. Ценообразование мирного договора против warScore —
  Шаг 2b (мир + границы, отдельный заход).
- **Нюанс баланса / отклонение от буквы плана:** план называл третьим входом
  «длительность (истощение тянет к миру)». warScore здесь — измеритель
  ПРЕИМУЩЕСТВА (кто побеждает), а не готовности к миру; истощение от
  длительности отыгрывается отдельной военной усталостью в `makePeace`
  (`STALEMATE_WEARINESS_*`), не смешивается с сигналом преимущества — иначе
  решительная, но долгая победа занижалась бы неверно.

## Мирное разрешение и аннексия (реализовано 2026-07-11, план 08 Шаг 2b)

`WarService.makePeace` → `applyPeaceTerms(war)` — детерминированные условия по
warScore. LLM/игрок решает, КОГДА заключить мир (действие `peace`); движок —
СКОЛЬКО территории переходит.

- **Белый мир.** `|warScore| < WARSCORE_ANNEXATION_THRESHOLD(30)` — граница не
  меняется, вся оккупация войны снимается (`revertOccupationForWar`).
- **Аннексия по warScore.** Иначе победитель (сторона по знаку warScore)
  аннексирует оккупированные ИМ регионы проигравшего — но не больше «бюджета
  очков»: `maxAnnex = floor(|warScore| / WARSCORE_COST_PER_ANNEXED_REGION(25))`.
  Выбор регионов детерминирован (по возрастанию id). Остальная оккупация
  снимается. Проигравший-оккупант ничего не аннексирует.
- **`transferRegion`** (`simulation/war/occupation.ts`) — единственная
  прод-мутация `ownerCountryId` вне сценарной загрузки: меняет владельца и
  снимает оккупацию (occupiedBy + стабильность-модификатор). Командная обёртка
  `commands/war.ts::transferRegion` — для будущего LLM-действия с условиями.
- Числа — тюнингуемые плейсхолдеры (`shared/src/defines/war.ts`). Легитимность/
  репарации проигравшему (ниже) применяются поверх, без изменений.
- **Отложено (обогащение):** LLM предлагает конкретный `PeaceTerms` (составной
  `data`-объект контракта), валидируемый против того же бюджета warScore — нужен
  живой прогон Gemini, отдельный заход. Сейчас условия чисто детерминированы.

## Явные пробелы (не реализовано сейчас)

- **Морские десанты (высадки)** — контакт ищется только через
  `neighboringRegionIds` (сухопутное соседство). Войны против заморских/
  островных целей без общей границы не находят точку контакта вообще, фронт
  не двигается. Отложено до починки `isCoastalRegion()`
  (`generateMapFeatures.ts`, сейчас всегда `false`) — готовая к внедрению
  механика (навал-превосходство открывает контакт) описана в TODO.md, не
  реализовывать плейсхолдером на `capitalRegionId`.
- **Phase 3** — логистика/окружение (BFS-связность), `War.supporters`
