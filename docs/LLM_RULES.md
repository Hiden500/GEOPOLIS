# LLM World Simulation Rules

Last updated: 2026-07-10

## Роль LLM в архитектуре

**LLM — главный двигатель событий и обработчик решений и последствий.**

Это значит:
- Каждое решение игрока проходит через LLM: она интерпретирует намерение, оценивает реалистичность, генерирует структурированные последствия.
- Мировые события (перевороты, кризисы, войны, дипломатические сдвиги) инициируются LLM, а не жёстко закодированы.
- ИИ-страны для качественных решений (война, пакты, нацфокусы) используют LLM, а не хардкод.

**LLM не является игровым движком и не заменяет детерминированные тики.**

Детерминированные тики (EconomyTick, ResourceTick, PopulationTick, MilitaryTick, ResearchTick, DiplomacyTick) работают независимо от LLM каждый месяц и остаются единственным источником числовых данных о состоянии мира.

Разделение ответственности:

```
[детерминированные тики] → [состояние мира: ВВП, manpower, ресурсы, ...]
                                        ↓
[действия игрока + мировой контекст] → [LLM: интерпретирует + генерирует события
                                         + формирует структурированные последствия]
                                        ↓
                              [движок применяет последствия]
                                        ↓
                              [обновлённое состояние мира]
```

Игровой движок является единственным источником истины. LLM предлагает изменения — движок валидирует и применяет.

Ход геймплейно заблокирован без ответа LLM: `GameState.llmRespondedThisTurn` —
пока флаг не выставлен, `GameService.advanceMonth` бросает `LLMGateError`
(HTTP 409) и месяц не продвигается. Флаг сбрасывается после успешного хода.
Гейт работает одинаково и для ручного цикла, и для авто-цикла.

Ответ LLM может быть получен двумя путями: ручной clipboard-цикл
(`LLMPanel`) или автоматизированный `GeminiProvider` (`POST /llm/auto`).
Правила промта одинаковы для обоих — остальное содержимое этого файла
провайдер-агностично.

### Два канала изменений: `actions` и `primitives` (2026-07-26)

Ответ модели несёт два независимых массива, и путать их не следует.

- **`actions`** — исторические 11 действий (`docs/plans/02_LLM_CONTRACT.md`).
  Остаются как есть, grandfather.
- **`primitives`** — алфавит примитивов воздействия (`docs/PRIMITIVES.md`).
  Разбирается по элементам (`parsePrimitives`), применяется через границу хода
  (`server/src/primitives/turnBatch.ts`), возвращает ФАКТИЧЕСКИЕ величины.
  Массив необязателен: месяц без режиссуры — законный ответ.

Три правила канала примитивов, которые держит код, а не текст промта:

1. **Idempotency на ход** (`CONCEPT.md` §7.2). Ключ выводится из содержания
   ответа и текущей игровой даты; повторно поданный тот же ответ примитивы
   второй раз не применяет. Старый канал `actions` этой защиты НЕ имеет —
   зафиксировано в `docs/TODO.md`.
2. **Граница агентности.** Каждый глагол алфавита отнесён к одной из двух
   сторон в `VERB_AGENCY` (`server/src/llm/primitiveAgency.ts`): акт
   государственной политики (`playerDecision`) с источником = страна игрока
   отклоняется, давление извне и снизу (`worldPressure`) разрешено. Сегодня
   решениями игрока считаются `repress`, `grant_autonomy`, `enact_reform`,
   `diplomacy`, `sanction`, `war`, `peace`, `send_aid`, `condemn`,
   `support_proxy`; миром, действующим на игрока, — `incite_unrest`,
   `spawn_incident`, `capital_flight` и `split_country` (последний разрешён
   осознанно: подтверждением необратимого служит выбор осколка). Проверяется
   кодом, а не просьбой в промте.

   Словарь **полный по типу** (`Record<PrimitiveVerb, AgencySide>`) намеренно:
   до 2026-07-29 граница была списком из трёх глаголов, который не обновлялся,
   пока алфавит рос с пяти до четырнадцати, и девять новых — включая `war` —
   молча проходили за игрока. Новый глагол теперь не компилируется без решения
   о его стороне.
3. **Числа последствий модель не называет.** Она пишет нарратив ДО применения и
   знать величин не может. Фактические дельты считает движок после commit'а и
   отдаёт их интерфейсу (локализуемый отклик) и следующему промту.

### Секции промта, зависящие от политического ядра

- **`## Regional Crises`** — регионы под кризисным латчем, развёрнуто не более
  `MAX_PROMPT_CRISES` (сейчас 5, `CONCEPT.md` §7 «hard-cap ≤ ~5»), отбор по
  АКТУАЛЬНОЙ остроте каждый рендер, хвост — одной агрегатной строкой с истинным
  числом оставшихся. Секция выводится из латча, а не из одноразовых фактов:
  факт `region_crisis` выдаётся один раз при пересечении порога, поэтому отбор
  среди фактов терял бы невлезший кризис навсегда. Пересчёт остроты даёт
  «тлеющий всплывает сам», а снятый кризис исчезает сам.
- **`## Rejected Attempts Last Cycle`** — отклонённые примитивы с причинами
  (`PRIMITIVES.md` §3, «чтобы не долбилась в невозможное»). Одноразовая:
  потребляется при рендере.

## Обработка решений игрока

Игрок выражает намерение **свободным текстом** (не структурной формой с фиксированными типами действий) — строить, воевать, дипломатить, инвестировать, что угодно словами.
LLM получает: намерение игрока (как есть, без структурирования на стороне движка) + снимок релевантного состояния мира (страна игрока, соседи, текущий год, события).
LLM возвращает: структурированный список изменений состояния (примитивы воздействия, `docs/PRIMITIVES.md`) + нарративный текст (что произошло и почему) — именно LLM переводит свободный текст намерения в структуру, не движок.
Движок: валидирует структуру, проверяет допустимость (нет ресурсов → отказ), применяет изменения.

Игрок **не** получает детерминированный ответ типа "+100 производства" — он получает нарратив с реалистичными последствиями, рассчитанными LLM в пределах, выставленных движком.

Идентификаторы стран/регионов в промте и в ответе LLM — только реальные id, никогда не имя. LLM **никогда** не угадывает/сокращает id из названия (например, не превращает "Soviet Union" в "SOV" — реальный id может быть "SUN"); все допустимые id перечисляются явно в промте, LLM обязана скопировать их дословно.

**Guardrails на намерение игрока** (docs/plans/02_LLM_CONTRACT.md, Шаг 5,
2026-07-10; переписано 2026-08-02 под единственный оставшийся канал):
намерение интерпретируется LLM только в примитивы воздействия с теми же
предпосылками и капами, что и любой другой источник (приказ игрока,
топ-держава через LLM) — свобода формулировки текста не даёт полномочий выйти
за пределы контракта (`server/src/primitives/primitiveSchemas.ts` — форма по
глаголу; `PrimitiveEngine` — предпосылки, коридоры величин и капы хода).
Историческая неправдоподобность намерения (см. §"Альтернативная история"
ниже — фантастическое намерение принимается как канон нарративно) — вопрос,
отдельный от магнитуды: даже канонизированное намерение проходит через тот же
контракт, никакого «привилегированного» пути применения не существует. С
2026-08-02 это гарантировано сильнее, чем устройством пайплайна: ВТОРОГО
канала нет — старый `actions` удалён, а массив с таким именем отклоняется
кодом `legacyActionsChannel`. Ни схема примитива, ни движок не имеют доступа к
`game.playerIntent` и не читают его при валидации/применении. Лимит длины намерения — на границе API (`playerIntentSchema`,
`server/src/validation/schemas.ts`, 2000 символов).

## Приоритеты

При генерации решений LLM обязана учитывать:

1. Интересы государства.
2. Внутреннюю ситуацию государства.
3. Экономические возможности.
4. Военные возможности.
5. Дипломатическую ситуацию.
6. Исторический контекст текущего года.
7. Только после этого действия игрока.

LLM не должна концентрироваться исключительно на игроке.

---

## Симуляция стран

Каждая страна должна рассматриваться как самостоятельный актор.

Каждый ход LLM обязана предполагать, что все государства продолжают:

- строить объекты;
- развивать экономику;
- исследовать технологии;
- развивать армию;
- проводить дипломатическую деятельность;
- реагировать на соседей;
- реагировать на мировые события.

Даже если игрок ничего не делает, мир должен продолжать развиваться.

---

## Ограничения знаний

LLM никогда не должна хранить карту мира в контексте.

LLM никогда не должна оперировать предположениями о существовании регионов.

Все регионы, страны, провинции, моря, океаны и объекты должны использоваться только из данных, переданных игровым движком.

Если регион отсутствует в переданных данных, он считается неизвестным.

---

## Работа с регионами

LLM никогда не должна использовать названия регионов как уникальные идентификаторы.

Все действия должны использовать идентификаторы объектов.

Пример:

Плохо:

"Построить завод в Уральской области"

Хорошо:

{
  "action": "build_factory",
  "regionId": "USSR-URAL-12"
}

Это иллюстративный пример принципа (идентификаторы вместо названий) —
реальных региональных LLM-экшенов пока нет в списке action-типов (см.
"Экономика" ниже).

---

## Работа с картой

LLM не должна создавать полигоны.

LLM не должна изменять геометрию карты.

LLM может только предлагать изменения игрового состояния:

- смена владельца региона;
- создание объекта;
- удаление объекта;
- изменение характеристик объекта;
- изменение характеристик страны.

---

## Масштабирование

Система должна корректно работать с:

- полным набором регионов мира (число — см. docs/WORLD.md);
- 100+ государствами;
- десятками тысяч объектов карты.

LLM не должна требовать загрузки полного мира в контекст.

LLM должна работать только с релевантным подмножеством данных.

### Учёт расхода токенов

Бюджет промта назван в `docs/CONCEPT.md` §7 (~8–10k токенов). Чтобы он
проверялся фактом, а не назначался на глаз, каждый **автоматический** вызов
модели пишет строку в `logs/token-usage.jsonl`: вход, выход, токены
рассуждения, итог, время, модель и назначение вызова
(`world-cycle` / `intent-translation`).

```text
node scripts/token-usage-report.mjs
```

Отчёт даёт перцентили по каждому назначению отдельно — мировой цикл и перевод
приказа игрока отличаются по размеру на порядок, и общее число не описывает ни
один из них. Метод «ближайший ранг»: предел назначается по реально
случившемуся вызову, а не по интерполяции между двумя, которых не было.

Границы, названные явно: телеметрия только записывает и ничего не ограничивает;
сбой записи не роняет ход (`appendTokenUsage` возвращает `false`); ответ
провайдера без `usageMetadata` — не ошибка, а отсутствие строки в журнале;
ручной copy-paste цикл журнал не пишет вовсе, потому что расход в нём несёт
внешний сервис.

---

## Военные действия

LLM не должна самостоятельно рассчитывать результаты боя.

LLM должна принимать решения:

- наступать;
- обороняться;
- перебрасывать силы;
- мобилизовываться;
- заключать мир.

Результаты рассчитываются игровым движком.

**Статус реализации:** из перечисленного как LLM actions реализованы только
`war` и `peace` (объявление войны / заключение мира через `WarService`).
Тактические решения — наступать/обороняться/перебрасывать силы/
мобилизовываться как отдельные LLM actions — целевая модель, пока не
реализованы: фронт считается полностью детерминированно в `WarTick.ts` по
`military.activePersonnel`, без LLM-input на тактическом уровне.

---

## Экономика

LLM не рассчитывает ВВП.

LLM не рассчитывает производство ресурсов.

LLM не рассчитывает логистику.

LLM только принимает решения:

- строить завод;
- строить шахту;
- строить порт;
- строить железную дорогу;
- инвестировать в отрасль.

Все результаты рассчитываются игровым движком.

**Статус реализации:** список выше — целевая модель, пока **не** реализована
как LLM actions (строить завод/порт/жд, инвестировать в отрасль как
отдельные экшены отсутствуют). Реализовано сейчас — `research_shift`
(домен-инвестиции технологий: `data.domain`/`data.share`),
`production_shift` (фокус производства техники: `data.equipmentType`/
`data.share`, War Phase 2) и `build_extraction` (docs/plans/04_RESOURCES.md,
2026-07-11 — частичная реализация «строить шахту»: `data.regionId`/
`data.resource`/`data.delta` меняет уровень добывающих мощностей на ±1 за
ход; визуальная MapFeature-фича шахты — за скобками, план 06), все три
доступны и игроку, и топ-державам через `sourceCountryId`, по тому же
паттерну, что объявление войны. **Устарело 2026-08-02:** канала `actions` не существует. Все перечисленные
воздействия — глаголы алфавита примитивов (`docs/PRIMITIVES.md` §2), где
величину считает движок из состояния, а причина отказа приходит структурным
кодом. `influence` удалён 2026-07-29 (влияние покупается помощью, `send_aid`).
Не смешивать два статуса — целевой список экономики и фактически реализованные
глаголы — как единое актуальное правило.

> **Superseded ([`CONCEPT.md`](CONCEPT.md) §2, §5.6):** «целевой список» отдельных
> build-экшенов пересмотрен. Целевой end-state — **единый алфавит примитивов**
> (`построить_объект`/`переместить_объект`/… ~15–20 глаголов), а не расширение
> фиксированного каталога действий; строительство игрока и LLM идёт одним валидируемым
> алфавитом, не отдельным build-путём. Каталог выше описывает текущий контракт кода.

## Историческая достоверность

LLM обязана учитывать исторические реалии текущего года.

1946 год не должен использовать технологии 1980-х годов.

1880 год не должен использовать технологии XX века.

События должны соответствовать доступным технологиям, политическим условиям и уровню развития эпохи.

Помимо простого отсутствия анахронизмов, LLM обязана, где применимо, опираться на **конкретные реальные события** текущего месяца/года, а не только на обобщённые формулировки ("напряжённость растёт") — например, называть реально произошедшее событие с датой, если оно есть, вместо расплывчатого пересказа общей тенденции. Это правило уступает приоритет §"Альтернативная история" ниже: если предыдущие ходы уже увели мир от реальной истории, LLM следует логике изменённого мира, а не насильно возвращает события к историческому результату.

---

## Альтернативная история

После отклонения от реальной истории LLM должна руководствоваться логикой мира, а не пытаться возвращать события к историческому результату.

Игрок может изменить ход истории.

Другие государства должны реалистично реагировать на последствия этих изменений.

---

## Генерация событий

События должны возникать не только вокруг игрока.

Большинство событий должны происходить независимо от игрока.

Мир обязан создавать собственую историю.

Примеры:

- экономические кризисы;
- перевороты;
- выборы;
- гражданские войны;
- научные открытия;
- локальные конфликты;
- дипломатические кризисы;
- колониальные восстания.

Игрок является частью мира, а не центром вселенной.

Механизм в промте: помимо великих держав (`## Major Powers`, страны с `tier === 'major'`), каждый цикл в промт попадает ротация non-major стран (`## Spotlight Countries`, детерминированный round-robin по id) — LLM **обязана** дать конкретный сюжетный бит минимум двум из них в нарративе за цикл, не просто общей фразой. Нарратив за цикл — минимум три смысловых абзаца: великие державы, Spotlight-страны конкретно, прогноз на следующий месяц. LLM **не должна** упоминать или предпринимать действия за страны, не перечисленные явно в промте (`## Country IDs`) — если страны нет в списке, для симуляции её сейчас не существует.

Память страны: в блоках `## Player Country`/`## Major Powers`/`## Spotlight
Countries` движок показывает строку "Recent: <title> (<дата>)" — последние N
заголовков (`title`) из `eventHistory` этой страны. Это не новое поле в
ответе LLM — только фильтрация/форматирование уже существующего `title`,
который LLM и так производит каждый цикл.

**Когда текст ответа становится событием** (исправлено 2026-07-26 по внешнему
аудиту; контракт целиком — `docs/PRIMITIVES.md` §3, «Нарратив только после
commit»). До правки `title`/`descriptions` уходили в `eventHistory`
безусловно, поэтому предложение, отклонённое границей агентности или
предпосылками движка, всё равно становилось каноном: «Восстание подавлено» при
неприменённой репрессии попадало в память страны, а через год — в летопись.
Теперь:

- ответ **предложил** изменения (`actions` и/или `primitives` непусты) и **ни
  одно не применилось** → события нет; текст уходит диагностикой игроку и
  причинами отказа в следующий промт, но каноном не становится;
- применилось хоть что-то → событие записывается вместе с машиночитаемым
  результатом (`Event.primitiveOutcomes` / `Event.rejectedPrimitives`), и
  потребитель ПОЛУЧАЕТ ЧЕМ проверить заголовок — но сам заголовок остаётся
  сырым текстом модели и по факту не переписывается;
- ответ вообще ничего не предлагал → чистый нарратив, законное событие: движку
  он ничего не предлагал, проверять в нём нечего.

**Степень подтверждённости и что из неё следует для летописи** (решение
пользователя 2026-07-27 по итогам внешнего аудита; контракт целиком —
`docs/PRIMITIVES.md` §3). Каждое событие несёт `Event.factuality`, выведенную
из чисел применённого и отклонённого (`server/src/llm/eventFactuality.ts`):
`confirmed` — всё предложенное движку применено; `partial` — часть отклонена, и
текст вправе описывать именно её; `unconfirmed` — движку не предлагалось
ничего. Значение считает код, вызывающий его не выставляет.

- **Летопись** (`ChronicleTick`) берёт заголовок только у `confirmed`; у
  `partial` вместо заголовка идут фактические следы применённых примитивов из
  `Event.primitiveOutcomes`; `unconfirmed` в неё не попадает вовсе. Причина в
  цене ошибки: летопись целиком уходит в КАЖДЫЙ промт и живёт всю партию, так
  что ложное утверждение там дороже пропущенного.
- **«Память страны»** (`getRecentTitlesLine`) и **`## Recent Events`**
  по-прежнему берут `Event.title` дословно, включая частично подтверждённые, —
  граница названа осознанно: окно там короткое и самоочищается, а без него
  модель лишилась бы операционного контекста собственного прошлого хода.
- **Игрок** видит пометку у неподтверждённого текста в ленте событий и в панели
  цикла — там она читается как заявление режиссёра, а не как факт.
- Приведение самого ТЕКСТА к факту требует второго вызова модели («перепиши по
  фактам») и отнесено к Милстоуну 1 (`docs/TODO.md`).

`Event.countries` (по какой стране событие попадёт в её память) считается из
ФАКТИЧЕСКИ применённого — источник примитива, контролёры затронутых регионов,
страна реформы, — а не только из старого канала `actions`. Раньше чистое
primitive-событие получало пустой список и выпадало из памяти собственной
страны.

Летопись кампании (`## Chronicle`, docs/plans/02_LLM_CONTRACT.md, Шаг 3,
2026-07-10): память страны выше решает проблему в пределах ~24 ходов
Spotlight-ротации, но на десятилетия кампании этого мало — "почему Франция
ненавидит нас с 1953?" уже негде понять из окна последних N заголовков.
Раз в игровой год движок склеивает заголовки `eventHistory` завершившегося
года в одну строку-запись (`GameState.chronicle`, `ChronicleTick.ts`) —
промт получает всю летопись целиком, старейшие записи первыми. **Статус
реализации:** только детерминированная конкатенация заголовков (до 5 на
год), без вызова LLM — LLM-сжатие в более связный текст отложено до
подтверждения на практике, что дешёвый вариант недостаточен (docs/DECISIONS.md,
2026-07-05). Не заменяет `## Recent Events` (последние 5 событий глобально,
операционный контекст текущего цикла) — разная зернистость, обе секции
нужны одновременно.

## Язык вывода

Язык нарративного текста (`title`, `descriptions`) фиксируется при создании игры (`GameState.locale`) и передаётся в промт явной инструкцией — LLM пишет весь генерируемый текст на этом языке. Это не относится к идентификаторам стран/регионов и другим служебным полям — те никогда не переводятся. Смена языка на лету посреди партии не поддерживается.

Это правило про язык нарратива LLM — **не** про полную мультиязычность игры.
Интерфейс и `Country.name`/`getText()` пока не локализованы; это отдельная
нереализованная задача (см. `docs/TODO.md`).

## Стиль нарратива (2026-07-30)

Промт запрещает прозе три вещи, и каждая ломает фикцию изнутри: цитировать
точные числа и суммы из данных промта, вносить технические идентификаторы в
текст (имя страны с её кодом в скобках) и упоминать симуляцию, кампанию, ход
или «данные».

Правило появилось из замера, а не из вкуса: на локальной модели без него
нарушения были в 7 прогонах из 10 («$118.69B» в прозе, «США (USA)», «в этом
симуляции»), с ним — 0 из 4 при неизменной схема-валидности. Цена — около 142
токенов промта. Разделение труда то же, что во всём проекте: **числа
принадлежат движку, смысл — хронике**.

Граница: замер делался русской формулировкой, отправленной отдельным
сообщением; в промт внесён английский эквивалент рядом с секцией языка, и
эффект именно английской редакции не перемерен.

## Провайдеры автоматического цикла (2026-07-30)

Провайдер по умолчанию — **локальный** OpenAI-совместимый рантайм
(`LLM_PROVIDER=local`), облачный Gemini доступен переключением. Реализации
живут за одним интерфейсом `LLMProvider`, который принимает **Zod-схему**, а не
готовую схему провайдера: диалекты structured output разные, и конвертировать
обязан тот, кто знает свой API, иначе роутер начинает знать, к кому подключён
движок.

Требования к локальному рантайму — не настройки, а условия работоспособности
(замер `.agent/runs/local-llm-runtime-bench-2026-07-30.json`):

- **Формат ответа держит инструкция в конце промта, а не `response_format`**
  (уточнено 2026-08-01, см. ниже). На рантайме, который грамматику применяет,
  без `json_schema` было 0 схема-валидных из 10 против 10 из 10 с ней; на шлюзе,
  который её только принимает, схема не даёт ничего, и работает инструкция.
- **Лимит генерации не ниже 8192 при включённом размышлении.** На 4096 — 3 из
  10, причём провалы не качественные: размышление съедало лимит целиком.
- **Размышление включено по умолчанию.** Оно стоит 60 с против 6 с, но снимает
  выдуманные идентификаторы: 0 против 7 несуществующих доменов технологий на 10
  ходов. Выдуманный домен проходит схему (`domain` в контракте — свободная
  строка) и отклоняется уже применимостью, то есть «быстрый» режим платит
  отклонёнными действиями, а не секундами.

Расход токенов пишется одинаково для обоих провайдеров, но считается по-разному
по необходимости: у Gemini размышление идёт отдельной статьёй сверх ответа, у
OpenAI-совместимых — внутри `completion_tokens`, поэтому во втором случае оно
вычитается. Без этого один и тот же ход давал бы несопоставимые перцентили.

### Как просить JSON: инструкция, а не `response_format` (2026-08-01)

Замер `.agent/runs/gemini-prompt-modes-2026-08-01/` — 140 вызовов на реальном
промте хода через OpenAI-совместимый шлюз с ключом (модель
`gemini-3.6-flash-high`), 12 конфигураций по двум независимым осям: способ
запроса формата и наличие инструкции «верни только JSON» в конце промта.

**`response_format` на таком шлюзе не работает вовсе.** Без инструкции ответ
приходил в markdown-заборе **60 раз из 60** — одинаково при `json_schema` со
`strict: true`, при `strict: false`, при `json_object` и вообще без
`response_format`. С инструкцией — **0 из 80**. База против кандидата по 30
вызовов: 30/30 против 0/30, Fisher p = 1,5·10⁻¹⁴.

Метрика здесь важнее вывода: по доле схема-валидных ответов разницы НЕ видно
(138 из 140 везде), потому что забор снимает `stripCodeFence` ещё до валидации.
Мерить пользу `response_format` надо по сырой форме ответа, иначе защита от
дефекта выглядит его отсутствием.

Отказ от схемы не поднял долю выдуманных идентификаторов: 2 прогона из 40 со
схемой против 8 из 100 без неё, p = 0,72. `research_shift.domain` в контракте —
свободная строка, схема его не ограничивает, поэтому и удержать не может.

Умолчание `LocalOpenAIProvider` — `LOCAL_LLM_RESPONSE_FORMAT=prompt`: инструкция
дописывается в конец промта (`server/src/llm/jsonOnlyInstruction.ts`),
`response_format` не отправляется. Схема возвращается значением `json_schema` —
рантайм, применяющий грамматику, от неё по-прежнему выигрывает, и замер на шлюзе
про него ничего не говорит. Инструкция стоит 87 токенов промта; схема, вопреки
ожиданию, в `prompt_tokens` шлюзом не включалась вовсе.

`reasoning_effort` шлюз, в отличие от схемы, ПРИМЕНЯЕТ: «не задан» и `none` —
разные состояния (ход 4,9 с против 2,5 с при нулевом размышлении в обоих), а
видимое размышление даёт только `high` (2573 знака, ход 6,6 с). На формат ответа
ось не влияет; умолчание по ней не менялось.
