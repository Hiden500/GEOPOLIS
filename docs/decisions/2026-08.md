## Легитимность усиливает репрессию и удешевляет её — доминирование по обеим осям снято (2026-07-31)

На фикстуре среза (`stability = 70`, доля группы 0.88, хинт `severe`):
`legitimacy = 100` даёт `suppression 0.5444 / alienation 0.1000`,

растёт вместе с легитимностью, то есть ровно та «иная цена легитимной
власти», которой этот пункт и требовал. Строгого доминирования больше нет:
легитимный режим давит сильнее и мягче, но каждый разгон тратит то, что даёт
ему оба преимущества. (Калибровка второй оси — отчуждение опускается до пола
коридора у полностью легитимного режима — осталась открытым вопросом в

## 2026-08-01 — JSON у локального провайдера просит промт, а не `response_format`

**Решение.** Умолчание `LocalOpenAIProvider` — `LOCAL_LLM_RESPONSE_FORMAT=prompt`:
`response_format` не отправляется, а в КОНЕЦ промта дописывается инструкция
«верни только JSON» (`server/src/llm/jsonOnlyInstruction.ts`).
`generatePrompt()` не тронут — промт хода и требование к формату склеиваются в
провайдере. Прежнее поведение возвращается одним значением `json_schema`
(строгая схема + промт без добавки), есть и `json_object`. Опечатка в
переменной роняет запрос, а не откатывается молча.

**Замер.** `.agent/runs/gemini-prompt-modes-2026-08-01/` — 140 вызовов на
реальном промте хода через шлюз с ключом (`gemini-3.6-flash-high`), 12
конфигураций по двум независимым осям. Без инструкции ответ приходил в
markdown-заборе **60 раз из 60**, ОДИНАКОВО при `strict: true`, `strict: false`,
`json_object` и вообще без `response_format`. С инструкцией — **0 из 80**. База
против кандидата по 30 вызовов: 30/30 против 0/30, Fisher p = 1,5·10⁻¹⁴.

**Метрика важнее вывода.** По доле схема-валидных ответов разницы НЕ видно —
138 из 140 во всех режимах, — потому что забор снимает `stripCodeFence` ещё до
валидации. Прошлый замер (2026-08-01, до `stripCodeFence`) видел забор только
как провал парсинга и потому оценил его в 3 из 10; на самом деле он был в 10 из
10. Защита от дефекта выглядела его отсутствием, и первая версия этой задачи
чуть не сравнила режимы по метрике, которая их не различает.

**Цена отказа от схемы не подтвердилась.** Выдуманных идентификаторов: 2
прогона из 40 со схемой против 8 из 100 без неё, p = 0,72. Иначе и быть не
могло — `research_shift.domain` в контракте свободная строка, схема его не
ограничивает ничем; все 10 случаев именно `Unknown technology domain`.
Токенами схема тоже не стоила: нижняя граница `prompt_tokens` одинаковая (5976)
со схемой и без. Инструкция, наоборот, стоит +87 токенов на ход. То есть замер
подтвердил ЗАМЫСЕЛ задачи (строгий режим бесполезен), но опроверг её
обоснование (схема занимает место в запросе).

**Поправка к записи от 2026-07-30.** `reasoning_effort` шлюз ПРИМЕНЯЕТ, вопреки
выводу «размышления нет вовсе»: «не задан» и `none` — разные состояния (ход
4,9 с против 2,5 с при нулевом размышлении в обоих), видимое размышление даёт
только `high` (2573 знака, 6,6 с). На формат ответа ось не влияет; умолчание по

**Проверено.** `LocalOpenAIProvider.test.ts` (21 тест). Негативный контроль: на
восстановленном из HEAD провайдере падают 4 из 5 новых тестов; пятый —
«`json_schema` возвращает прежнее поведение» — на старом коде проходит по
построению, он и есть гарантия отката. `npx tsc --noEmit`, `npm test` (server),

## 2026-08-01 — Правило C стало двусторонним; храповик, который держит мир, оказался у Правила A

**Решение.** Правило C возвращает долю welfare → military, когда stability
поднимается выше `STABILITY_RECOVERED` (= `STABILITY_LOW` + 5). Между порогами
— гистерезисная зона, в ней бюджет не двигается. Границы возврата — стартовые
доли обеих статей (= `spendingFloor` × 2): military не выше своей стартовой,
welfare не ниже своей. Новых полей и миграции сейва не потребовалось. Команда
`shiftWelfareToMilitary` — зеркало существующей, обе через один механизм.

**Почему именно такие границы.** Возврат обязан отменять ровно СВОЙ сдвиг:
верхняя граница не даёт спорить с военным ramp'ом Правила B (у страны, которую
B подняла выше старта, возврат — ноль), нижняя не даёт отыгрывать назад
урезание Правила A. Ширину гистерезиса выбрал замер, а не вкус: из 82 стран с
просевшей военной долей черту 45 к десятому году перешагнули 17, черту 50 —

## 2026-08-01 — Экономический вход недовольства: двусторонний и по своей стране. Пороги не двигались — их открыл вход, а не подгонка

**Три заявления аудита 2026-07-30 перемерены целиком** до правок

1399 размеченных регионов). Все три подтвердились, два — с уточнением методики:

- корреляция «политическая координата власти ↔ недовольство» = **−0,889 по
  странам** (число аудита воспроизвелось точно) и −0,742 по регионам: единица
  наблюдения у аудита — страна, и это меняет величину, а не вывод;
- порог восстания 0,65 брали **2 региона из 1399**;
- порог отделения читает недовольство группы-БОЛЬШИНСТВА, а не региона (аудит
  мерил региональное). По правильной величине: строжайший порог 0,82 не брал
  **ни один** регион при максимуме по миру 0,8190, `severe` (0,70) — ровно один;
- `regionWelfare` давала тождественный ноль у **536 регионов из 1399 (38,3 %)**:

**Решение — чинить вход, а не пороги.** Положение региона считается по
логарифмической шкале с паритетом посередине; отставание ДОБАВЛЯЕТ недовольство,
опережение УМНОЖАЕТ уже накопленное на долю меньше единицы. Ориентир достатка —
легальный владелец (`regionWelfareReference`), а не оккупант: агрегат оккупанта
этот регион не включает вовсе, поэтому старое деление сравнивало регион с
множеством, в которое он не входит.

**Симметричный вычет пробован первым и отвергнут замером.** У региона, который и
богат, и идеологически близок власти, сумма уходила ниже нуля, `clamp01` сажал
её на пол — и там умирала монотонность по дистанции: сдвиг состава к более
далёкой группе не менял недовольство вовсе (0,000000 → 0,000000, поймано
`campaignSmoke.test.ts`). Мёртвая зона лечилась сверху и заводилась снизу.
Умножение положительным множителем такой зоны не создаёт, и смысл честнее:
достаток смягчает имеющееся недовольство, а не выдумывает довольство из ничего.

**Итог на живых данных:** мёртвый экономический член 536 → 41 региона (2,9 %,

построению); порог восстания берут 17 регионов на старте и 18 за 120 месяцев вместо 2;

**Ни один порог не изменён:** недостижимость была свойством мёртвого входа, а
подгонка чисел под распределение сейчас посчитала бы эффект дважды — параллельно
правится нормировщик дистанции, который распределение расширит сам.

**Одномерность НЕ вылечена, и это измеренный вывод, а не отступление.**
Корреляция по регионам упала −0,742 → −0,693, по странам осталась −0,881:

регионам. Причина лежит в данных каталога — `desiredIdeology.political > 0` у

Кандидаты во второй вход проверены свипом и отвергнуты числами: легитимность

поднимает (−0,888 → −0,907); коррупция — переодетая та же ось (R = −0,77);
страновые `stability`/`governmentSupport` — константы; `region.stability`
статична и дублирует само недовольство. Лечение — в `groups.json`, не в формуле.

**Статус:** реализовано. Держат guard-тесты на живых данных

единственная историческая опора), для Австрии — восстановленный в 1945 году
красно-бело-красный, для Кореи — тхэгык без триграмм (в 1946 флаг ещё не
стандартизован, а восемь штриховых групп в блоке 88 px сливаются). Два
осознанных исключения: у Маньчжурии схема перевёрнута (поле советское, солнце
китайское — территория не делится на зоны, различать нечего), у Договорного
Омана нет ни оккупанта, ни единого флага, поэтому взята общая схема флагов
шейхств Залива.

**Почему кодом.** Сначала были составлены промты — сперва для растровой
генерации, затем для SVG в AI Studio. Пользователь указал на очевидное:
геометрия точная, её надо написать, а не выпрашивать. Проверка это
подтвердила — на живом прогоне модель дала поле не по спецификации, ряд звёзд,
вываливающийся за границу кантона, и радиус звезды в полтора раза больше
заказанного. Генерация остаётся за растровыми задачами
(`server/scripts/generateAsset.ts`): портреты, текстуры, иллюстрации.

**Найдено рендером:** французский кантон растворялся в поле — у австрийской
зоны его белая полоса продолжала белую полосу поля, а красная красную, и флаг
читался как «синяя полоса слева». Добавлена разделительная линия по краю
кантона, одна для всех: разнобой был бы заметнее самой проблемы.

**Проверено:** все двенадцать отрисованы и просмотрены в трёх размерах, включая
88 px вперемешку с настоящими флагами набора; 18 тестов зелёные, негативный
контроль — убранный файл ловится. Собственные ассеты не попадают в список
требующих атрибуции: обязательство не должно размываться тем, чего в нём нет.

## 2026-08-03 — Флаги 1946 скачаны и нормализованы: четыре дефекта, которых не видел ни один формальный признак

**Решение.** `scripts/map/fetch_flags.py` скачивает файлы по манифесту и кладёт
их в `client/public/flags/<КОД>.svg` (145 файлов, 8,4 МБ) вместе с
`index.json` — лицензия, автор, ссылка на Commons и ИСТИННАЯ пропорция каждого
флага. Имя по коду страны, а не по имени с Commons: интерфейсу нужен
предсказуемый путь `/flags/ITA.svg`.

**Нормализация — общий бокс, а не общая пропорция.** Каждый файл получает
внешний бокс 300×200, но полотнище внутрь ВПИСЫВАЕТСЯ, не растягиваясь и не
обрезаясь. Растянуть значило бы подделать флаг: советский и британский — 1:2 по
статуту. Обрезать нельзя из-за примерно двадцати пяти британских колониальных
энсинов, у которых бэдж стоит в центре правой половины: обрезка 1:2 → 3:2
срезает по 12,5% с краёв и разрушает ровно ту деталь, которой Кения отличается
от Нигерии. Истинная пропорция сохранена в `index.json` — вёрстка, которая
захочет выравнивать флаги по высоте (как на флагштоке), возьмёт её оттуда.

**Четыре дефекта, найденные проверкой, а не рассуждением** — все они давали
валидный файл правдоподобного веса:

1. **26 флагов из 145 не рендерились.** Отбросив корневой тег оригинала, скрипт
   оставлял в теле префиксы `sodipodi:`/`rdf:` без объявления — документ
   переставал быть валидным XML, браузер показывал пустоту. Нашёл рендер в
   браузере; ни один формальный признак этого не видел.
2. **Флаг Гондураса потерял цвет.** Заливка объявлена один раз на корне
   (`fill="#0d3b99"`) и наследуется фигурами — вместе с корнем ушла и она.
   Теперь переносится ВЕСЬ корень, кроме кадрирующих атрибутов.
3. **Флаг Коста-Рики схлопнулся в полоску.** `width="1e3"` — законная научная
   нотация, наивный парсер прочитал «1» и дал пропорцию 0,0017. Ловится теперь
   машиной: вычисленная пропорция сверяется с метаданными Commons, расхождение
   больше 1% — отказ.
4. **Форму задаёт кадр, а не `viewBox`.** У венгерского флага кадр 1200×600 при
   viewBox 2,05; у лаосского кадр 3:2 при квадратном viewBox. Вписывание
   считается по кадру, а внутри оригинал распоряжается своим
   `preserveAspectRatio` сам.

Плюс пятое, не про картинку: на Windows запись переводила `\n` в `\r\n`, и у 26
файлов с собственными `\r` цикл «записал → прочитал → сравнил» не сходился —
каждый прогон переписывал их заново и шумел в git. Записываем с `newline=""`;
повторный прогон теперь даёт ноль изменений.

**Безопасность.** SVG — исполняемый формат, а файлы приходят с сайта, который
редактирует кто угодно: каждый проверяется на script, обработчики событий,
`foreignObject` с телом и внешние ссылки. Пустая самозакрывающаяся заглушка
Illustrator (она есть у канадского Red Ensign) удаляется до проверки — исполнить
в ней нечего; `foreignObject` С ТЕЛОМ по-прежнему приводит к отказу. Обе
половины границы закреплены тестами.

**Проверено:** все 145 флагов загружены в браузере, ноль битых, у всех бокс
300×200; 14 тестов зелёные, негативный контроль показал падение на
восстановленном старом поведении (перенос атрибутов и парсер размеров).

**Известный дефект, оставлен сознательно:** `SDN` (Англо-Египетский Судан) —
кондоминиум, нарисованный двумя флагами рядом, пропорция 3,46; в общем боксе
даёт большие поля. Нужен свой ассет — записано в `docs/TODO.md`.

## 2026-08-02 — Правило A стало двусторонним: у аустерити появился обратный ход

**Решение.** ИИ-страна восстанавливает все пять дискреционных долей на
+5%/тик (`AUSTERITY_RESTORE`) до потолка — стартовой доли (= `spendingFloor`

обратный ход отменяет ровно урезание аустерити. Команда
`applyAusterityRecoveryRaise` (`commands/economy.ts`) — зеркало
`applyDeficitAusterityCut`, мутации долей сразу приводят суммы.

**Гистерезис двухосевой, обе ширины сняты замером, у осей разные роли.**

протекает (7 стран), 0,03 — ноль циклов даже при `--bias 0.3`; шаг
восстановления ≤ 0,05 × 0,85 дохода, и запас больше шага останавливает
восстановление до черты дефицита. (2) Потолок долга держит скорость расчистки
долговой ямы первых лет: с восстановлением уже при долге < 0,6 к 60-му месяцу
в долгу оставались 34% мира (тест `exportIncome.test.ts` падал), при 0,3 —

во всех вариантах.

**Что это дало на живых 120 месяцах** (`probeStabilityRule`, до → после):
education ниже стартовой доли — 64 → 0 стран (к 60-му месяцу 64 → 4);
military ниже стартовой — 81 → 30, и у всех 30 кризис ещё идёт (раньше среди
просевших было 16 стран с давно завершившимся кризисом, запертых навсегда);
«возврат Правила C заперт полом welfare» — 16 → 0. Полный цикл в стрессе:
дефицит → пол → возврат ровно к стартовым долям у всех 83 урезанных стран,
медиана 34 месяца после конца стресса.

**Проверено.** Фикстурные тесты `AiBehaviorTick.test.ts` (факт восстановления,

  channel» игнорируется, а JPEG прозрачности не несёт. В HUD иконки — inline SVG

  партии, — у них прототипа не существует.

**Проверка формы кадра — в скрипте.** Размеры читаются из заголовка JPEG без
зависимостей и сверяются с ожидаемым отношением вида (допуск 5%); расхождение

## 2026-08-02 — Морские зоны режутся у берега, а не в океане; непроходимость становится стоимостью

Разбор перенарезки шести океанских монолитов (81,4% воды, 295,3 млн км² из
362,8 по свойству `area_km2`). Замер провёл проектировщик, решения принял
пользователь; реализация НЕ начиналась.

**Правило разреза изменено по ходу разбора.** Исходная гипотеза «разрезать
океан на 2–3 куска» отвергнута в пользу формулировки пользователя: резать надо
**береговую полосу**, у которой нет своего краевого моря, а абиссаль оставлять
целой. Замер показал, почему: Северная Атлантика касается **112 прибрежных
регионов в 39 странах** — от Гренландии до Либерии и Бразилии — не потому, что
велика, а потому, что вдоль этих берегов ничего не названо. Тип зоны
(`open_ocean` / `shelf` / `enclosed`) перестал быть ярлыком и стал правилом
нарезки.

**Порог гранулярности — не более ~25 прибрежных регионов на зону.** Число взято
не с потолка: существующие названные моря столько и держат (Северное 23,
Японское 24, Балтика 18, Мексиканский залив 17). Архипелаги — законное
исключение (Карибское 73, Южно-Китайское 54). Ориентир состава: 101 − 6 + 6
абиссальных ядер + ~30–35 шельфовых ≈ **130–140 зон**.

**Крошечные зоны-проливы сохраняются.** `Strait of Gibraltar` (1 638 км²) и
`Singapore Strait` (2 919) существуют зонами в источнике IHO; растворять их в
соседях ради чистоты правила «пролив = ребро» не будем — в зоне можно стоять и
драться, в ребре нельзя. Узкое место остаётся атрибутом РЕБРА, а зона со
степенью 2 ведёт себя как ребро.

**Проверено и опровергнуто по ходу:** утверждение «узкие места не являются
зонами IHO» неверно для четырёх из пяти названных (Гибралтар, Мраморное море,
Каттегат/Скагеррак, Суэцкий залив — зоны; Ормуз и Баб-эль-Мандеб — прямые
рёбра). Антимеридиан текущий граф НЕ рвёт: рёбер, существующих только через
±180, ноль, компонента одна — каждый океан у даты это одна фича из двух частей.
Риск возникает при разрезе, поэтому особый случай в `build_neighbor_graph.py`
(его там нет) вносится ДО нарезки: сегодня он доказанно даёт 0 новых рёбер,
то есть проверяемый no-op. 143 изолированных острова из `design-partner-audit`
F64 уже вылечены: 174 региона без сухопутных соседей, морской сосед есть у всех
174 — это базовая линия приёмки.

**Непроходимость — отдельная задача, два уровня.** Данных о рельефе в проекте
нет вовсе, но плотность считается из своих: `population` в `regions.state.json`
для всех 1444 регионов и `area` в `regions.core.json`. Фильтр «площадь
> 250 тыс. км² и плотность < 1 чел/км²» даёт 25 регионов на 27,6 млн км²
(18,5% суши) и находит названное пользователем — Амазонию, Якутию,
Красноярский край, сахельский пояс. Но **одна плотность классификатором быть не
может**: в том же хвосте Гуам (0,067), Гуадалканал (0,727), Алеуты (0,480) —
места крупных кампаний. Площадь в фильтре отсекает острова, ложные
срабатывания уровня Невады и Ньюфаундленда остаются — список **кандидатов на
ручное подтверждение**, не ответ.

Формулировка пользователя «условно непроходимы» принята как модель: наши
регионы смешивают непроходимое ядро с проходимым коридором (в Якутской АССР на
3,07 млн км² лежат Лена и Якутск, в Красноярском крае — Транссиб, в Amazonas —
река как главная дорога). Бинарная стена на таком размере невозможна физически,
градиент стоимости возможен. Уровня два (`impassable` / `hard`), но
**`impassable` предсказуемо окажется почти пустым** — даже Гренландия при
0,0097 чел/км² несёт 21 000 человек по побережью.

**Статус.** Решения приняты, работа не начиналась. Слой
`out/seas_iho_coastline.geojson` в мир по-прежнему не внедрён, и до игры

## Милстоун 1 — хвосты контрактов ядра (независимое ревью 2026-07-27)

Ревью сессии «Контракты ядра» (read-only) нашло шесть дефектов/расхождений —
все закрыты той же сессией (детали `docs/decisions/2026-08.md`). Ниже — то,
что решено НЕ чинить сейчас.

- **Кап диагностической записи обходится ИМЕНАМИ ключей.** `MAX_PRIMITIVE_ID_LENGTH`
  ограничивает длину ЗНАЧЕНИЯ трёх известных идентификаторов, но `.strict()` в
  схеме глагола кладёт в причину отказа имя нераспознанного ключа целиком, а
  имена ключей в теле запроса не ограничены ничем. Оценка ревью: одиннадцать
  примитивов с пятитысячесимвольным ключом дают секцию отказов ~67 000 символов
  против бюджета `CONCEPT.md` §7 (~20k токенов). Предсуществующее, не регрессия
  Милстоуна 1. Лечение — кап на длину САМОЙ записи в `pushRejectionFact`.
- **Удаление записи словаря, все числовые поля которой нули, диф не видит.**
  `leavesEqual` считает отсутствие листа и нулевой лист одним и тем же (это
  осознанно — так палитра остаётся точной при создании записи памяти), но у
  СЛОВАРЕЙ то же правило делает удаление нулевой записи невидимым. Переход на
  сопоставление по id (2026-07-27) массивы вылечил, словарей не касается: у их
  записей идентичность — сам ключ, и «ключа не стало» отличимо от «значение
  ноль» только на уровне листа. Сегодня недостижимо ни одним глаголом.
- **«Память страны» выдаёт сырой заголовок независимо от подтверждённости.**
  `LLMService.getRecentTitlesLine` и `## Recent Events` берут `Event.title`
  дословно, включая `partial`, — в отличие от летописи. Это НАЗВАННАЯ граница
  решения 2026-07-27 (окно короткое и самоочищается, летопись копится всю
  партию), но записана она пока только в `PRIMITIVES.md` §3, без теста. Решать
  вместе со вторым вызовом модели «перепиши по фактам».
- **Интерфейс не читает признак дубля из квитанции.** `receipt.duplicate = true`
  клиент показывает как «режиссёр предложил невозможное» (повтор попадает в ту же
  ветку «ничего не применилось»), хотя это ретрай уже применённого ответа, а не
  отказ. Правка клиентская: отдельная ветка в панели цикла по `duplicate`.

## Хвосты сессии «Жизненный цикл государств» (Милстоун 1, 2026-07-27)

- **Осколок носит имя ГРУППЫ, а не государства.** `split_country` даёт новой
  стране `LocalizedText` этнической группы («Литовцы»), потому что имён
  гипотетических государств в состоянии нет вовсе. Игроку это читается как
  «страна Литовцы». Лечение — словарь «группа → имя государства» в данных
  сценария либо отдельное поле `EthnicGroupDefinition.statehoodNames`;
  и то и другое — наполнение данных, не механика.
- **Именные соединения и ядерный арсенал при расколе не делятся.**
  `military.units` и `nuclearWarheads` остаются у метрополии (либо у
  правопреемника): штучные объекты не являются величиной, делимой по населению.
  Запасы ресурсов (`stockpile`) копируются осколку целиком — то есть при расколе
  РАСТУТ в сумме по миру. Сегодня безобидно (запасы малы и быстро
  пересчитываются торговым тиком), но это нарушение того же принципа, что держат
  казна и живая сила. Решать вместе с `merge_countries`, где встанет обратная
  задача — сложение.
- **Столица и объекты карты — отдельный реестр ссылок.** `countryRefs.ts`
  объявляет ссылки на СТРАНУ; ссылки на РЕГИОН (`capitalRegionId`,
  `MapFeature.regionId`, `groupImpactMemory.regionId`, `Modifier.target` вида
  region) живут по местам и проверяются `invariants.ts` поимённо. Пока регионы
  не создаются и не удаляются, этого достаточно; глагол, меняющий состав
  регионов, потребует второго такого же обхода.
- **Составной ключ бюджета хода держится соглашением о формате строки.**
  `primitiveTurnBudget.targetUses` ключуется `"<verb> -> country <id>"`, и
  `countryRefs.ts` разбирает его сегментами. Это единственное место реестра, где
  связь не выражена типом: изменение формата ключа в `targetUseKey` молча
  сломает перенос. Лечение — структурированный ключ в `PrimitiveTurnBudget`
  (формат сейва, поэтому вместе со следующим `SAVE_VERSION`).
- **Правило «раскол не заявляет числовых ячеек» — исключение в сторожевом
  тесте.** Сторож «палитра и сверка описывают одни и те же каналы» получил
  исключение, ключуемое ПАРОЙ (глагол, путь), и `split_country` исключён
  целиком. Это осознанно: его правдивость держат сходимость сумм и ноль висячих
  ссылок — механизмы сильнее поячеечной сверки. Но каждый следующий структурный
  глагол придётся так же решать вручную; если их станет много, правило стоит
  выразить свойством класса (структурные не заявляют ячеек), а не списком.
- **След «здесь сменился флаг» не пишется в историю места ни одним глаголом.**
  `peace` с аннексией по договору, `annex` и `merge_countries` двигают границы, но
  записи в `regions[*].placeHistory` не оставляют: строка отклика у всех троих
  называет страны, а не место, и записи потребовалась бы своя. Решать одной
  работой на все три — иначе у одинаковых случаев окажутся разные ответы.
- **`create_country` не требует смежности отделяемых регионов.** Уходят все
  регионы владельца с той же группой-большинством, независимо от географии — то
  же правило, что у раскола. Связность территории в состоянии не выражена ничем,
  кроме списка соседей; требовать её значило бы изобрести правило, которого у
  раскола нет. Решать вместе с механикой, которая первой прочитает связность.
- **`puppet` не снимается.** Обратного глагола («освободить клиента», разрыв
  вассалитета) в алфавите нет: спецификация §2 его не заявляет, а выводить
  отдельный глагол под снятие одной связи — расширение алфавита числом, которое
  §1 прямо не рекомендует. Кандидат — параметр направления у существующего
  глагола, вместе с механикой деколонизации.
- **Порог `VASSALAGE_MIN_HELD_SHARE` (0.5) — решение, а не вывод из данных.**
  Оккупированных регионов в поставляемом сценарии ноль из 1399, поэтому
  распределения, из которого его можно было бы вывести, не существует.
  Перепроверить на первой партии с настоящей войной.

- **Клиентский минимум состояния кампании.** `CampaignStatePanel` — простая
  разметка без визуального дизайна: выбор осколка списком кнопок и текст
  поражения. Дизайн ведёт пользователь отдельно.

## Хвосты сессии «Дипломатический блок алфавита» (Милстоун 1, 2026-07-27)

Реализованы `diplomacy`/`sanction`/`war`/`peace`, переведённые типы удалены из
старого канала, у `influence` снято числовое поле. Ниже — то, что осталось.

- **Три вида санкций из четырёх — репутационные.** Торговлю режет только
  `trade_embargo` (`TradeTick.getEmbargoPenalty`). `economic_sanctions`,
  `military_sanctions`, `diplomatic_sanctions` меняют отношения и лежат в
  состоянии, но их не читает ни одна подсистема. Примитив это НЕ скрывает
  (`AppliedSanction.cutsTrade`), поэтому нарратив не врёт, — но механики у них
  нет. Чем они должны отличаться, решается в `TRADE.md` и военной модели, а не
  в алфавите.
- **Повод войны (casus belli) не проверяется.** Претензий, спорных территорий
  и обид в состоянии не существует; отношения — единственный кандидат — в
  сценарии 1946 нулевые у всех 157 стран, поэтому порог по ним был бы либо
  пустым, либо запирал бы войну во всём мире. Закрывается наполнением стартовой
  дипломатии 1946 (тот же пункт, что держит фильтр союзника в `border_dispute`),
  а не правкой движка.
- **Мир не оставляет записи в истории места.** Аннексия по договору меняет
  владельца региона, и «здесь сменился флаг по мирному договору» истории места
  было бы к лицу, но записи потребовалась бы своя строка отклика (заголовок
  `peace` называет страны, а не регион). Отложено осознанно.
- **Отчёт `peace` строится из дифа состояния**, поэтому сверка результата на
  ячейках `legitimacy:`/`treasury:`/`relation:` этого глагола становится
  тождеством и лжи поймать не может. Граница там — палитра. Альтернатива —
  перечислять эффекты мира по памяти — хуже: это второе мнение о том, что
  сделал `WarService`, и оно разойдётся с ним при первой правке условий мира.
- **Общий слот пары запрещает два мягких дипломатических акта по одной паре за
  месяц.** Это защита от обхода коридора сменой глагола, и цена у неё есть:
  «объявить санкции и одновременно предложить переговоры» в один месяц по одной
  паре невозможно. Смягчается калибровкой
  (`MAX_PRIMITIVES_PER_TARGET_PER_TURN`), а не отменой слота.
- **Потолок накопления по величине покрывает только память воздействий.**
  `IMPACT_FIELD_TURN_CEILING` считает дельты троек (регион, группа, поле);
  у каналов `relation:`/`legitimacy:`/`treasury:` такого потолка нет. Сегодня
  их держит слот пары (спилловера в чужие ячейки у домена нет по построению),
  но глагол, который начнёт писать в отношения ТРЕТЬИХ стран, потребует
  обобщения потолка на ячейки сверки — с изменением формата ключей
  `primitiveTurnBudget.impactAccrued` и, следовательно, `SAVE_VERSION`.
- **Сторож «промт не упоминает `annex`/`puppet`» переписан 2026-07-29** —
  проверка подстроки была не просто хрупкой, а неверной (оба глагола законно
  вернулись в алфавит); история причины — `docs/decisions/2026-08.md`.

## Хвосты сессии «Мягкие глаголы алфавита» (Милстоун 1, 2026-07-29)

Реализованы `send_aid`, `capital_flight`, `condemn`, `support_proxy`; `influence`
удалён из старого канала. Ниже — то, что осталось.

- **`shift_mood` — глагол без поля состояния; нужен ПРОДУКТОВЫЙ ответ, а не
  реализация.** Спецификация §2 описывает его как «толчок настроения группы»,
  но поля «настроение» в состоянии нет вовсе. Есть четыре следа воздействий
  (`GroupImpactMemory`: `suppression`, `alienation`, `concession`,
  `emboldenment`), и каждый уже принадлежит своему глаголу: подавление —
  `repress`, отчуждение — `repress`, уступки — `grant_autonomy`, решимость —
  `incite_unrest`/`spawn_incident`/`grant_autonomy`. Разбор трёх вариантов:
  - **выразить через существующие следы** — значит сделать `shift_mood`
    синонимом одного из четырёх глаголов с другим именем. Отвергнуто по тому
    же основанию, что и `shift_ideology`: два способа сделать одно и то же
    хуже, чем один;
  - **завести пятое поле** (`mood`/`morale`) — единственный честный путь, но он
    требует ответа на вопрос, которого спецификация не даёт: чем настроение
    отличается от НЕДОВОЛЬСТВА, которое движок и так выводит из дистанции,
    благосостояния и памяти воздействий (`CONCEPT.md` §4.1). Без этого ответа
    поле окажется вторым мнением о том же самом, а недовольство — центральная
    величина среза;
  - **признать глагол лишним в этой форме** — вероятный исход, и он ничего не
    отнимает: «настроение группы» уже двигают четыре существующих канала.

  Решение отложено до наполнения Милстоуна 2, где появится второй потребитель
  «настроения» (кризисная выборка). Заводить поле состояния раньше него значило
  бы калибровать вслепую.
- **«Влияние без денег» стало недоступно.** `send_aid` покрывает влияние,
  КУПЛЕННОЕ помощью; пропаганда, ухаживание и дипломатическое давление без
  бюджета не выражаются ничем. Это цена удаления `influence` из старого канала,
  названная сознательно: плоский шаг мимо коридора хуже, чем временно
  отсутствующая способность. Возвращается отдельным глаголом алфавита, когда
  для него найдётся предпосылка, отличная от «есть деньги».
- **`shift_ideology` отвергнут, а не отложен.** Честного отличия от
  `enact_reform` не нашлось (`docs/PRIMITIVES.md` §2). Если он понадобится, у
  него должна появиться СВОЯ природа — например дрейф координат под давлением
  общества, — но это механика тика, а не примитива с источником-государством.
- **`send_aid` не усиливает получателя военно.** Спецификация §2 говорит
  «эконом/воен. усиление»; реализовано экономическое (деньги в казну).
  Военное отдано `support_proxy`, у которого для этого есть предпосылка
  (идущая война). Помощь оружием в мирное время не выражается — если
  понадобится, это параметр вида помощи, а не новый глагол.
- **Три вида санкций из четырёх по-прежнему репутационные** (пункт прошлой
  сессии, не закрыт). Теперь рядом с ними стоит `condemn`, который
  репутационным является ПО ЗАМЫСЛУ и честно бьёт по легитимности, — то есть
  разрыв между «объявили режим» и «ничего не произошло» стал заметнее.
- **Ключи капа `condemn`/`capital_flight` запрещают двум государствам
  действовать по одной цели в один месяц.** Это защита от сложения коридоров, и
  цена у неё есть: «весь мир осудил X» в один месяц невыразимо. Смягчается
  калибровкой `MAX_PRIMITIVES_PER_TARGET_PER_TURN` либо обобщением потолка
  накопления на ячейки сверки (последнее меняет `SAVE_VERSION`).
- **Паритет клиентских словарей не проверяется тестом.** Новые ключи
  `primitiveOutcome`/`primitiveRejection` заведены в обеих локалях вручную;
  автоматической проверки «ru и en описывают один набор ключей» и «сервер не
  эмитит ключа, которого нет в словаре» нет ни одной. Отдельная работа — она
  требует либо чтения клиентских JSON из серверного теста, либо экспорта
  списка ключей в `shared/`.

## 2026-08-09 — Прямой путь на Gemini не работал вовсе: схема несла `exclusiveMinimum`

**Дефект.** Каждый запрос к прямому Gemini возвращал 400 «Unknown name "exclusiveMinimum"». Zod 4 выражает `regionId: z.number().int().positive()` строгой границей, а OpenAPI-подобный диалект провайдера такого ключа не знает — шесть вхождений в отправляемой схеме, ни одного зелёного вызова. Не замечено потому, что провайдер по умолчанию локальный (шлюз), и в Google игра не ходит: путь оставался сломанным, пока его не позвали.

**Правка.** `enrichForGemini` переводит строгую границу ЦЕЛОГО во включающую (`> 0` → `minimum: 1`, точный эквивалент); у дробного точного эквивалента нет, там граница снимается — как уже снимается `additionalProperties`, потому что схема направляет генерацию, а настоящую проверку ответа делает Zod. Включающие `minimum`/`maximum`/`minLength`/`maxLength`/`maxItems` диалект принимает: тот же 400 перечислил ВСЕ неизвестные поля и ни одного из них не назвал.

**Проверка сменила форму, и это важнее самой правки.** Раньше тест перечислял ЗАПРЕЩЁННЫЕ ключи (`const`, `additionalProperties`) — `exclusiveMinimum` прошёл ровно в эту щель. Теперь проверяется обратное: в отправляемой схеме нет ни одного ключа ВНЕ списка разрешённых. Точечная проверка ловит известный дефект, эта — класс. Полнота списка ограничена честно: пять ключей подтверждены живым ответом, остальные взяты из документации `Schema` и живьём не проверялись, потому что наша схема их не производит.

**Побочно измерено:** прямые `gemini-3.5-flash` и `gemini-3.6-flash` нашу схему не принимают независимо от этой правки — union примитивов валится уже на трёх ветках из четырнадцати. Умолчание остаётся `gemini-3.1-flash-lite`. Подробности и числа — `LLM_RULES.md` §«Префиксный кэш».

**Граница ветки.** Здесь только то, что не зависит от порядка секций промта: телеметрия кэша, два замерных скрипта и починка диалекта. Перестановка блока инструкций живёт отдельной веткой и ждёт своего замера качества; `LLMService.ts` этой веткой не тронут.

## 2026-08-09 — ШАПКА вернулась на экран: размещающие свойства не живут в инлайновом стиле

## 2026-08-08 — Доминирование портит отношения к доминирующему: мир 1946 ожил

**Решение делегировано пользователем исполнителю** («сам решай, взвесь за и
против»). Выбрано: вражда между ИИ-странами рождается из ПОДЧИНЕНИЯ, а не из
конкуренции за клиентов. Довод — один член формулы чинит обе измеренные дыры
сразу: даёт соперничеству второй, динамический источник И оживляет ветку
балансировки Правила B, у которой до этого не было кандидатов.

**Что сделано.** Цель дрейфа отношений перестала быть симметричной: у неё
появился направленный член `DOMINATION_RESENTMENT` — обида подчинённой стороны.
Это первое несимметричное слагаемое модели, и это архитектурное решение:
сюзерен и вассал переживают одну и ту же связь по-разному. Вход — та же
величина, что даёт приязнь патрону (`subordinationTo`, зеркало
`dependencyStrength` в одну сторону), поэтому обе стороны связи растут из одного
числа. Гарантия в подчинение не входит: защита — не власть.

**Константа задана коридором из двух проверяемых границ, а не выбрана:** снизу —
полностью подчинённый при идеологическом безразличии обязан уйти в соперники
(> 32,5), сверху — полностью подчинённый единомышленник обязан остаться лояльным
(< 52,5). 40 = `DEPENDENCY_AFFINITY + IDEOLOGY_AFFINITY_SPAN/4`. Первая версия
(`= DEPENDENCY_AFFINITY`, «подчинение ровно гасит приязнь связи») выглядела
инвариантом и была мертва: замер показал −0,54…−0,15 при пороге −2,5 и НОЛЬ
новых соперничеств.

**Результат на 240 месяцах живого 1946 без LLM** (приёмка перевыполнена):

| | было | стало | приёмка |
|---|---|---|---|
| стран без единого отношения за партию | 143 из 157 | **65** | < 100 |
| пар-соперников на 240-м месяце | 13 | **86** | ≥ 40 |
| пар-союзов | 5 | **80** | ≥ 15 |
| союзов на 1-м месяце | 0 | **0** | ≤ 3 |
| балансирующих из угрожаемых (Правило B) | 0 из 11 | **7 из 11** | — |

**Цена, вскрытая замером и оплаченная в той же правке.** Ожившая балансировка
обнажила третий односторонний храповик проекта: военный ответ Правила B не имел
обратного хода. Страны, которым больше не угрожают ИЛИ которым уже нечем
платить, держали военные расходы на потолке 40% дохода до конца партии — 6 стран
садились в вечный долг, 2 из них свыше 60% ВВП, тогда как без обиды таких не было
ни одной. Добавлено: (1) вооружается только платёжеспособный — порог долга взят у
Правила A, чтобы два правила реагировали на одно событие согласованно;
(2) разоружение к стартовой доле, шаг зеркален подъёму. После правки на 240-м
месяце в долгу 4 страны, свыше 60% ВВП — ноль.

**Статус.** Реализовано и проверено: server 1435 passed + 1 skipped (94 файла),
typecheck чист. Негативный контроль двойной: при `DOMINATION_RESENTMENT = 0`
падают 4 из 6 новых тестов механизма и только они; при снятом обратном ходе
Правила B — 2 из 3 его тестов. `SAVE_VERSION` не менялся.

**Два чужих теста переписаны, оба со свойства на свойство, а не под результат.**
`rivalryReversibility` судил о застревании по симметричному тяготению — теперь по
низшей из направленных целей И по тому, движется ли пара (равновесие меняется по
ходу партии, и пара, чья цель стала невраждебной поздно, физически не успевает
выйти). `exportIncome` проверял снимок «< 10% должников на 60-м месяце» — теперь
монотонность: доля должников обязана убывать от года к году, тяжёлые долги —
исчезнуть к десятому. Фикстура `unstableAI` приведена к инварианту игры
(`spendingFloor` = половина стартовой доли): она утверждала, что страна
стартовала выше собственной стартовой доли.

## 2026-08-08 — Морские зоны внедрены в мастер: 16 секторов → 85 зон, вода перераспределена, а не подменена

**Почему нельзя было просто подставить зоны.** Замер до правки: зоны построены
против водного слоя прототипа и с мастером не совпадают — вылезают за союз

крупнейший кусок 28 408 км² в Хальмахере) и не покрывают внутри него 16 138 км².
Наивная подстановка сдвинула бы воду на +16 435 км².

**Конструкция.** Заменяемая вода `U` (союз шестнадцати секторов)
ПЕРЕРАСПРЕДЕЛЯЕТСЯ: зоны обрезаются по `U`, взаимные наложения снимаются,
затем границы нодируются и `polygonize` даёт мозаику, чьи рёбра общие по
построению; ячейка без хозяина уходит соседу с самой длинной общей границей
(gap-first). Берег при этом не трогался вовсе — он взят из самого мастера.

**Почему допуск площади относительный, а не ±1 км².** Абсолютный допуск на этой
операции недостижим, и это свойство геодезии, а не программы: нодирование
вставляет в границу новые вершины, а `Geod` считает площадь по геодезическим
между СОСЕДНИМИ вершинами — вставленная точка лежит на планарной хорде, а не на
геодезической. Тот же самый регион с другим набором вершин даёт другую площадь.
Что регион ТОТ ЖЕ, доказано точно и отдельно: `area(U − зоны) = 0` и
`area(зоны − U) = 0`, наложений 0. Порядок величины у самого проекта:

## 2026-08-07 — Новый экран подключён к партии: один экран, два источника

местах. Это не гипотеза: на переносе ЛЕНТЫ и ПОЛОСЫ расхождение стоило целого
захода. Теперь разойтись они не могут физически.

рисуется. Панель, заполненная правдоподобной выдумкой, обесценивает соседнюю с
настоящим числом, а отличить их игрок не может. Поэтому в игре сейчас пусты
слоты техники, проекты, красные линии и советник.

**Два ранга разведены.** Место по ВВП (таблицы, досье) и место в мировом
рейтинге силы (ШАПКА) — разные величины; в одной колонке они давали два
четвёртых места подряд.

**Ход — весь цикл за одно нажатие:** намерение → ответ режиссёра → тик. Сервер

## 2026-08-07 — Кантон: берётся из настоящего флага державы, размер считается по правилу

**Решение.** Кантоны нарисованных флагов больше не рисуются вручную: полотнище
флага-донора (`client/public/flags/SUN.svg` и т.д.) вкладывается в прямоугольник
кантона как есть. Серп с молотом, Union Jack и звёздное поле приходят из файлов
набора — проверенных и нормализованных. Побочная выгода: правка флага державы
сама доезжает до всех зон, где он стоит кантоном.

**Размер кантона считается, а не задан константой.** Правило выведено из
замеров по набору (canvas, доля от полотнища) и официальных спецификаций:

| флаг | пропорция | кантон | доля площади |
|---|---|---|---|
| Canadian Red Ensign | 1:2 | 0,500 × 0,500 | 25,0% |
| флаг США | 1:1,9 | 0,400 × 0,538 | 21,5% (7 полос из 13) |
| флаг Либерии | 10:19 | — | 5 полос из 11 |
| флаг Малайзии | 1:2 | — | 8 полос из 14 |
| британские энсины | 1:2 | «одна четверть поля» по спецификации | 25% |

Отсюда три правила: **(1)** кантон сохраняет пропорцию своего донора, а не
подгоняется под квадрат — у Red Ensign кантон 0,5×0,5 от флага 1:2 это H в
ширину и H/2 в высоту, ровно 2:1, пропорция самого Union Jack; **(2)** площадь
не больше четверти флага; **(3)** на полосатом поле нижний край кантона ложится
на границу полосы, а сколько полос он накроет — определяет правило (2): берётся
самая нижняя граница, при которой кантон ещё укладывается в четверть.

На наших полях при боксе 300×200 и доноре 1:2 это даёт: Германия (5 полос) —
кантон 160×80, 21,3%, **две полосы**; Австрия (3 полосы) — 133×67, 14,8%,
**одна полоса**; Корея и Маньчжурия (сплошное поле) — 173×87, ровно 25%.

**Разделительная рамка кантона убрана** по решению пользователя. Цена известна и
названа: у французского кантона на австрийском поле красная треть сливается с
красной полосой поля, у советского кантона на красном поле Маньчжурии граница
видна только по эмблеме. Вексиллологический способ решить это, если понадобится,
— не рамка интерфейса, а фимбриация, тонкая светлая кайма как элемент самого
флага.

**Ловушка, которую стоит помнить:** первый просмотр показал в советском кантоне
одну крупную звезду без серпа и молота — это был кеш браузера, отдававший
предыдущую версию файла. Замер с обходом кеша: золота в кантоне 841 пиксель
против 3093 у полного флага, отношение 0,27 при квадрате отношения размеров
0,28. Проверять картинки в браузере нужно с меткой версии в URL, иначе видишь
вчерашнюю работу.

он же документирует метод. Числа: Далянь 2116,6 → 3540,8 км², Ляонин
57 408,2 → 55 984,0 (перенос 1424,2 в 18 кусках, суша не менялась); суша мира
+70,9 км², вода −70,9. Состав и число регионов не тронуты, каскада `region_id`
нет.

**Оценка рва в 217 км² была неверной, и это меняло смысл правки.** 217 —
площадь всего кольца вокруг города, из них ~130 — открытая Атлантика. Отдать её
штату значило дать границу город↔штат 1,90069° при границе город↔море **ровно
ноль**: портовая столица Бразилии стала бы сухопутной. Возвращено 71,0 км²
собственно рва: город↔штат 0,62083°, город↔море 1,27986°, сумма сходится с
периметром города.

**Признак «что здесь ров» — не расстояние, а след буфера:** в сегменте рва
граница штата равноудалена от города ровно на 0,01° (среднее 0,01000,
ст. откл. 0,00003), потому что она и есть дуга `buffer(0.01)`. У настоящего
берега расстояние гуляет.

**Урок метода, стоивший четырёх забракованных подходов: площади сходятся
раньше, чем сходится топология.** Прямолинейное `Ляонин ∩ эталон` дало
идеальные 3540,8/55 984,0 — и при этом уронило `coverage_is_valid` мастера
(0,10722428° несовпадающих рёбер с Жёлтым морем), потому что подрезало
островам БЕРЕГОВУЮ линию по чужой оцифровке. Правила, которые из этого следуют:
часть, лежащая внутри эталона целиком, переносится verbatim и не режется; резать
можно только внутри суши; разрез обязан кончаться в СУЩЕСТВУЮЩЕЙ вершине
соседа, иначе у соседа появляется вершина, которой у него нет. Забракованы
замером: пересечение с буфером соседа (режет вдоль границы, 7 осколков моря),
`set_precision` (рвёт общие рёбра сильнее), морфологическое замыкание суши
(перестраивает границу буфером и заливает устья настоящих бухт).

Классификация намеренно консервативна: из 0,66572° дуг возвращено 0,62083°,
ячейка 5,8 км² в бухте Гуанабара оставлена водой — рендер подтверждает, что
это акватория вокруг острова. Не дочинить участок рва дешевле, чем отдать штату
настоящую воду.

Корень в `build_brazil_1946.py` (`buffer(0.01)` убран) исправлен, но **прогоном
не проверен**: `sources/geoBoundaries-BRA-ADM2.geojson` отсутствует с
2026-08-02.

## 2026-08-08 — Правка геометрии обязана тянуть пересчёт экономики; приёмка этого не проверила

Обнаружено при доводке Филиппин: `regions.state.json` в `main` расходился с
геометрией. Задача `map-dalian-rio` вернула Даляню 1 424,2 км² и отдала Рио
70,9 км² суши, но `fill_region_economy_1946.py` после этого не запускался, а
экономика считается ОТ ПЛОЩАДИ.

Масштаб расхождения по четырём затронутым регионам:

| регион | площадь | население было → стало |
|---|---|---|
| Kwantung (Далянь) | 3 541 км² | 9 722 140 → **1 102 426** |
| Liaoning | 55 984 км² | 2 461 373 → 2 430 335 |
| Rio de Janeiro (город) | 1 121 км² | 502 915 → 222 601 |
| Rio de Janeiro State | 42 818 км² | 1 523 509 → 1 533 988 |

Всего пересчёт тронул 70 регионов (TWN 33, BRA 28, QMS 9); суммарное население
мира изменилось на +2 человека, то есть это перераспределение, а не приток.

**Пересчёт детерминирован и воспроизводим:** прогон
`fill_region_economy_1946.py` на версии из `main` дал результат, побайтно
совпавший с уже полученным. Значит устаревшей была именно версия в `main`.

**Почему не поймали.** Приёмка проверяла геометрию (площади, касания,
покрытие) и прогоняла `validate_region_economy_1946.py` — но тот проверяет
инварианты слоя, а не согласованность с площадями. Ни один гейт не связывает
«площадь региона изменилась» с «экономику надо пересчитать».

**Следствие для задачи `geometry-snapshot-gate`:** к классам `AREA_MOVED`,
`REGION_COUNT_CHANGED` и `PAIR_DETACHED` добавляется `ECONOMY_STALE` — площадь
региона отличается от той, при которой считалась его экономика. Дешевле всего
хранить в снимке площадь на момент пересчёта.

## 2026-08-07 — Источники карты вынесены в общее хранилище; на GitHub — ссылки и благодарности

Решение пользователя: все внешние входы пайплайна лежат в одном месте, вне
репозитория, переносятся между рабочими деревьями локально и в git не уходят.
На GitHub вместо данных — реестр со ссылками и благодарностями.

**Механизм не изобретался — он в проекте уже был.** `build/paths.py` с самого
начала умел переопределяться средой, а `scripts/worktree-new.ps1` подключает
`node_modules` junction'ами. Оба приёма соединены: хранилище одно на машину,
путь в новой переменной `PAXMAP_SOURCES_STORE`, в каждом дереве —
junction `scripts/map/sources/`, который теперь создаёт `worktree-new.ps1`.
Каталог уже был в `.gitignore`, поэтому junction гиту не виден.

**`game_map.json` (36,9 МБ) переехал** из `client/src/assets/` в хранилище.
Клиент его не импортировал ни разу — файл читают 12 скриптов пайплайна, и все
через `paths.game_map()`. Старое место закрыто правилом `.gitignore`, чтобы
файл не вернулся по недосмотру.

Порядок разрешения путей — от частного к общему, чтобы не сломать существующие
ветки: точечная переменная (`PAXMAP_GAME_MAP`, `PAXMAP_SOURCES`) → хранилище
или junction → путь внутри репозитория. Скриптам достаточно junction;
переменная нужна только чтобы его создать.

**Честная цена.** Из истории git файл не исчезает — там он остаётся во всех
прошлых коммитах, и клон меньше не станет. Выигрыш в том, что репозиторий
дальше не растёт, а не в том, что он похудел. Вычистить историю можно только
переписыванием — не делаем.

Проверено прогоном: аудит геометрии зелёный, `build_ph_regions_1946.py` и
`build_region_edits_islands.py` находят `game_map` через junction без единой
переменной среды, валидатор экономики чист, public eval 161/0.

Реестр «что положить в хранилище, откуда взять, под какой лицензией» и раздел
благодарностей — `docs/provenance/MAP_GEOMETRY_PROVENANCE.md`. Там же записано,
что 8 из 11 источников отсутствуют и потому `--rebuild-master` невозможен;
мастер-карта под git и остаётся единственным согласованным источником
геометрии.

## 2026-08-08 — Пересборка 27.07 снесла всю курацию Китая от 23.07; эталон при этом цел

Атрибуция регресса Даляня на `a9530ea` («топологическая пересборка») была
**ошибочной и снята**: тот коммит изменил 18 регионов на 110,8 км² суммарно, и
ни Даляня, ни Циндао среди них нет. Виновник — `628a3bd` (27.07, «restore
Panama Canal Zone, fix Kiel Canal Zone stray fragment»).

**Метод, которым это выяснилось не сразу.** Первый заход «бисектил» по выводу
`git log` и дал бессмысленный ответ: `git log` смешивает ветки по дате, а
`a9c7d11` и `628a3bd` не предки друг друга. Ходить только по
`git rev-list HEAD -- <файл>`. Записано, потому что ошибка воспроизводимая.

По прямой линии предков HEAD одно событие откатило шесть регионов:

| | 23–24.07 (`f7455b2`…`f59b754`) | с `628a3bd` по HEAD |
|---|---|---|
| Циндао `ASI-0044` | 955,6 км² / 1 часть | 1 071,1 / 2 |
| Шаньдун `ASI-0011` | 154 934,2 / 3 | 154 818,5 / 10 |
| Nenjiang `ASI-0033` | 62 715 | 81 325 |
| Heilongjiang `ASI-0034` | 234 101 | 224 462 |
| Songjiang `ASI-0031` | 80 274 | 76 035 |
| Jilin `ASI-0030` | 105 508 | 101 273 |

Далянь пострадал тем же событием и уже починен (2026-08-07). Обе группы —
записанные решения пользователя от 23.07 (`docs/decisions/2026-07.md`):
Циндао 1071,1 − 138,5 + 22,95 = 955,6; Nenjiang 62 714,9 с раздачей рукава
+9639/+4238/+4234. Сумма пяти маньчжурских дельт ровно нулевая.

**Корневая причина — НЕ «правка вне пайплайна».** Эталон
`out/china_1946_historical.json` отслеживается git и **цел**: там все
курируемые числа. Расходится с ним мастер. То есть пересборка мира собрала
Китай мимо живого эталона и молча вернула докурируемое состояние, а все 12

соседями им невидим.

Замерено: лишний кусок Циндао (138,48 км²) целиком лежит в эталонном Шаньдуне,
четыре косы Шаньдуна (19,41 / 1,82 / 1,67 / 0,05) — целиком в эталонном
Циндао. Симуляция даёт эталон точно: 955,57 / 1 часть, перекрытие
0,000000000 км², сумма пары сохранена. Резать нельзя: на Даляне прямолинейное
`сосед ∩ эталон` подрезало островам берег по чужой оцифровке и уронило
`coverage_is_valid`, оставаясь невидимым по площадям.

Вторая половина задачи — шаг-сверка мастера с эталоном в `STANDARD_STEPS` до
`import_to_game.py`, падающий на расхождении вне обоснованного allowlist.
Негативный контроль готов историей: на `628a3bd` он обязан упасть.
