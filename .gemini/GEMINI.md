## Домен ответственности

Gemini отвечает за **`client/`** — UI, карта, компоненты, визуал.

| Область | Владелец |
|---|---|
| `client/` — UI, карта, компоненты | **Gemini** |
| `server/` — симуляция, сервисы, маршруты | Claude |
| `shared/types/` — общие типы | **только через `main`, не параллельно** |
| `docs/`, `scripts/` | любой, не одновременно |

Границы — дефолт, не жёсткий закон. Менять через запись в `docs/DECISIONS.md`.

Подробности о координации моделей — раздел «Координация моделей» в `AGENTS.md`.

1. `git checkout main && git pull` — актуальный `main`
2. `git log --oneline -10` — что сделала другая модель

## Команды разработки

### Клиент

```bash
cd client
npm run dev          # Vite dev server (порт 5173 по умолчанию)
npm run build        # tsc -b && vite build (typecheck + сборка)
npm run test         # vitest run (все тесты)
npm run lint         # eslint
```

### Сервер (только для проверки — домен Claude)

```bash
cd server
npm run dev          # tsx watch src/index.ts (порт 3001)
npm run test         # vitest run
```

### Typecheck обоих пакетов

```bash
cd client && npx tsc -b --noEmit && cd ../server && npx tsc --noEmit
```

### Перед коммитом (обязательно)

1. Typecheck: `cd client && npx tsc -b --noEmit`
2. Тесты: `cd client && npm run test`
3. Lint: `cd client && npm run lint`
4. Если затронут сервер: `cd server && npx tsc --noEmit && npm run test`

Не коммитить с красными тестами или ошибками типизации.

## Архитектура клиента

```
client/src/
├── App.tsx              # Главный компонент, маршрутизация
├── App.css              # Основные стили (30KB — весь дизайн)
├── index.css            # Базовые стили и ресеты
├── main.tsx             # Точка входа React
├── api/                 # API-клиент (единый, fetch-based)
├── assets/              # Статические ассеты (game_map.json и др.)
├── components/          # UI-компоненты
│   └── Window.tsx       # Базовый оконный компонент (drag/resize)
├── hooks/               # React-хуки
│   └── useWindows.ts    # Управление перетаскиваемыми окнами
├── map/                 # Модули карты
│   └── engine/          # GeometryEngine, TopologyBuilder, label pipeline
└── types/               # Клиентские типы
```

### Оконная система

Все информационные панели — **перетаскиваемые окна** (`Window.tsx` + `useWindows.ts`), не постоянные колонки. Карта всегда занимает весь `game-content`, окна открываются по клику и закрываются явно. Обоснование — `docs/DECISIONS.md` (раздел «Редизайн интерфейса»).

### Карта

- `MapView.tsx` — главный компонент карты, слои MapLibre
- `client/src/map/engine/` — GeometryEngine, TopologyBuilder, buildCountryLabels
- Источники данных: `world_1946.geojson` (клиентский), `regions.json`/`countries.json` (серверные, сценарий 1946)
- Движок подписей стран: `docs/GEMINI_MAP_ENGINE.md` (MAS Pipeline)

## Инструменты

### MCP-серверы (настроены в `.mcp.json`)

| Сервер | Назначение |
|---|---|
| **Repowise** | Кодовая база: индекс, контекст, символы, здоровье, мёртвый код |
| **Context7** | Документация внешних библиотек (React, Vite, MapLibre, Vitest) |

**Не добавлять** второй инструмент для той же задачи — дублирование тратит контекст.

### Repowise — протокол использования

Дефолт — **самый дешёвый достаточный вызов**:
1. `get_context` skeleton (~37% полного Read) → для понимания файла
2. `get_symbol` → для тел конкретных функций/классов
3. `path:a-b` range reads → для участков между символами
4. Полный Read файла — только если индекс не может обслужить

**Trust protocol:**
- `verified: true` → **не перечитывать** те же строки через Read
- `confidence: "high"` / `grounding: "extracted"` → цитировать напрямую
- Перечитывать только при: `bounds: "approximate"`, `_meta.stale_warning`, `search_method: "bm25"`, `confidence: "low"`

### Context7 — когда использовать

Для актуальной документации **внешних** библиотек: React 19, MapLibre GL JS, Vite 8, Vitest 4, Turf.js, Zustand. **Не использовать** для документации проекта Geopolis (для этого — Repowise и `/docs`).

## Правила кода

### TypeScript

- Strict mode включён (`tsconfig.app.json`)
- Все типы из `shared/` импортируются через путь `@shared/...` (alias настроен в Vite и tsconfig)
- Не добавлять `any` без комментария с причиной
- Предпочитать `interface` для объектов, `type` для union/utility

### React

- Функциональные компоненты + hooks (без классов)
- Не создавать глобальное состояние через `useContext` — при внедрении Zustand перейти на store
- Компоненты в `client/src/components/`, хуки в `client/src/hooks/`
- Стили — **vanilla CSS** в `App.css` (единый файл, ~30KB), не CSS modules и не Tailwind

### Карта (MapLibre)

- `feature-state` для динамических цветов (O(1) обновление, не пересоздание source)
- Границы через shared edges (LineString), не `turf.union` в рантайме
- Подписи — Point-фичи с посимвольным позиционированием (buildCountryLabels)
- Целевая производительность: 60 FPS при 10 000 регионов

### Тесты

- Framework: Vitest + @testing-library/react + happy-dom
- Конфиг: `client/vitest.config.ts`
- Тесты лежат рядом с кодом: `__tests__/` внутри соответствующей директории
- E2E-тесты карты: `client/src/map/engine/__tests__/`

- Ветки Gemini: `gemini/<feature>`
- Мержить в `main` только когда тесты и typecheck зелёные

**Standing authorization:** локальные коммиты без подтверждения, если typecheck/тесты/lint проходят. Push — с подтверждением.
